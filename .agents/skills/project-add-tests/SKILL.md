# 按规范补测试

## 输入与必读

输入为仓库路径、变更名、待验证任务或缺陷。读取[AGENTS.md](../../../AGENTS.md)、相应 OpenSpec 场景/设计/tasks、[测试规范](../../../docs/standards/04-测试规范.md)和[安全规范](../../../docs/standards/03-安全开发规范.md)。涉及 AI/数据时补读对应规范。

## 执行

1. 读取当前代码与现有测试、真实门禁命令，列出场景编号→正常/失败/边界→用例→断言的映射。修缺陷先保留可复现的失败证据。
2. 测业务值和副作用；读写资源配未登录、跨班/同班他人及低权限。附件、私有执行记录、未开放答案不得遗漏。按 TEST-09 分开业务码与 HTTP 契约。
3. 使用独立测试库、合成A/B班数据、临时文件和注入时钟；单元替换外部依赖，真实 MySQL/Qdrant 与浏览器验收另列，不访问生产数据。
4. 编写最小必要用例；运行与改动相适用的命令并记录退出码。对核心规则做可回退的破坏验证，确认用例变红，再恢复并复测；不保留坏实现。
5. 同步追溯关系与任务勾选，输出真实覆盖和缺口；不以行覆盖率代替失败路径覆盖。

## 停止条件

没有实现、场景、真实命令或所需环境时，停止该测试流程，列出缺项和“未执行”；不要创建空门禁或假用例。在修复已授权缺陷时可继续做范围内工作，超范围变更先明确范围。

失败不得删断言、降阈值或跳钩子掩盖；未经解释的跳过不能算通过。没有权限的外部/破坏操作不执行。

## 输出证据

在 `docs/changes/<变更名>.md` 写场景映射、环境、实际命令/退出码、用例结果、破坏与恢复复测、未执行项。原始报告按规范保留在被忽略目录，摘要脱敏；不把自检写成人工批准。
