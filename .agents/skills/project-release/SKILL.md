# 按规范发版本

## 输入与必读

输入为变更名、目标环境、候选版本/提交、发布授权范围和前一已验证制品。读取[AGENTS.md](../../../AGENTS.md)、变更文件、[部署运维](../../../docs/standards/05-部署运维规范.md)、[安全](../../../docs/standards/03-安全开发规范.md)、[数据](../../../docs/standards/07-数据规范.md)及[评审规范](../../../docs/standards/08-评审与完成定义规范.md)。

## 执行

1. 先只读核对真实门禁、适用测试/评测、人工评审、环境配置、备份与回滚演练证据。确认当前授权覆盖目标环境和实际发布；已有明确授权不重复询问。
2. 从锁定依赖构建不可变制品，标签对应真实版本/提交，检查无秘密、扫描无阻断漏洞；保留前一版本和必要清单。
3. 在接流量前执行已评审的兼容迁移，验证旧版可在新结构运行。涉及破坏性数据变更必须有单独已授权方案，不随发布顺手执行。
4. 采用已确定的滚动或蓝绿方案发布，检查存活、核心就绪、关键主路径、日志关联和可选依赖降级；未就绪不切流量。
5. 失败立即按已演练方案回到前一制品，验证兼容和关键数据；回退不等于盲目回滚数据库。无法确认安全回退时停止，报告现场，不扩大副作用。
6. 成功并验证后在授权范围内打版本标签，记录包含变更、制品、环境、实际命令/退出码、耗时、批准和结果。

## 停止条件

缺应用/Compose/门禁、目标不清、无批准、无可恢复前一制品或未验证迁移时，不发布；只输出缺项与具体准备结果。技能文本不是发布、推送、打标签或发送外部消息的授权。

## 输出证据

未来记录 `docs/releases/YYYY-MM-DD-<版本>.md`，关联 `docs/changes/<变更名>.md`；实际失败、回退和复测也记录。未演练的能力写“未验证”，秘密只记录配置键名，不写值。
