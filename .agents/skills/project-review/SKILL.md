# 按规范评审变更

## 输入与必读

输入为仓库路径、变更名、改动文件清单与已有证据。读取[AGENTS.md](../../../AGENTS.md)、变更所有规划文件及任务状态、[评审规范](../../../docs/standards/08-评审与完成定义规范.md)，按改动类型打开其余规则，不依赖路径自动加载。

## 执行

1. 核对授权范围与实际文件，逐项匹配规约场景/任务和交付物；纯文档和代码采用各自完成定义，不能用 skip_specs 豁免业务场景。
2. 检查安全归属、分层/命名、统一响应、AI 引用与教师审核、数据副本与兼容；按适用范围抽查，给出具体规则编号及可观察问题。
3. 查命令是否真实存在、实际执行及退出码，检查测试/评测/演练环境与报告。未执行不能写通过；若适用代码门禁未建立，指出阻断，不创建空命令。
4. 检查 README、页面清单、必要字典和证据同步；核对约束文件变更理由、范围、例外和人工复核状态，不自行降标。
5. 对每项给“通过/失败/未执行/不适用/待人工评审”，不适用写理由；只有交付及验证均满足的任务才可勾选。保留失败、返工和复测因果。

## 停止条件

缺规划或改动范围不清时先列缺项，无法判断的部分记未执行。纯文档缺应用代码不阻止文档审查，但运行检查仍未执行。发现安全失败、未获授权的副作用或门禁篡改时指出阻断，不替实施人静默修改标准。

本技能不授权合并、发布、发送外部消息或人工批准；仅将可审阅结果交给实际评审人。

## 输出证据

在 `docs/changes/<变更名>.md` 归档变更说明、验证记录、评审结论：已查文件/规则/命令、实际结果、问题及优先级、未执行与不适用理由、人工评审状态。规范生效的四层证据单列，不把本会话审查写成独立会话验证。
