# 限流与场景追溯修复

## 变更说明

用户授权修复主干审查发现的两项缺口，基线为 main 的 `16eafa8`，实施分支为 `change/2026-11-05-fix-rate-limits-traceability`。

使用 `openspec-propose` 的制品流程补齐 proposal、design、两份能力规格及 tasks，严格校验通过后按用户已明确的修复授权进入 `openspec-apply-change`。变更为 `2026-11-05-fix-rate-limits-traceability`。实现按共享限流、场景追溯、收尾三组依次验证，正式人工功能测试仍由后续验收任务承担。

- 登录按 WSGI 直连来源、已认证写入按服务端账号，分别每 UTC 自然分钟 60 次。限额选择基于 OPS-12 的写入基线，登录来源暂取同一数值。客户端转发头不改变配额，固定窗口允许边界突发，代理后的客户端默认共享代理来源额度。均在设计及 README 登记。
- MySQL 数据库时钟、联合唯一键及事务内原子计数使各 worker 共享配额，计数封顶 61。先授权和同源校验，再限流，再进入请求体解析、口令校验或业务写入。超额 429/1600 及 Retry-After，数据库错误 503/1500。幂等重放与参数失败的已受理请求均计数。
- 追加 0003 迁移，沿用原数据库及锁定依赖。字典登记摘要、计数、两分钟窗口清理及兼容回退。仅在现有独立合成 Compose 测试库执行迁移、缺表及回退验证。
- Makefile 在保留原检查的基础上增加场景清单核验。当前六份实现规格共登记 78 个场景，其中 68 个有可执行映射，10 个骨架工程流程场景绑定既有未完成专项任务。22 份未来能力规格保持规划状态。清单变更需人工复核，不能把待验证状态算作运行通过。
- 映射核对具体 pytest 文件和函数、实际断言，以及测试到 Compose 运行脚本的调用链。脚本断言按 AST 绑定且必须唯一。认证脚本仅将重复的响应变量改成有语义的名称，原断言判据保留。
