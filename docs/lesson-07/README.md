## 本课的目标与边界

在同一个小组仓库内按顺序完成**建仓库 → 定规约 → 立规范 → 落骨架**，得到任何组员按 README 都能从零启动的最小壳；四步须在本课内完成。规范文本、严格校验、Git 合并都是中间证据，不能代替启动、测试、规则生效或交叉评审。

本课骨架包括分层及依赖方向、外置配置、统一响应/错误和日志、免认证就绪入口、可复现构建及真实测试。参考思路允许安排通用授权检查位置与统一入口；默认拒绝的机制不能因“无业务”被省略。完整登录流程、班级资源权限策略、资料问答、题库和测验属于后续业务增量。本课的正向页面/接口样本须在骨架规约中明确测试用途与清理方式，不借验证一次生成整套业务。

## 完成顺序与证据位置

1. 组长/运维确认成员、命名偏差、教师访问及编码前主干保护；本次历史偏差保留待评审。
2. 建立独立骨架变更的四份规划、能力场景表和可量化判据；严格校验后按骨架任务实施。
3. 建立真实启动与门禁，再完成 V2/V3/V4、每名成员冷启动、交叉评审及本课回滚。
4. 验收后归档骨架变更、创建真实标签，将实际记录汇总到本目录。本报告仅是入口和缺口分析。
