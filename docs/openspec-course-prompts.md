# CampusClaw 各课 OpenSpec 生成提示词

每次把「通用提示词」和**一条**「分课提示词」一起交给可以读取仓库和运行 OpenSpec CLI 的模型。先生成并评审各课规约，再逐课实施。第 3–6 课和第 8 课各生成一个 change；第 7 课保留已经交付的规范变更，另生成一个运行骨架 change 补齐本课剩余任务。第 6 课的重复链接合并处理。

以下提示词是规约起草输入，当前实施依赖、可运行交接及验收归属以 [README 的依赖表](../README.md#规约依赖与验收交接)与各 OpenSpec 任务为准。

## 生成与实施顺序

| 顺序 | 课程 | change 名称后缀 | 上游规划 | 本次演示链路 |

| 2 | 第 3 课 | `add-class-auth-material-ingest` | 第 7 课骨架 | 教师上传 → 本班学生浏览，跨班与越权被拒 |

## 通用提示词

```text
你是 CampusClaw 的 OpenSpec 规划助手。结合紧接本段的分课输入，为当前这一课生成一个中文 spec-driven change。只交付规约和规划校验记录，完成后停在待人工评审。

1. 读取磁盘上的 AGENTS.md、README.md、选题说明(1).pdf、openspec/config.yaml、现有主规格、活动与归档变更；必读安全、评审规范，并按涉及范围读取产品、后端、测试、运维、AI、数据规范。读取 .agents/skills/openspec-propose/SKILL.md，按其流程使用实际 CLI。先确认当前仓库有哪些文件和可执行命令；所有历史仓库实现、测试、部署与模型调用都只能作为需求参考。技术方向沿用 Flask、HTML/CSS/原生 JavaScript、SQLAlchemy/MySQL 8、Qdrant、pytest、Compose。
2. 打开分课来源里的正式任务清单及实践页。区分课程必交、课件示例、项目扩展、可选提高及待确认的等价映射。打不开的来源写明缺口。对照实际前置变更，区分已实现、已有规格、尚在规划、待确认；若前置规约缺失，指出具体缺失和受影响的验收。保留第 7 课规范和 AGENTS.md 的门禁。发现课程和项目约束冲突时列明差异、影响、拟议映射、确认责任及阻断项，不把待确认项写成已批准的例外。
3. 使用实际建变更日期和分课后缀组成 YYYY-MM-DD-短横小写英文名。先查同名或同课变更，已有同范围变更则读盘并使用现有修订流程。新建时用 openspec new change，按 openspec status --change <全名> --json 与 openspec instructions <artifact-id> --change <全名> --json 指示的路径和依赖生成所有工件。
   - proposal.md 写服务对象、问题、相对优势、课内验收、影响、范围、明确排除项、放弃的方案；列出课程条目与选题扩展的归属，以及已存在/未实现的依赖。
   - design.md 写角色与资源授权矩阵、页面入口和四态、接口/业务码、状态机、数据归属与字段、唯一约束、事务/外部副作用、兼容迁移与回滚、可观测性、参数与取舍。没有事实支持的数值标为拟定基线并给确认人、验证方法和关闭条件。表结构、AI 参数、发布等专项工作在 tasks 中安排适用技能。
   - specs/<能力>/spec.md 使用 CLI 要求的 delta、Requirement 和 Scenario 标题。新增能力用 ADDED；修改已入主规格的能力用 MODIFIED，保留完整受影响 Requirement。上游仍在规划时，在 proposal/design 引用其路径和依赖能力；涉及同一未归档能力的修改，按已读的上游完整条款起草依赖该条款的增量，明确归档顺序和届时的主规格对照、复验任务。各能力含成功、边界及至少四条真实失败场景，覆盖参数非法、权限不足、资源不存在、依赖故障；不适用类别说明理由并送审，仍须有四条真实失败场景。每条写可复现的前置条件、操作、可观测结果；用状态码/业务码、公开字段、页面状态、持久化记录和副作用共同判定，日志只作补充。覆盖 A/B 班、同班他人及适用的失败后重试。跨班和不存在按仓库约定比较规范化响应。
   - tasks.md 按依赖分组，每组可独立验收，所有实现任务先保留 [ ]。为每组写输入、输出、对应场景编号、预期命令/环境、判据和证据路径，列明实施、评审、运维角色；组员实名待小组指定。记录能力 → 场景 → 任务 → 证据对照。前课能力通过回归复用；从零新增能力写真实待办。预留 README、页面清单、OpenAPI、数据字典等适用同步项。
4. 默认拒绝；每次从当前数据库身份校验角色、班级和资源；私人会话/执行记录仅本人。凭据由私有环境提供，访问令牌只在内存；若启用刷新则走受限安全 Cookie 和轮换。模型、资料、技能、工具与队列都不能放宽授权或提前暴露测验答案；上传技能不执行脚本。沿用统一错误与确定性业务规则。所有读取、下载、订阅、状态查询与重试入口均写授权判据。
5. 为每项可能耗时的操作标注请求内同步、SSE 或后台任务及理由。第 3–6 课使用其前置能力；第 8 课统一引入持久队列。较早阶段为将来的队列改造设计稳定的业务标识、状态、版本与幂等边界。同步判定、流式交互和依赖同一轮回答的工具调用保留各自的即时契约。第 8 课所有后台任务复用同一套任务可靠性契约。
6. 跑 openspec validate <全名> --strict 和 openspec status --change <全名> --json；结合人工可读的场景对照自检。将实际命令、退出码、未执行项及待人工评审记入 docs/changes/<全名>.md。计划中未来要跑的 make check、pytest、Compose、浏览器、真实依赖、回滚、同伴交叉验证都列为待执行；缺命令写原因。业务和骨架都要有 specs，不启用 skip_specs。结构校验通过只说明规划格式合规。
7. 返回生成文件、change 全名、实际校验、待确认课程映射、前置缺口与待审事项。规约文件可单独审阅提交。后续提交时按仓库约定使用 change/<全名> 分支，提交只包含这一课规约和实际证据，Change/Verify/Evidence 尾注引用真实记录。提交、推送和实施按当轮授权执行；应用、合并、归档、打标签及发布各自保留真实前置条件。
```

```text
本课后缀为 add-skeleton。读取现有 establish-project-standards 的规划、证据及 README C7-01–07。保留原名、历史记录与八规范五技能。本课补齐唯一的运行骨架变更，范围为启动、健康、通用授权落点和工程门禁；登录、资料、模型、工具、队列和测验留给对应业务课次。

将载体、独立会话、正向生成、故意违规分层留证。正向样本与移除已有授权等违规演练走评审规范的隔离协议，清理样本后保留可启动的非业务主干。明确每名成员独立冷启动、真实制品及前一可运行基线、课内回滚演练步骤和耗时、后续归档标签及 docs/lesson-07/ 汇总。若某项需外部角色执行，在规约中注明负责人和可观察关闭条件。
```

```text
本课后缀为 add-class-auth-material-ingest，依赖第 7 课运行骨架。从零规划账号、班级、可吊销会话、资料元数据与正文；种子数据为合成 A/B 班，各有师生。登录签发可失效的 Bearer 访问令牌供后续 Swagger 与 SSE 使用，浏览器内存持有；设计记录它与第 3 课 Cookie 会话示例的差别，说明如何保留登录换发、注销撤销、当前数据库身份和枚举防护语义，并安排课程口径确认。

```

```text
规划选题 §6.2 的不少于 30 个独立人工标注问题，分直接事实、同义改写、跨片段和无答案；补单独的跨班安全用例。隔离调参与最终集，固定三模式、环境和模型参数，写明 Hit@5、依据充分率、无答案处理、中位数及 P95 的口径和证据，80%/90%/90% 是待验证目标。实验页面仅作为核心验收后的可选项。
```

## 第 5 课 · 提示词、AI 技能、流式会话与教学反馈

[正式任务清单](https://devops.hello1023.com/课程任务清单-第5课.html) · [SSE](https://devops.hello1023.com/课件/第5课-课件-提示词AI技能与流式会话/pages/stream.html) · [实践与验收](https://devops.hello1023.com/课件/第5课-课件-提示词AI技能与流式会话/pages/apply.html)

```text
本课后缀为 add-streaming-ai-assistant，复用第 4 课授权检索与证据契约。规划 AI 应用入口（写作润色、学习规划、练习生成、资料问答）、教师班级模板与变量预览、助手提示词及版本、助手绑定本班材料/技能、本人会话与消息及私有执行记录。明确应用、助手、模板、技能、会话、执行记录的复用关系，保留第 4 课单次问答的公开契约。配置变更时列明既有会话重读哪些绑定、停用生效时点与配置版本取证方式。

教师管理技能；含至少一个只提供步骤提示的解题引导技能，另选一个组内内置技能。支持白名单字段的 JSON 技能校验、有界顺序步骤和版本追溯，拒绝脚本或任意调用；对比课件的技能文件表示并记录项目映射。确定性路由最多选一个当前已启用且绑定的技能，明确同分、零分和停用规则。提示词由服务端组装，用户资料、上传技能内容只按受限数据处理；历史上下文有界，检索用本轮问题，材料范围与章节、助手绑定求交。资料问答无证据时沿用固定提示；如解题引导允许无证据的一般提示，须标明无课内依据、无伪出处、无最终答案，并单独测试。

规定 Bearer fetch + SSE 的 meta、增量 delta、done、error、事件顺序、流前 HTTP 失败、流内错误、浏览器中断、重试与最终持久化判据。定义未经校验的流式片段如何展示及如何阻止答案泄露；最终完成态与快照需通过出处/数值检查，断流或重复请求不伪造完成、不重复落库。即时问答保留 SSE 路径。

实现规划涵盖旧资料问答持久会话、历史出处快照、学生有帮助/未解决反馈、教师本班未解决列表和处理。原资料重建/删除时标记出处状态，按数据规范处理快照留存或删除，旧引用不能转指新切片。教师只读授权反馈及最小字段，与私人会话隔离。补本课 Swagger（可试调 Bearer）、按接口组织的 apitest/cases、run_all.py 一键执行和 HTML 报告；在 Python 测试体系中共享用例并说明与 make check 的关系。列出课件四项同伴交叉验证、流式事件证据及固定 AI 回归。
```

## 第 6 课 · MCP 与受控 HTTP 工具

[正式任务清单](https://devops.hello1023.com/课程任务清单-第6课.html) · [协议](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/mcp-model.html) · [实践与验收](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/apply.html)

```text
本课后缀为 add-controlled-mcp-tools，依赖第 5 课助手、技能、SSE 和执行记录。规划同一仓库、同一 Compose 网络中的自建 MCP 服务，含 /health、POST /mcp、JSON-RPC 2.0 的 initialize、tools/list、tools/call，以及至少两个贴合教学且无写副作用的工具，给出名称、适用范围和输入 schema。按选题目标记录 Streamable HTTP 协议版本、握手及互操作验收。服务令牌由环境注入。另支持受部署白名单约束的 HTTP 工具适配，复用宿主安全策略。

教师只管理本班已允许的服务器与工具；登记映射到部署批准的地址和凭据引用，响应只暴露配置标记。连接为握手加发现，均成功才替换清单；任一步失败明确不可用，断开清空并立即使引用失效；重复发现不加倍。对工具名@服务器名引用在保存和实际调用时分别校验，支持班级启用及按次选择。出站地址、解析结果和重定向均校验，拒绝任意地址与未批准数据外发。新增工具或说明变更安排审阅。

写 Swagger 和真实 Compose 端到端场景：连接、发现、绑定、触发、记录、断开再拒绝；另测错误令牌、非法 JSON-RPC、未注册工具、跨班、超限、SSRF 与工具注入。安排课件四项同伴交叉验证及记录只增、秘密无泄露的判据。
```
