# 测试规范

类别：五类必修。适用：未来 pytest 单元/接口测试、真实依赖集成和浏览器主路径验收。实现或修复任务后使用[补测试技能](../../.agents/skills/project-add-tests/SKILL.md)。本文件的用例卡片不是已运行测试。

## 规则

| 编号 | 规定 | 原因 | 检查动作 | 失败判据 |
| --- | --- | --- | --- | --- |
| TEST-01 | 单元测规则，接口测每条能力，浏览器只测主路径 | 保持反馈成本可控 | 本次查层次约定；实现后查用例分布 | 主路径外大量依赖浏览器或业务规则无单元覆盖 |
| TEST-02 | 测试名/注释写规约场景编号，形成双向映射 | 让通过率有含义 | 实现后场景与用例逐条对照 | 有场景无用例或用例无来源 |
| TEST-03 | 每条能力有正常/失败/边界三类，失败数不少于规约列出数 | 覆盖真实失效 | 本次查健康卡片；实现后查用例清单 | 缺类别或负向场景遗漏 |
| TEST-04 | 独立库/schema，单例前后清理，执行顺序无关 | 避免残留污染 | 实现后随机顺序及重复运行 | 结果随顺序改变或写入非测试库 |
| TEST-05 | 单元使用模型、工具、向量及时钟替身，不访问真实网络 | 快速且可重现 | 实现后断网、固定时钟 | 网络/时间变化导致单元失败 |
| TEST-06 | 真实 MySQL/Qdrant 集成与浏览器证据单列，不用 SQLite 或替身代替 | 验证真实约束与检索 | 实现后按环境执行并归档 | 将本地替身结论充当真实依赖通过 |
| TEST-07 | 断言值、授权范围及副作用，不只断言非空和长度 | 防止无效绿灯 | 实现后改坏关键逻辑再运行 | 错误逻辑仍全绿 |
| TEST-08 | 一键门禁 `make check` 汇总全部必需项，任一失败非零退出 | 结果可复现 | 实现后制造一条失败并运行 | 命令吞错误、无测试仍通过 |
| TEST-09 | 业务按独立 code 和数据判定，HTTP 映射独立校验 | 防止协议误判业务 | 实现后构造 HTTP 200/code 非0 | 仅凭 HTTP 认定业务放行 |
| TEST-10 | 失败、未执行、不适用、跳过分别记录；不得保留已知失败，跳过数只减不增；已有跳过须理由/追踪号/期限 | 禁止掩盖缺口 | 每次对照基线报告及跳过变化 | 把未执行当通过、保留已知失败或新增跳过 |
| TEST-11 | 每个读写资源有未认证、水平越权和功能越权配对 | 保持安全回归 | 实现后 A/B 班及同班账号重放 | 漏测附件、私有记录或答案旁路 |
| TEST-12 | 修缺陷先保留失败复现，再修复并保留回归 | 防止再次引入 | 实现后查看前后证据 | 只有修复后绿灯无复现依据 |
| TEST-13 | 正向用例记录端到端时延，按运维两档及固定环境判定 | 区分偏慢与不可接受 | 实现后核耗时、样本和环境 | 没有环境说明或忽略超预算 |

## 未来位置、命令与隔离

| 层次 | 约定位置（未建立） | 范围 |
| --- | --- | --- |
| 单元 | `tests/unit/` | 切片、阈值、状态、评分、统计和权限规则 |
| 接口 | `tests/api/` | HTTP 契约、认证、错误、幂等和资源归属 |
| 真实集成 | `tests/integration/` | 独立 MySQL/Qdrant、文件及跨存储补偿 |
| 浏览器 | `tests/e2e/` | 登录→资料→检索问答→出处，以及审题→测验→提交→反馈主路径 |
| AI 回归 | `tests/eval/` | 版本固定的正向、拒答、注入及引用校验 |

拟用 pytest marker 分开 unit/api/integration/e2e/eval；骨架变更建立实际命令及依赖锁。未来 `make check` 必需包含格式/静态检查、分层、机密、依赖、规约追溯及已适用的测试；AI 变化加评测，数据变化加迁移/回退验证。不能因实现难而把必需项改可选。

环境前提：锁定依赖、独立测试数据库与向量集合、测试账号、临时上传目录、可替换模型与时钟。未来环境变量键名在骨架契约登记，禁止默认连生产；缺少环境即非零退出或明确记未执行，不算成功。`pytest` 无测试的结果不能转换为完整通过。

报告计划位置为 `reports/<变更名>/`，该目录默认忽略，防止原始请求泄露；脱敏命令、退出码、数量、失败和适用范围摘要归档 `docs/changes/<变更名>.md`。真实服务验收可写独立临时环境，禁止使用生产或其他成员共享数据。

## 健康能力的三类文字用例卡片

以下均待骨架实现，来源为 OPS-03/04；具体就绪端点及响应结构由骨架规约确定后补入测试。

| 编号/类别 | 前置条件 | 操作 | 可观测结果 |
| --- | --- | --- | --- |
| HC-N01 正常 | 服务启动，核心数据库可用 | 匿名访问 `/health` 就绪和独立存活端点 | 均成功；`/health` 含版本、UTC时间与安全依赖状态，无内部地址、凭据或业务数据 |
| HC-F01 失败 | 服务进程存在，测试数据库被停止 | 访问 `/health` 和独立存活端点 | 存活仍成功，`/health` 返回503且不接新业务流量；错误有可诊断状态、不含堆栈 |
| HC-B01 边界 | 核心库可用，模型/Qdrant 暂不可达 | 访问 `/health` 并执行确定性主路径 | 核心就绪返回200，报告可选依赖降级；资料浏览、人工建题、已发布测验不被封锁 |

三类卡片只规定验证目标，未创建测试代码，不是完整的骨架验收场景集合；后续正式用例必须补对应骨架场景编号。HC-B01 中资料浏览、人工建题和测验仅在相应业务实现后验证，不要求为了验收骨架提前创建业务。匿名访问业务接口仍按 SEC-01 拒绝。

骨架及每条业务能力的正式规约至少有四条可分别判定的真实失败场景，并覆盖参数非法、无权限、资源不存在、依赖不可达四类。匿名健康端点等确无某类权限或资源时，登记不适用理由与评审依据，并从真实契约补齐其他失败路径；不适用不是一条失败场景，不能用来自动减免总数，也不能编造业务凑数。若真实边界不足，明确保留课程验收缺口并提交人工复核。场景写角色、归属、既有数据、具体操作、返回值及数据副作用，数值边界必须具体。

## 缺陷判定口径

业务成功码为 0。code 非0、无越权数据且无约定外副作用时，不因 HTTP 2xx 认定业务放行；不符合 HTTP 契约仍单独记契约缺陷。下载、协议探针、网关拒绝等例外按已登记契约判断。

| 判定词 | 含义 |
| --- | --- |
| 被当成成功 | 负向请求得到成功业务码、发生约定外变化或返回不该看的数据，任一即缺陷 |
| 被放行 | 权限负向请求拿到不该看的数据或写操作实际生效 |
| 被误拒 | 合法请求未得到成功信号或预期副作用 |
| 未处理故障 | 未捕获异常、堆栈外泄或只有“系统错误”的不可诊断提示；单独 HTTP 500 不足以判断 |

边界至少考虑空白必填、首尾空格、0/false、最大值±1、闰日与带时区时间、重复与并发、非法筛选、跨页批量。文本按契约规范化，枚举不擅自变换。
