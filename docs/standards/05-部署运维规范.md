# 部署运维规范

类别：五类必修。适用：未来构建、运行配置、制品、日志和发布。当前无 Dockerfile、Compose、Makefile 或运行服务。本文件约定不是已完成部署证据；发布用[版本技能](../../.agents/skills/project-release/SKILL.md)。

## 规则

| 编号 | 规定 | 原因 | 检查动作 | 失败判据 |
| --- | --- | --- | --- | --- |
| OPS-01 | 依赖锁入库、多阶段镜像，运行层只含必要制品；标签为版本/提交号 | 制品可追溯 | 实现后同锁定输入重建并核对清单 | 隐式依赖、机密进入镜像或仅用 latest |
| OPS-02 | 开发/测试/生产隔离，同一镜像换外部配置 | 保持测试代表性 | 实现后跨环境换配置 | 需要改源码重建或共享生产数据 |
| OPS-03 | `/health` 免认证表达就绪；存活独立，核心未就绪不接业务流量 | 区分进程与依赖并对齐课程 | 实现后停核心库检查两端 | 核心未就绪仍接流量或进程被误判死亡 |
| OPS-04 | 模型/向量是可降级依赖，不封锁确定性教学主路径 | 故障隔离 | 实现后停模型/向量仍浏览和作答 | 人工建题或已发布测验不可用 |
| OPS-05 | 收停止信号先撤就绪，再处理在途请求，有界退出 | 减少中断 | 实现后在写请求中停止服务 | 已接受事务被无说明截断或无限等待 |
| OPS-06 | 单行 JSON 日志统一字段与请求关联，排除敏感内容 | 支持追查 | 实现后抽请求跨模块串联 | 缺关联字段、原文/秘密入日志 |
| OPS-07 | 请求量、错误率、时延和依赖指标均有告警负责人及处置 | 告警可行动 | 实现后故障注入 | 无告警、无人处理或无动作 |
| OPS-08 | 发布按构建→兼容迁移→发布→就绪→版本留证，保留可用回滚制品 | 限制发布风险 | 发布前核对技能证据 | 无回滚路径或未就绪接流量 |
| OPS-09 | 迁移采用扩展→迁移→收缩，旧版本兼容新结构 | 支持回退 | 实现后旧版本在新结构运行 | 回滚需清库或旧版无法运行 |
| OPS-10 | 备份有频率/留存/RPO/RTO，定期真实恢复 | 备份不等于可恢复 | 实现后恢复演练计时 | 仅存在备份文件无恢复证据 |
| OPS-11 | 性能预算、批量和外部调用配额集中登记 | 限制失控成本 | 实现后固定环境采样 | 超硬预算、无上限或无环境说明 |
| OPS-12 | 写入和高成本接口按主体限流，返回 1600 与重试建议 | 保护资源 | 实现后超过配额重放 | 无限排队或绕过主体限流 |
| OPS-13 | 每次发布记录版本、变更、测试、演练与批准 | 可回溯时间线 | 发布后按标签检索证据 | 有标签无证据或伪造批准 |

## 骨架待建文件契约

| 未来文件/能力 | 骨架变更必须交付 | 当前状态 |
| --- | --- | --- |
| `Dockerfile` | 分阶段构建 Flask 应用及所需静态资源，依赖锁固定 | 未建立 |
| `docker-compose.yml` | 应用、MySQL 8、Qdrant 的网络、持久目录和健康；仅应用公开必要端口 | 未建立 |
| `.env.example` | 所需键名和空值，公开默认值另写文档，不含真实口令 | 未建立 |
| `Makefile` | 统一 `make check`，任何必需项失败均非0 | 未建立 |
| 冷启动 | 克隆→配置→`docker compose up --build -d`→匿名 `/health`；就绪单独验证 | 未实现 |
| 版本 | 不可变镜像标识、健康输出版本、经过授权的 Git 版本标签 | 未建立 |

数据库与向量服务默认不映射宿主公网端口，演示工具若需要独立服务由对应功能变更登记。`/health` 按课程作为就绪入口，返回版本、UTC时间和安全依赖连通状态，核心可用200、不可用503；存活检查另设路径，由骨架规约明确。响应不泄露地址、SQL、口令或学生信息。可降级依赖失败按 OPS-04 报告而不撤销核心就绪。

## 日志与容量参数

未来日志字段：`ts`（UTC）、`level`、`module`、`request_id`、`version`，可附 `duration_ms`、业务码、脱敏主体标识、依赖类别。后台任务携带独立任务标识和来源请求标识。模型用量字段见 AI-10；日志不记录问答全文、令牌、学生作答或私有执行原文。

以下为**本项目暂定验收基线，未压测、未演练**。参数变化必须在适用变更中说明环境、原因、评审和新证据；不能为了已有失败单方面放宽。

| 项目 | 暂定基线或必须登记项 | 责任/检查与阻断 |
| --- | --- | --- |
| 普通查询时延 | 正向请求 >300ms 标记，>1000ms 不通过；固定数据1000条、并发10，在记录配置的测试机测量 | 实施人记录端到端、样本和P95；缺环境或超过硬档不能通过性能验收 |
| 模型总时延 | 警告与硬超时由 AI 参数表约束，不套普通查询阈值 | AI实施人登记模型配置和耗时；不将超时当无证据 |
| 优雅停止 | 暂定最多30秒排空，剩余任务标记可恢复 | 运维人演练；重复评分或任务丢失阻断 |
| 备份/恢复 | 暂定每日加密备份、保留14天，RPO≤24小时、RTO≤2小时 | 运维人每学期及首次发布前恢复演练；未达目标不得宣称恢复能力 |
| 普通写入限流 | 暂定每用户60次/分钟，登录按来源额外限制；不得以此替代认证 | 实施人用测试主体超额验证，返回重试建议 |
| 高成本操作 | 模型/索引等限额见 AI 参数表；批量接口另登记行数与并发 | 未登记责任人和边界不开放该能力 |
| 告警 | 暂定5分钟窗口错误率>5%且请求≥20、P95>预算、核心依赖不可达立即告警 | 运维人分派处理；错误率看业务码，降级依赖单独显示；无处置记录不闭环 |

首次上线前须确认这些目标适合实际班级规模，写明实名运维责任人及通知渠道。不是本次创建通知或向外部系统发消息。

## 检查清单与违规处理

本次执行：核对容器、命令、健康、日志和标签的文字契约及状态。实现后执行：从干净配置冷启动，匿名健康、停依赖、在途停止、超额请求；发布与回滚按[技能](../../.agents/skills/project-release/SKILL.md)执行。

应用回退到已验证的前一制品，不自动回滚破坏性数据结构；数据回退须检查兼容和备份。每迭代回滚演练，至少每学期恢复演练。未来记录位置为 `docs/releases/YYYY-MM-DD-<版本>.md`，须含实际耗时与失败原因。

第 7 课也须完成一次回滚演练：在隔离环境分别启动当前与前一可运行版本，执行回退并核验健康、版本与日志，记录实际步骤、耗时及结果，README 同步可复现步骤。首次骨架没有前一制品时，先在骨架变更中安排建立可运行基线及后继版本，再演练；不能把文档提交当可运行版本，也不能把缺少版本记为回滚通过或不适用。当前无运行制品，此项为本课未完成任务。发布策略在实施规约中明确滚动或蓝绿方案，不能用 Compose 命令退出成功代替切换与回滚验证。

配置、探针、回滚或备份规则发生变化须人工复核；没有运行证据只能记“约定/未验证”，不能以规范文字替代部署验收。
