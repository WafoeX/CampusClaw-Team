## Context

第 7 课骨架提供 Flask 分层、MySQL/Qdrant 和门禁。人工教学闭环可与检索和流式并行开发，先冻结班级、章节、原文版本、证据和反馈的共享接口，并用两个合成班联调。人工建题和测验不依赖模型、Kafka 或 MCP。AI 候选题复用有限证据接口和固定版练习提示配置，工具关闭，不要求完整通用应用目录或技能管理上线。

## Goals / Non-Goals

- Goals — 先完成 MySQL 中的人工建题、发布、交卷与评分，再接入候选题异步作业和可选后台索引。
- Non-Goals — 首版不做模型评分、教师改分、跨班管理或看板副本。以候选题演示课程异步三项判据的等价性待任课教师确认。若课程要求异步评分，单独立规约，明确客户端版本切换与迁移。

## Decisions

### 1. 题库、版本及教学证据

- MySQL 记录题目与不可变修订、审核人和时间。状态为草稿、已审核，编辑新建草稿并使题库当前修订待审，已发布快照维持原样。审核、编辑、发布对期望修订作条件写入并留下去内容审计。仅本班教师可读写题库及其答案。
- 单选为 2–6 个互异选项且恰有一个正确选项，判断为固定真/假，题干、解析必填。手工题可无出处，有出处须授权。AI 批次只接本班章节或资料之一，数量 1–10，固定任务的模板、模型和来源版本，启用已有受控技能时才记录其版本；使用固定版练习提示配置并复用第 4 课证据接口，可复用第 5 课已有编排，限 8 片/12000 码点。上游无证据时零对话调用，候选批次失败；依赖异常和输出错误分别以 1500、1501 分类。资料、技能及模型输出是数据，工具和外部任意地址关闭。必须通过完整结构、题型、答案、适用数值、出处与来源授权校验，整批提交草稿及成功状态，失败不保留半批。每任务/代次以业务键只产生一批可见草稿。
- 来源快照保留批准的最小摘录、原文/索引版本和区间。重建后仍有当前权限时可看旧快照；删除/撤权隐藏摘要、标题、链接及应删除的衍生副本，显示安全状态。不可变评分依据与可撤销出处投影分开；清理出处不改评分，正式隐私删除按数据规范同时处理受影响业务记录。

### 2. 发布、时间、草稿和正式提交

- 教师按班及章节组卷，仅引用当前已审核修订。发布事务锁定并复核发布中的测验、题目修订和本班应参与名单，冻结题干、选项、分值、答案、解析、出处引用、评分规则版本及名单。测验至少 1 题且应参与名单非空；分值用正整数，基线每题 1–100、每份最多 50 题。发布后截止、开放时间与快照均固定；有正当调整需求创建新测验。学生访问须同时满足当前学生身份、同班及名单，后来入班不自动获得既有测验资格。
- UTC 由服务端和数据库提供，发布要求 `publish_at < deadline_at <= answers_open_at`，开放时间默认截止。正式提交不获取全测验排他锁，读取不可变发布快照，按固定顺序锁定当前学生账号、该测验的参与与草稿行，事务内复核当前角色、班级与参与资格，再取数据库 UTC。锁内 `accepted_at < deadline_at` 才能创建首次提交，等于截止即拒绝。隔离环境用同一测验多学生在截止前并发提交，观察各参与行等待和受理结果。
- 草稿按测验/学生唯一，用修订号防覆盖。正式提交冻结规范化作答与时间，在同一短事务用已读取的快照计算并写入唯一正式提交、结果和幂等记录，无外部调用。首次 201/0，返回 submission_id；同主体、同测验、同键等价重放返回原 201 和 ID，异内容 409/1400，新键且已有提交 409/1401，否则截止 409/1402。未作答计错。浏览器按修订保存草稿并显示已保存状态，刷新或登录到期后用原账号回读最新服务端草稿和剩余时间，重新提交仍受修订与截止检查。
- 学生在答案开放前仅看允许作答内容、本人作答和提交状态。总分、逐题正误、正确项、解析、来源及衍生提示均须开放且评分完成才在学生成绩/错题端可见。教师只查本班授权测验提交和审核数据，管理读与学生投影分离。答案数据不进入共享 RAG、普通会话历史或 MCP 候选、工具参数、作答下载、任务错误、前端页面内嵌数据、日志和缓存。被测学生复制题目到独立问答时，系统不提供受保护的评分或答案数据。用成对角色测试所有直接/间接入口及出处访问，记录内容和副作用。

| API 与页面 | 授权与结果 |
| --- | --- |
| `/console/questions`，`/api/v1/questions`、`/{id}/reviews`、`/question-generation-jobs` | 教师本班手工建题、修改、审核和发起候选题；候选 202，任务进度不含答案 |
| `/quizzes`、`/quizzes/{id}`，`/api/v1/quizzes`、`/{id}/publications` | 教师组卷与发布，学生仅浏览本人有资格的已发布测验 |
| `/api/v1/quizzes/{id}/draft`、`/{id}/submissions`、`/{id}/my-submission` | 学生本人保存和恢复草稿、正式提交及读取结果。首次或等价重放均为 201/0，含 submission_id。成绩按答案开放规则可见。 |
| `/api/v1/teaching-jobs/{id}`、`/{id}/replays` | GET 只读，原发起者按当前归属查状态。候选题或索引重放单独授权写入，按当前教师业务资格复核。 |
| `/mistakes`、`/console/dashboard`，`/api/v1/mistakes`、`/api/v1/learning-insights`、`/api/v1/quizzes/{id}/submission-results` | 学生只查本人；教师查本班汇总及授权提交详情；出处额外检查当前原资料权限 |
| `/api/v1/materials/{id}/index-builds` 及既有构建状态入口 | 核心闭环自动化验证通过并选做后切换 POST 为 202/0，保留 build_id 并返回 task_id；教师按本班权限轮询，构建状态读保留第 4 课领域状态及可公开原因 |

表内缩写路径相对同一行完整前缀，实施时在 OpenAPI 列出完整方法与路径。沿用同源 Cookie 会话及写入防护、响应信封与业务码。匿名 401/1100，学生调教师功能 403/1200，外班/他人/缺失对象 404/1300 同构。参数 400/1000，过期修订/状态 409/1400，配额 429/1600，依赖失败 503/1500。分页稳定，默认 20 上限 100；页面均有加载、正常、空、错误四态，任务状态额外显示等待、处理中、退避、完成和可重试提示。未知路由 404，按产品规范测试键盘和窄屏。

### 3. 持久任务、重试和故障边界

- Kafka 仅用于候选题和核心闭环自动化验证通过后选做的后台索引。课程环境用持久卷的单节点 KRaft、显式创建 topic，候选题与索引各用独立 topic、消费组和并发配额，配置独立的死信 topic。实施时锁镜像摘要和客户端版本。Web、MySQL 是人工教学主链路，Kafka 及投递器和 worker 作为 Compose 扩展，单节点只验证重启恢复。
- 任务和 outbox 同事务，事件只包含 event_id、task_id、任务代次、协议版本及追踪标识，按 task_id 分区。短事务认领 outbox，事务外以 `acks=all` 和幂等生产者发送，收到目标 topic 的成功交付回执后才标已投递。超时或回执丢失重发原 event_id，MySQL 业务唯一键防止重启重发造成重复结果。具体配置以 [Kafka 生产者文档](https://kafka.apache.org/41/configuration/producer-configs/) 为准。
- 状态 `pending → running → succeeded`，瞬态错误进入 `retry_wait`，永久错误为 `failed`，耗尽为 `dead_letter`，撤权或过时为 `cancelled`。消费者关闭自动提交和自动存储 offset，每分区顺序处理，只在对应结果、重试安排或隔离记录已持久化后手动提交连续 offset，禁止越过未处理记录。DB 故障暂停分区并有界退避。再均衡停止旧分区认领，旧代次不提交 offset，MySQL 租约和结果唯一键拦截陈旧执行。提交 DB 后、提交 offset 前崩溃可重放而只产生一份结果。
- 瞬态重试最多 4 次，MySQL 记录到期时间及新 outbox，投递器到期才发，不阻塞分区。watchdog 回收过期租约，并对账超过恢复窗口的已投递未完成任务，仅在待办尚未完成且无有效租约时按当前代次重新发件，覆盖保留期截断或 offset 超界。耗尽时终态与死信 outbox 同事务，投递失败可恢复。畸形记录按 topic/partition/offset 唯一隔离，持久化隔离与发件记录后才推进 offset。
- 只读 GET 无调度或重试副作用。人工重放仅允许当前仍符合业务资格且无成功结果的可恢复失败，新代次共享结果唯一键。出题和索引在受理、执行与最终写入复核当前教师角色、班级、资源、来源/目标版本。
- 运维记录消费组 lag、最老待办年龄、处理时长、重试、死信和积压。满额的新异步请求返回 429，已受理任务保留。候选题和索引有独立配额，Kafka 停机时人工建题、草稿、交卷和评分继续。

### 4. 错题、统计、索引切换与证据

- 错题从本人正式作答派生，遗漏题计错，答案开放后可查看。看板在一致读视图取冻结名单、正式提交与结果。提交率为正式提交人数/发布应参与人数；平均分和逐题正确率以正式提交为分母。评分失败整笔回滚，不纳入任何提交分母，也不记 0 分。零分母显示无数据。章节未解决数按 FB-01 口径独立聚合，反馈模块未接入时显示未接入。首版实时查询。
- 后台索引接手第 4 课 prepare/run/publish/cancel/cleanup 边界，材料原文入库仍同步；教师工作台上传成功后可显式发起首次构建。沿用原文、索引、配置版本并加入构建 ID 与租约，防止旧任务重新发布。静态参数非法或原文超 32,000 码点同步拒绝且不建任务；默认自动模式沿用固定窗口回退，标题/自定义执行时超 64 片在任务终态提示改用自动。发布前比较资料存在、目标版本、教师授权和租约；精确补偿未发布版本的关系行、Qdrant 点和适用文件，失败可重跑。现有发布索引继续服务，首次关系索引完成后即可关键词检索，向量就绪后再开放向量/混合；完整旧版重建期间保持原版。版本切换和出处语义继续以第 4、5 课为准。
- 用真实候选题任务验证 202 不等待模型、停 worker 后恢复、数据库已提交但 offset 尚未提交时的重放去重。分别记录受理和任务完成时延，报告样本与 P95。客观评分只测提交事务时延和截止并发。课程如另有量化门槛，实施前登记确认，不预设异步快 20%。
- 课末自查按课程编号记红绿，先发现、再留证，真实红项交后续课修复，明文秘密即刻撤销、轮换并按授权处置历史。评审复现至少两条，未发现红项如实记录并提交课程确认。安全实测由课末安全预检执行，本变更在 7.1–7.3 引用同一证据。

## Risks / Trade-offs

- 单节点代理和数据库各自可能失效 → 持久发件箱、确认、去重及独立恢复演练，避免将 Compose 单机视为容灾。
- Kafka 单节点及消费再均衡可能造成重放或延迟，使用受理与结果时延、持久待办和 offset 回放验证恢复。
- 新旧索引客户端期望不同 → 工作台和 OpenAPI 同步切换、先验证轮询，部署期避免混流；失败时走经过验证的回退步骤。
- 成绩可用于反推答案 → 在开放前同时屏蔽总分、逐题与汇总旁路，验收先覆盖教师/学生投影，接入 SSE/MCP 后追加其路径复核。

## Migration Plan

先验证空库和已有数据库，建立题库、测验、提交和评分迁移。人工闭环通过后再增加 Kafka、任务和发件箱，验证候选题 202 与恢复，再按需切换索引。回退暂停新异步受理并保留已承诺任务，确认兼容 worker 能排空，核对数据库终态、outbox 和 Kafka 消费位置，业务结果不得重复或丢失。
