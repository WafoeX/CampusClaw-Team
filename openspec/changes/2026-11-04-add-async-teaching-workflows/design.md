## Goals / Non-Goals

- Goals — 一条可复现的教学闭环、受理与执行解耦、数据库和代理部分失败可恢复。使用同一个变更，按依赖分组验收。
- Non-Goals — 无教师手工改分、模型评分、测验答题助手、跨班管理或额外汇总副本。模型批改、教师改分、作业批改/错题讲解技能与课件的差异由课程教师确认；规约和内部业务验证可先进行，课程等价结论保持待定。

## Decisions

### 1. 题库、版本及教学证据

- MySQL 记录题目与不可变修订、审核人和时间。状态为草稿、已审核，编辑新建草稿并使题库当前修订待审，已发布快照维持原样。审核、编辑、发布对期望修订作条件写入并留下去内容审计。仅本班教师可读写题库及其答案。
- 单选为 2–6 个互异选项且恰有一个正确选项，判断为固定真/假，题干、解析必填。手工题可无出处，有出处须授权。AI 批次只接本班章节或资料之一，数量 1–10，固定任务的模板、技能、模型和来源版本；复用第 5 课练习生成的受控编排和第 4 课证据接口，限 8 片/12000 码点。上游无证据时零对话调用，候选批次失败；依赖异常和输出错误分别以 1500、1501 分类。资料、技能及模型输出是数据，工具和外部任意地址关闭。必须通过完整结构、题型、答案、适用数值、出处与来源授权校验，整批提交草稿及成功状态，失败不保留半批。每任务/代次以业务键只产生一批可见草稿。
- 来源快照保留批准的最小摘录、原文/索引版本和区间。重建后仍有当前权限时可看旧快照；删除/撤权隐藏摘要、标题、链接及应删除的衍生副本，显示安全状态。不可变评分依据与可撤销出处投影分开；清理出处不改评分，正式隐私删除按数据规范同时处理受影响业务记录。

### 2. 发布、时间、草稿和正式提交

- 教师按班及章节组卷，仅引用当前已审核修订。发布事务锁定并复核测验、题目修订和本班应参与名单，冻结题干、选项、分值、答案、解析、出处引用、评分规则版本及名单。测验至少 1 题且应参与名单非空；分值用正整数，基线每题 1–100、每份最多 50 题。发布后截止、开放时间与快照均固定；有正当调整需求创建新测验。学生访问须同时满足当前学生身份、同班及名单，后来入班不自动获得既有测验资格。
- UTC 由服务端和数据库提供，发布要求 `publish_at < deadline_at <= answers_open_at`，开放时间默认截止时刻。短事务在持有测验及参与/作答锁后取数据库 UTC 作为受理判定点，`accepted_at < deadline_at` 才允许首份正式提交，等于截止即拒绝；锁等待跨截止按实际判定点处理。事务先确认当前权限，再比幂等记录、已有正式提交、截止及作答版本；只有事务提交成功才返回受理。评分使用已冻结作答和快照，即使队列延迟、账号停用/换班或已截止，已合法受理工作仍评分，当前身份决定后续读取。
- 草稿按参与学生和测验唯一，使用修订号防覆盖；正式请求带当前草稿修订和规范化作答，可遗漏题目，遗漏计错，重复选项、题外 ID 或非法值拒绝。受理事务冻结作答和时间，写提交、任务、发件箱，数据库以测验/学生唯一。同主体同测验同键等价请求在保留期内返回原 202 与相同 ID，无新写入；已改变指纹 409/1400，新键且已有正式提交 409/1401，否则截止 409/1402。重放不重验过期截止去创建新任务，只重验当前访问权限。服务端评分按冻结选项、分值与规则版本确定，重复结果有唯一约束；请求路径只受理，无同步评分回退。
- 学生在答案开放前仅看允许作答内容、本人作答和粗粒度处理状态。总分、逐题正误、正确项、解析、来源及衍生提示均须开放且评分完成才在学生成绩/错题端可见。教师只查本班授权测验提交和审核数据，管理读与学生投影分离。答案数据不进入共享 RAG、普通会话历史或 MCP 候选、工具参数、作答下载、任务错误、前端页面内嵌数据、日志和缓存。被测学生复制题目到独立问答时，系统不提供受保护的评分或答案数据。用成对角色测试所有直接/间接入口及出处访问，记录内容和副作用。

| API 与页面 | 授权与结果 |
| --- | --- |
| `/console/questions`，`/api/v1/questions`、`/{id}/reviews`、`/question-generation-jobs` | 教师本班手工建题、修改、审核和发起候选题；候选 202，任务进度不含答案 |
| `/quizzes`、`/quizzes/{id}`，`/api/v1/quizzes`、`/{id}/publications` | 教师组卷与发布，学生仅浏览本人有资格的已发布测验 |
| `/api/v1/quizzes/{id}/draft`、`/{id}/submissions`、`/{id}/my-submission` | 学生本人草稿、正式受理、按答案开放门控的个人结果；新受理和等价重放均为 202/0，带 submission_id/task_id |
| `/api/v1/teaching-jobs/{id}`、`/{id}/replays` | GET 只读，原发起者按当前归属读脱敏状态；教师仅在授权测验提交视图看评分状态。授权重放单独写入口，评分重放仅授权运维；出题/索引还校验本班教师及当前业务资格 |

### 3. 持久任务、重试和故障边界

- 选 RabbitMQ 持久队列、独立投递器和 worker。进程内线程无法跨 Web 重启恢复，仅扫业务表会把投递、调度和背压堆进各业务。MySQL 是受理与结果事实源；broker 存独立消息。Compose 至少新增 `rabbitmq`、`job-dispatcher`、`job-worker`，复用应用制品，独立入口。评分与模型/索引按队列和 worker 配额隔离，防止慢任务占满评分。broker 仅内网，私有卷及分权凭据；锁镜像摘要和客户端版本，按第 7 课许可、漏洞、迁移与恢复门禁。单节点隔离验收不当作高可用结论。应用公开探针保持 RT-02，内部独立观测 broker/投递器/worker；broker 故障时在持久积压额度内仍可受理。
- 业务行、任务和 outbox 同事务；消息只含 task_id、任务类型、任务代次/协议版本及追踪标识，任何正文、作答、答案、令牌和模型结果均从受控业务存储读取。任务持有 class_id、发起者、目标 ID/版本、业务幂等键、状态、尝试/代次、租约、起止、可公开错误；业务幂等键按任务类型、资源标识和目标版本派生，并区分同资源的合法独立请求。短事务认领待投递行，事务外以持久消息和可靠路由发送；使用 publisher confirm 及不可路由退回判定，确认路由且获 confirm 后才条件标已投递。断线、确认丢失、投递器重启重发同事件 ID，允许重复。按[确认与 ACK](https://www.rabbitmq.com/docs/confirms)区分两种信号。
- 状态 `pending → running → succeeded`；瞬态失败转 `retry_wait → pending`，永久失败转 `failed`，耗尽转 `dead_letter`；可撤销任务过期、撤权或资源失效进入 `cancelled`。结果库写入业务键唯一且检查租约令牌与代次，陈旧执行者不可提交。worker 在短事务认领，外部工作在事务外，业务结果和任务完成同事务提交后才 ACK。遇已有终态或确有有效租约的重复投递可 ACK，前提是持久租约监视可在到期后重建待投递行；DB 不可用时不确认，断线或有界背压后再交付，避免热循环。watchdog 按条件更新到期租约并补 outbox，未完成重放、确认丢失和并发执行均以唯一结果收敛。课程记录分别报告实际执行尝试和消息投递，提交后 ACK 丢失所致的重投无需再跑评分。
- 瞬态重试暂定最多 4 次执行，间隔基数 2 秒、指数退避上限 60 秒并加有界抖动；预算包括租约到期恢复，重复投递不增加真正执行次数。以同一任务代次和独立投递序号记录，下一次计划及 outbox 同事务，ACK 在其提交后。耗尽时先持久化终态和死信 outbox，再由投递器确认投递死信；数据库状态可查，不将 broker 原生死信当作业务唯一凭证。不可识别消息隔离至协议级死信且不执行，队列侧异常隔离配合 DB 巡检核对未完成任务。[RabbitMQ 死信行为](https://www.rabbitmq.com/docs/dlx)
- 只读 GET 无调度或重试副作用，建议前端 2 秒轮询、上限退避至 10 秒，终态停止。人工重放仅允许当前仍符合业务资格、没有成功结果的可恢复失败，生成新的执行代次但共享业务结果唯一键；已评分不得重评，普通用户无法驱动评分。出题、索引在受理、执行及最终写入分别复核当前教师角色、班级、资源、来源/目标版本；撤权、换班、删除或过时结果取消并清理。评分只核对已合法受理的冻结资格，依法清除数据的任务不得复活。
- 运维登记接收/处理速率、队列长度、最老待办年龄、处理时长、重试/失败/死信、限流、响应 P95、告警和处置。满额在受理事务前明确 429 并留已受理任务，不能丢弃；评分、索引、模型故障隔离。停机先停止认领，有界排空，超时交由租约回收。实施前锁定限额、超时、RPO/RTO、版本和责任人。日志、任务错误和报表只记脱敏标识与状态。

### 4. 错题、统计、索引切换与证据

- 错题从本人已评分正式作答派生，遗漏题也计入，答案开放后才可查看；按发布章节筛选，来源回读再验当前权限。看板在一致读视图取冻结名单、正式提交和成功评分。提交率为正式提交人数/发布应参与人数，计入待评分和评分失败；平均分为已成功评分的正式提交总分之和/成功评分人数；题目正确率为该题答对的成功评分人数/适用该题且已成功评分人数，遗漏计错。分别展示待评分和失败数量，存在缺口时成绩指标标为暂定；分母零显示无数据，不作 0%。章节未解决数沿用第 5 课授权反馈的当前未解决口径，按章节聚合，不把未归属反馈算作某一测验。首版实时查询，物化仅在达到经评审的量级/延迟条件后另议。
- 后台索引接手第 4 课 prepare/run/publish/cancel/cleanup 边界，材料原文入库仍同步；教师工作台上传成功后可显式发起首次构建。沿用原文、索引、配置版本并加入构建 ID 与租约，防止旧任务重新发布。静态参数非法或原文超 32,000 码点同步拒绝且不建任务；默认自动模式沿用固定窗口回退，标题/自定义执行时超 64 片在任务终态提示改用自动。发布前比较资料存在、目标版本、教师授权和租约；精确补偿未发布版本的关系行、Qdrant 点和适用文件，失败可重跑。现有发布索引继续服务，首次待处理时只展示原文。版本切换和出处语义继续以第 4、5 课为准。
- 课程性能基线只在独立环境运行同一纯评分器和同步受理路径，固定数据、环境、预热及采样口径，各至少 20 个有效独立提交，按同一方法计算 P95。拟定显著性门槛为异步受理 P95 至少低于同步提交 P95 20%，同时独立记录课件要求的单次实际评分耗时，门槛在采样前登记。真实客观题差异无法区分时保留结果，用受控慢执行器或候选题另取解耦证据，独立标记条件，提交教师确认。禁止线上同步回退或合成数据冒充实测。另用停 worker、并发重放、ACK 前崩溃、broker 中断和回滚复现三项判据。
- 课末自查按课程编号记红绿，先发现、再留证，真实红项交后续课修复，明文秘密即刻撤销、轮换并按授权处置历史。评审复现至少两条，未发现红项如实记录并提交课程确认。交付证据及独立提交约定见 tasks。

## Risks / Trade-offs

- 单节点代理和数据库各自可能失效 → 持久发件箱、确认、去重及独立恢复演练，避免将 Compose 单机视为容灾。
- 客观评分比网络和持久写入更快 → 记录未达指标和分离证据，课程等价由任课教师确认。
- 新旧索引客户端期望不同 → 工作台和 OpenAPI 同步切换、先验证轮询，部署期避免混流；失败时走经过验证的回退步骤。
- 成绩可用于反推答案 → 在开放前同时屏蔽总分、逐题与汇总旁路，验收覆盖教师/学生不同投影和 SSE/MCP 数据路径。

## Migration Plan

先验证空库、带上游数据的库和迁移重跑，增量建立题库、测验、提交、评分、任务与 outbox 表、唯一约束、清理记录。评分逻辑先用隔离同步对照；任务存储、代理、投递器、消费、恢复均验证后开放 202，核心闭环通过后切索引。回退先停止新受理，保留并排空已承诺任务，必要时保持兼容 worker 处理已受理任务；回到上一可用制品前验证读取新结构。索引回退先停新的异步构建并收敛在途，旧客户端只接已核验同步入口。不得清空已有数据或让回退路径重复评分；恢复前对账 outbox/终态，重放撤销与删除清单，核对旧版本和向量孤儿。按项目留存基线登记学期结束后 30 天内清理、审计/日志与备份轮转。
