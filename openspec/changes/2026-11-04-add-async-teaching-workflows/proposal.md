## Why

教师需要用本班资料出题、发布可复核的测验并识别共性困难，学生需要可靠提交和在开放后回顾错题。将耗时处理移出 Web 请求，可在 worker 暂停、依赖失败或请求重放时保住已受理工作，且保留可解释的评分依据。

## What Changes

- 建设单选/判断题库、修订审核、测验发布快照、作答草稿、正式提交、确定性评分、个人错题和本班学习看板。支持手工建题与基于授权资料的 AI 候选题生成。
- 正式提交在 MySQL 短事务中完成客观评分，返回 201 和提交标识。教学闭环先用人工建题跑通。AI 候选题作为首个异步任务，返回 202 和任务标识，采用 Kafka、事务性发件箱和独立 worker。
- 核心闭环自动化验证通过且选做时，同一 change 接入后台索引，复用第 4 课服务。**BREAKING**：现有索引构建 POST 从同步结果切换为 202 受理，页面和 API 调用方改为轮询；原文、检索和既有发布版本语义延续。
- 复现课程的 202 响应、停 worker 恢复、重复投递唯一结果三项判据。由课末安全预检执行安全自查及同伴复验，本变更引用同一记录，课末证据可单独提交。
- 课件示范模型批改、教师改分及作业批改/错题讲解技能，本组采用客观题规则评分、教师审题和出处回顾。拟用 AI 候选题演示异步可靠性，等价验收待课程教师确认。若课程明确要求评分本身异步，先单独修订规约并评审，避免同一提交接口出现两套成功语义。性能证据保留原始实测与测试条件。

范围依据[选题说明](<../../../选题说明(1).pdf>) §3.2、§4.2–4.4、§6.1。文本 PDF、检索实验页、异步物化看板、主观题和监考留作后续候选。放弃进程内线程、仅轮询业务表、同步执行模型候选题及直接双写 MySQL/Kafka，理由见设计。

## Capabilities

### New Capabilities

- `reviewed-question-bank` — 手工题目、候选题任务、证据校验和修订审核。
- `published-class-quizzes` — 本班组卷、不可变快照、参与名单和答案开放。
- `async-quiz-submissions` — 既有工件标识，定义草稿、一次正式提交、事务内规则评分和本人查询。
- `durable-teaching-jobs` — 公共任务、发件箱、可靠投递、消费、重试与恢复。
- `class-learning-insights` — 错题回顾、教师授权明细及统计口径。

### Modified Capabilities

- `material-indexing` — 将 IX-01 的触发和执行契约改为后台任务，保留完整发布、权限、容量及副本治理约束。依赖第 4 课归档后的同名主规格。

## Impact

人工闭环依赖骨架与认证，共用章节标识及反馈读取契约。AI 候选题依赖有限证据接口和教学提示配置，章节未解决数量依赖反馈数据。第 6 课 MCP 独立验收，既非上线前置也不参与候选题。当前有运行骨架和各课业务规约，主规格为空。实施前复核上游行为，索引合并前核对完整 IX-01。最终项目验收沿用独立验收变更。本课依据[实践与验收](https://devops.hello1023.com/课件/第8课-课件-异步任务与消息队列/pages/apply.html)和[安全自查任务清单](https://devops.hello1023.com/课程任务清单-第8课.html)。
