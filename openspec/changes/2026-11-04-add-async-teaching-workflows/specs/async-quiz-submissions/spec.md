## Purpose

让合格学生保存草稿并只提交一次正式作答，可靠受理后以确定性规则评分，能复现接口解耦、故障恢复与唯一结果。

## ADDED Requirements

### Requirement: SB-01 一次正式受理与异步规则评分

系统 SHALL 按服务端 UTC、发布资格和当前授权管理草稿及正式提交，在同一事务冻结作答、提交、评分任务及待投递记录。受理返回 202 和任务标识，无评分；相同键与等价请求可回放，唯一正式结果由不可变快照及规则计算。本人状态查询只读，教师仅通过本班授权测验提交视图查看。

#### Scenario: SB-N01 草稿、202 与规则评分
- **GIVEN** 合格学生在截止前，已发布快照含单选和判断题
- **WHEN** 保存草稿、正式提交、轮询并在开放后查成绩
- **THEN** 提交返回 202/0、同事务有提交任务和发件箱，worker 按固定快照计算唯一成绩，开放前无成绩

#### Scenario: SB-N02 响应不等待评分的测量
- **GIVEN** 隔离环境固定规则、数据和环境，可独立计时且有同步对照
- **WHEN** 分别以至少 20 个有效独立提交记录异步和同步 P95，记录单次评分时间并观测受理前后评分事件
- **THEN** 202 无评分且不等待 worker；保存实际 P95、门槛及比较结论，未达标仍保留实际与课程确认状态

#### Scenario: SB-B01 截止瞬间、重放和迟到消费
- **GIVEN** 服务端 UTC 可控，至少有两个独立合格参与者
- **WHEN** 一份在截止前锁内受理，另一份恰到截止才过锁内校验，随后在截止后重放第一份并启动 worker
- **THEN** 首份 202 且可在截止后完成评分，第二份 409/1402，首份等价重放仍为原 202 与同一任务，不新增记录

#### Scenario: SB-B02 停 worker 再恢复
- **GIVEN** 代理和 MySQL 可用但 worker 已停
- **WHEN** 提交并反复查询，再启动 worker
- **THEN** 202 且状态保持待处理，只读查询无副作用；恢复后无需再提交即可完成

#### Scenario: SB-F01 参数、版本与幂等冲突
- **GIVEN** 本人有草稿、已受理请求及对应幂等键
- **WHEN** 提交非法选项或题外 ID，再用旧草稿修订或同键异内容请求
- **THEN** 分别返回 400/1000 或 409/1400，无作答、任务或结果被改写

#### Scenario: SB-F02 匿名与非学生越权
- **GIVEN** 测验存在且有合格名单
- **WHEN** 匿名和教师调用学生作答入口
- **THEN** 分别 401/1100 和 403/1200，无提交或任务

#### Scenario: SB-F03 他人、外班和缺失
- **GIVEN** 本班另一学生及 B 班用户知道目标提交或任务标识
- **WHEN** 分别尝试直读本人状态入口、成绩、任务并对照缺失标识
- **THEN** 404/1300 同构，教师只能走本班测验授权视图，无作答、答案或成绩泄露

#### Scenario: SB-F04 回滚与 broker 不可用
- **GIVEN** 库可在同事务任意写入处注入失败，broker 可单独停机且未满额
- **WHEN** 先注入失败，再恢复 DB 并停 broker 受理另一请求，最后恢复 broker
- **THEN** 失败返回 503/1500 且无孤儿提交、任务或 outbox；第二次 202，随后可恢复出队并只得到一份生效结果

#### Scenario: SB-F05 并发提交与 ACK 前中断
- **GIVEN** 同一学生并发发出等价与新键请求，且可在结果事务提交前及提交后 ACK 前分别终止 worker
- **WHEN** 重放提交、重复投递，分别在两个断点终止并恢复
- **THEN** 等价请求同 202 和任务 ID，新键 409/1401，每份提交只一份冻结作答及生效成绩；提交前中断后真实重算增加执行次数，提交后重投只增加投递观测
