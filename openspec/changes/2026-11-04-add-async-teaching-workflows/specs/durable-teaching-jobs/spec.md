## Purpose

为候选题与可选后台索引提供同一持久任务契约，使受理、投递、执行和恢复能追踪，并确保至少一次投递只产生一份生效结果。

## ADDED Requirements

### Requirement: JB-01 事务性受理、投递与恢复

系统 SHALL 同事务持久化业务工作、任务和发件箱，取得 Kafka 对目标 topic 的交付回执后才记已投递，结果、重试安排或隔离记录持久化后才手动提交连续消费 offset。重投、并发及租约失效 SHALL 以代次和唯一键收敛；瞬态有界退避、永久错误终止、耗尽可追踪死信。授权状态查询无执行副作用，授权重放不能覆盖成功结果。

#### Scenario: JB-N01 正常事务与脱敏观测
- **GIVEN** 同一 Compose 内 MySQL、Kafka、投递器与 worker 均可用
- **WHEN** 受理任务并观察 outbox、消息、状态及业务结果
- **THEN** 先有持久受理，再有确认投递及终态；消息仅引用和版本，状态可读、轮询到终态停止，观测可关联且不含敏感内容

#### Scenario: JB-B01 退避、死信和授权重放
- **GIVEN** 任务依赖可控且有固定次数上限
- **WHEN** 注入连续瞬态错误至耗尽，恢复依赖后由获授权主体重放
- **THEN** 有间隔和有界次数，失败及死信可追踪；获准重放新代次共享业务去重，最多一份结果

#### Scenario: JB-F01 非法消息与永久错误
- **GIVEN** 测试可注入坏消息或已不符合业务版本的任务
- **WHEN** 发送畸形/不支持版本的消息并执行永久失败任务
- **THEN** 非法消息隔离且不执行，永久错误终止且无瞬态重试，无伪造成功

#### Scenario: JB-F02 无权重放或撤权
- **GIVEN** 有可重放失败，另有待执行的本班教师出题或索引任务
- **WHEN** 未授权者尝试重放，再撤销原教师业务资格后调度原任务
- **THEN** 越权拒绝无新代次；可撤销任务取消且不发布，已有人工测验流程可继续

#### Scenario: JB-F03 跨班与缺失查询
- **GIVEN** A 班主体知道 B 班或同班他人任务 ID
- **WHEN** 读取或请求重放，并对照不存在 ID
- **THEN** 404/1300 同构，无目标字段及调度副作用

#### Scenario: JB-F04 Kafka 回执丢失和目标 topic 不可用
- **GIVEN** 任务和 outbox 已提交，Kafka 可注入目标 topic 不可用、交付回执丢失及重启
- **WHEN** 触发投递后恢复连接和目标 topic
- **THEN** 目标不可用或未确认不标已投递，恢复可重发同事件，允许重复但只一份结果，无丢失任务

#### Scenario: JB-F05 陈旧租约及并发执行
- **GIVEN** worker 已认领但未提交且租约可过期
- **WHEN** 停 worker，触发回收和并发再认领，再释放旧执行者
- **THEN** 新有效租约可完成，旧执行者不得覆盖或发布结果，待办不孤立

#### Scenario: JB-F06 异步积压和优雅停机
- **GIVEN** 出题与索引有独立配额，积压达到上限
- **WHEN** 持续提交并发停机信号，随后恢复
- **THEN** 达到上限的新请求 429/1600，已有待办保留并恢复，指标能查最老等待、死信及重试，人工测验仍可提交并评分

#### Scenario: JB-B02 停消费与提交 offset 前中断
- **GIVEN** 模型可用且候选题 worker 已停，测试可在结果提交后中断消费者
- **WHEN** 受理任务并查询，再恢复 worker，在提交 offset 前终止后再次启动
- **THEN** 初次 202 不等待模型，查询无写入；恢复后结果最终可见，重放只增加消费观测，只有一批草稿
