## 实施交接与验证责任

各实现组按 [CK-03](../2026-11-04-add-skeleton/specs/skeleton-check/spec.md#requirement-ck-03-实现组可运行交接) 交接。确定性闭环验证建题发布和正式提交 201，队列验证投递与消费者恢复，候选题验证 202 受理及终态回读。选做后台索引单独记录构建与读取。第 5 组执行完整闭环自动化验证，7.4 完成变更收尾，7.1–7.3 引用课末安全预检结果。

## 1. 上游复核与数据准备

- [ ] 1.1 核对可运行骨架与认证基线，冻结班级、章节、题目快照及两班合成数据。人工建题、测验与规则评分先实现，反馈指标接入时核对 FB-01，候选题组核对有限证据和固定提示配置，后台索引组核对已同步的 IX-01。由课程联络人记录候选题 202 与课件口径差异。若要求异步评分，先修订受影响任务的规约。
- [ ] 1.2 用 `project-data-change` 建立数据字典、迁移与恢复矩阵。按组增量迁移，真实 MySQL 核对组合外键、唯一约束、冻结名单/快照、作答及评分依赖和任务/发件箱事务；空库、上游库、重跑、回退及删除恢复均留证，覆盖 QZ-F04、SB-F04、JB-F05、IX-F06。

## 2. 人工教学闭环与规则评分

- [ ] 2.1 实现人工单选/判断题、版本、审核及审计，先走人工题库，验证 QB-N01、QB-F01、QB-F02、QB-F03 的手工部分，断言答题角色无题库访问、编辑后的审核失效。
- [ ] 2.2 实现测验组卷、不可变发布、服务端时间和角色分离视图。验证 QZ-N01、QZ-B01、QZ-F01、QZ-F02、QZ-F03、QZ-F04、QZ-F05，留两班快照、发布回滚和提前泄露旁路证据；课内发布保持同步。
- [ ] 2.3 在 MySQL 接通草稿、201 正式提交与确定性评分，验证 SB-N01、SB-B01/B02、SB-F01–F05。用真实 MySQL 复验事务回滚、单个参与行持锁时其他学生可提交、截止前集中提交和同人幂等。用自动化浏览器验证刷新或会话到期并重新登录后的草稿恢复。

- [ ] 2.4 实现错题和看板，按冻结名单、已评分分母及 FB-01 口径。反馈接口未接通时先验证测验指标，未解决数显示未接入，不能以 0 代替，验证 LI-N01、LI-B01、LI-F01、LI-F02、LI-F03、LI-F04、LI-F05；用固定算例作自动化比对，核对 0、评分写失败回滚及来源撤销、两班权限。同步页面四态、术语与 OpenAPI。

## 3. Kafka 投递、消费与恢复

- [ ] 3.1 登记 Kafka KRaft、客户端、镜像摘要及课程环境容量。用扩展 Compose 验证显式 topic、持久卷、独立消费组、交付回执、目标 topic 不可用与断线恢复。保留 JB-N01、JB-F04、JB-F06 证据。
- [ ] 3.2 实现公共任务、事务性 outbox、稳定事件 ID、租约及结果唯一键。验证 JB-N01、JB-F01、JB-F04、JB-F05，注入回执丢失、重复投递、过期租约及消费位置落后于保留期，验证待办对账可恢复。
- [ ] 3.3 实现分区内顺序处理、手动连续提交 offset、退避、终态及死信 topic。验证 JB-B01/B02、JB-F01–F06，覆盖消费者再均衡、数据库提交后且 offset 提交前崩溃、死信发布失败以及过期执行者无写入。

## 4. AI 候选题接入

- [ ] 4.1 用固定练习提示配置和第 4 课有限证据验证候选结构、来源和真实模型可用性。验证 QB-N02、QB-B01、QB-F01–F05，无证据不调用模型，MCP 服务停机不影响候选题。
- [ ] 4.2 接入异步 202 候选题，授权查询状态和批次结果。用 project-prompt-eval 固定拒答、无证据、伪引用及候选结构回归，区分真实网关和替身证据。

## 5. 核心闭环及课程三项判据

- [ ] 5.1 用 AI 候选题复现 202 快速受理、停 worker 后恢复和 offset 重放去重（JB-B02）。分别记录受理、任务完成时延与样本量，不预设速度差。客观评分独立测提交延迟及截止竞态。
- [ ] 5.2 按 `project-add-tests` 将三项判据和 SB-F04、JB-F04、JB-F05 写入 `apitest/cases/` 或与之共享的真实依赖套件，纳入 `make check`；核对 API、业务码、持久化、确认及消费者副作用。提交并发和事务证据分别放 `reports/risk-concurrency.md` 与 `reports/risk-transaction.md`，写实测工具、对象、判据和结果，区分重投次数与业务生效次数。
- [ ] 5.3 用真实 MySQL、A/B 班夹具及自动化浏览器回归走通手工建题、测验、错题、看板，分别停 Kafka、模型和向量复验。再用真实 Kafka 和模型验证候选题支线。核心闭环自动化验证通过且选择后台索引后才执行第 6 组。正式人工业务走查由项目最终验收执行。

## 6. 后台索引提高项

- [ ] 6.1 复用第 4 课构建和发布服务，迁移客户端及 OpenAPI 到 202 和只读轮询；保留原文入库、旧索引可见性、教师权限及构建诊断。真实 MySQL/Qdrant/Kafka 验证 IX-N01、IX-B01、IX-B02、IX-F01、IX-F02、IX-F03；核对已上线同步客户端的切换和回退，发布前避免混流。
- [ ] 6.2 验证 IX-F04、IX-F05、IX-F06、JB-F02，注入向量部分写入、数据库失败、重复投递、旧租约、撤权和并发删除。核对 MySQL、Qdrant、已发布关键词和恢复后的向量，按实际接入能力做上游回归。

## 7. 实现交付与课末安全证据交接

先执行 7.4，交付可运行候选及 5.2 的并发和事务证据。随后由[课末安全预检](../2026-11-04-add-post-async-security-precheck/tasks.md)执行课程安全实测，7.1–7.3 逐项引用同一证据。

- [ ] 7.1 引用安全预检 1.1–1.2 的候选与课程 SEC-01–04 实测，保留受保护入口、写入副作用及评分写路径等价确认状态，指向 `reports/security-precheck.md` 与 `reports/risk-authz.md`。
- [ ] 7.2 引用安全预检 2.1–2.3 的课程 SEC-05–07 资产扫描与技能审计结果，指向 `reports/security-baseline.md` 及相应审计记录。
- [ ] 7.3 引用安全预检 3.2–3.4 的同伴独立复验、真实红项或全绿缺项、选做准备和六份脱敏报告路径检查。
- [ ] 7.4 用 `project-review` 复核实际门禁、课程三项判据、两班授权、撤权/恢复、README、页面、数据字典、Swagger 和版本/回滚记录。最终运行 `openspec validate 2026-11-04-add-async-teaching-workflows --strict` 与 `make check`，向 `docs/changes/2026-11-04-add-async-teaching-workflows.md` 汇总证据、失败复测及未执行项。完成本变更的代码评审，实施、评审及运维实名由小组确认。交接时单列课程等价与安全预检待办。此项完成后交候选到课末安全预检。课程范围确认及相应证据齐备后再登记演示标签。
