# 认证与班级资料原文设计

## Context

第 7 课代码当前提供 Flask 工厂、基于端点及方法的授权登记、`Identity` 与 `ResourceScope`、失败关闭、请求标识及 MySQL/Qdrant 健康检查。当前身份解析器默认为空，骨架没有登录或资料持久层。本课复用 [骨架授权规约](../2026-11-04-add-skeleton/specs/skeleton-access/spec.md) 的策略入口和资源边界。复用 AC-01 的精确公开路由装配和 AC-02 的服务端授权。SQLAlchemy 仓储放在 `app/adapters/`，迁移放仓库独立迁移目录，由本变更引入并锁定 SQLAlchemy 和迁移工具版本；装配层注入仓储，业务服务划定事务边界。

## Goals / Non-Goals

- 形成统一的当前身份解析、班级作用域、可撤销令牌及原文生命周期，覆盖认证、授权、入库、下载与清理四组。
- 原文及元数据使用同一业务数据库；Qdrant 健康降级沿用骨架，资料业务无需访问 Qdrant。章节、向量、出处和索引副本生命周期由后续变更引入。

## Decisions

### 1. 服务端 Cookie 会话

- 使用 32 字节随机数生成不透明会话标识，以 base64url 编码。数据库只存唯一 SHA-256 摘要，事务成功后通过 `Set-Cookie` 签发 `__Host-campusclaw_session`，属性为 `HttpOnly; Secure; SameSite=Strict; Path=/`，省略 `Domain`、`Expires` 和 `Max-Age`。服务端按 UTC 设置绝对有效期 30 分钟，无续期接口。每账号一条当前会话，通过账号唯一键和账号行锁串行化登录、注销和口令重置。并发登录仅最后成功提交的会话有效，页面禁用重复提交且不自动重放登录。注销仅撤销请求对应的当前会话并清除 Cookie，旧会话的迟到注销不得撤销新会话。
- 口令使用现有 Werkzeug 的加盐 scrypt，拟定 1–128 个 UTF-8 字节，按原样比较。登录名使用 1–64 个 ASCII 字母、数字、下划线或短横线，小写规范化后全局唯一。未知账号使用相同算法和参数的固定占位哈希；错误口令、停用和未知账号均走哈希验证并统一公开响应。口令校验在事务外执行，进入换发事务时重新核对账号状态与已验证的口令哈希。账号停用和重置口令同事务撤销会话。每次受保护请求按会话摘要联查当前账号与班级，Cookie 不承载角色或班级。鉴权使用一致的读取快照，已授权的在途读可完成，撤销后的新授权请求失败。写入事务再次核对当前会话和权限，以账号行锁与撤销、降权等身份变更序列化。
- 浏览器和 API 使用同一 HTTPS 源。后端从必填环境配置 `APP_PUBLIC_ORIGIN` 读取规范的 HTTPS 源，使用精确值校验所有已登记的写请求（含公开登录）的 `Origin`，并要求自定义头 `X-CampusClaw-Request: same-origin`。应用不允许跨源带凭据请求。缺失、空值或不匹配的来源，以及缺少规定请求头均失败关闭；不得用客户端 Host 或转发头推导可信源。授权失败保留原有 401/403 顺序，来源拒绝在解析请求体和业务写入前返回 403/1200。HTTPS 终止在可信入口，本地浏览器验收使用独立 HTTPS 源及相同配置。参考 [OWASP CSRF 指南](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。
- 会话标识只经 Cookie 往返。响应 JSON、URL、JavaScript、浏览器 Web Storage 和日志不得包含会话标识。认证与资料响应禁止缓存。选择服务端会话是为了立即撤销并保持刷新后的登录状态。课程联络人核对课件三项验收并留证。安全规范中的凭据边界与本方案一并提交人工安全复核。后续同源 Swagger 和流式 Fetch 接入需沿用同一 Cookie 和写请求防护；其课件中单列的 Bearer 试调要求由对应变更评审。

### 2. 路由、权限与页面

| 方法及路径 | 许可 | 成功契约 |
| --- | --- | --- |
| GET/HEAD `/login`、POST `/api/v1/auth/sessions` | 登录例外逐方法登记，POST 校验同源 | 空数据登录界面；POST 接收 JSON 登录名与口令，返回 200/0、`expires_at` 并以 Cookie 签发会话 |
| GET、DELETE `/api/v1/auth/sessions/current` | 有效身份，仅当前会话 | 200/0；GET 返回当前账号公开标识、角色与班级标识；DELETE 确认撤销 |
| GET `/api/v1/materials`、GET `/api/v1/materials/{id}` | 本班师生 | 200/0；列表只有公开资料元数据，详情附预览正文 |
| POST `/api/v1/materials` | 教师 | 201/0；返回资料 ID、标题、顺序、原文版本与元数据修订号 |
| PATCH、DELETE `/api/v1/materials/{id}` | 本班教师 | 200/0；PATCH 更新标题或顺序，DELETE 确认删除 |
| GET `/api/v1/materials/{id}/download` | 本班师生 | 200 附件字节，`Content-Type: application/octet-stream`、安全的 `Content-Disposition: attachment`、`X-Content-Type-Options: nosniff` |

- 复用骨架 `X-Request-ID`、统一响应和路由错误。公共探针仍独立。只为登录页 GET/HEAD 和登录 API POST 增设公开声明，受保护方法逐项登记，未登记入口维持 403/1200，非法方法维持 405/Allow。受保护 API 的校验顺序为身份→功能权限→参数→资源归属与业务状态→原文或持久化动作；依赖错误失败关闭。客户端身份头忽略，未声明查询、表单或 JSON 字段返回 400/1000。格式合法 ID 在当前班级过滤后找不到时返回 404/1300，与已删除或跨班同构。下载失败使用同一 JSON 错误，先取完有界正文再发送附件头。含凭据或资料的响应使用 `Cache-Control: no-store`。
- 页面沿用 `/login`、`/materials`、`/materials/{id}`、`/console`。登录页内嵌启动 CSS/JS，其他资源若需独立请求须精确登记。未登录或已到期时，页面专用 401 处理规则重定向至登录页，API 仍返回 401。返回地址只接受 `/materials`、合法资料详情路径或 `/console`，禁止外部地址、路径歧义及任意查询或片段。有效会话可直访及刷新，重登录后以当前角色重新授权返回路径。下载使用授权同源 API；Fetch 下载使用后撤销临时对象 URL。资料视图具备加载、正常、空、错误四态，预览只写文本节点，错误提示关联请求标识。
- 登录页采用深红渐变品牌区与白色表单区，右侧使用有标签的账号和口令输入、主按钮与就地错误提示。资料与教师工作台沿用浅灰底、白色侧栏和班级顶栏、浅红选中背景与细边框圆角卡片。顶栏显示当前身份和退出。导航只列本变更已实现且当前角色有权访问的入口；数据来自受保护 API。窄屏单列，支持键盘与清晰焦点，正文对比度符合 PROD-09。
- 列表 `page=1`、`page_size=20`，上限 100，超过上限截断；非正整数或未知筛选返回 400。按顺序值、资料 ID 升序排列，默认顺序 0。标题去首尾空白后 1–120 个字符；顺序为 0–1000000 的整数。PATCH 提交当前元数据修订号及标题或顺序，事务内比较版本，旧版本为 409/1400；相同目标值的有效请求可返回当前行且无写入。正文不可经 PATCH 修改，元数据更新独立递增修订号。删除重复请求返回 404，无新增副作用。

### 3. 数据、输入与幂等

| 实体 | 计划字段和约束 |
| --- | --- |
| 班级 `classes` | 主键、唯一班级编码、名称、UTC 创建时间 |
| 账号 `accounts` | 主键、全局唯一规范登录名、口令哈希、启用状态、单一 `class_id` 外键、教师或学生角色、UTC 创建和更新时间 |
| 登录会话 `auth_sessions` | 账号唯一外键、唯一令牌摘要、签发/到期/撤销 UTC 时间。到期、撤销的记录在下次换发覆盖或在失效后 24 小时内清理，保留去内容审计 |
| 资料 `materials` | 稳定主键、班级与创建人外键、标题、排序值、来源格式、媒体类型、字节数、原文版本、元数据修订号、UTC 创建/更新时间；班级与排序及 ID 联合索引 |
| 正文 `material_bodies` | 资料主键兼外键，原文字节以 MEDIUMBLOB 保存，主键保证一对一；元数据与正文同事务创建和删除 |
| 上传幂等与删除凭证 | 上传幂等按班级、创建人、键唯一，保存请求指纹、结果标识及最小响应字段，删除时标记失效；删除凭证只保留去内容的资料标识和时间，支持审计及恢复 |

- 班级、账号、资料 ID 采用服务端生成的不透明 UUID；班级和资料归属由服务端赋值。种子命令仅允许隔离开发/测试环境，使用固定合成班级编码及四个合成账号标识，口令从测试私有环境读取，重跑无重复且不覆盖现有角色或口令。实施时补集中数据字典和留存责任。
- JSON 接受 `title` 与 `text`，按 UTF-8 编码；multipart 仅接受标题和单个文件。原文按实际字节累计，上限 1 MiB。此为保存、预览和下载上限。严格解码后忽略一个开头 BOM、保留换行，以 Unicode 码点计数；超出首版检索上限 32,000 码点仍可保存，响应提供长度和容量提示，上传界面提交前显示「仅保留原文，要参与检索请按章节拆成每份不超过 32,000 字符后重新上传」。拟定 JSON 请求体上限 8 MiB、multipart 2 MiB（含封装）；应用对超限统一 400/1000，并在进入解析及读取时限定资源。文件只允许大小写不敏感的 `.txt`、`.md`、`.markdown`；对应允许 `text/plain`、`text/markdown`（Markdown 可由客户端声明 `text/plain`），或通用 `application/octet-stream`。声明校验后仍按实际字节严格 UTF-8 解码，检查空白与 NUL。UTF-8 BOM 仅在预览解码时忽略，保留原始字节及换行供下载和版本追踪。文件名限单一基名、最多 255 UTF-8 字节，拒绝分隔符、驱动器/冒号、控制字符及 `.`、`..`。下载名由服务端资料 UUID 加允许扩展名生成，绝不以客户端文件名构造路径或响应头。
- 鉴权在读取上传体之前完成；有界解析使用内存流，核对应用、WSGI 和网关的 multipart 缓冲配置，避免自动落盘。事务内写元数据、正文和幂等结果，失败共同回滚。上传必须提供 `Idempotency-Key`（1–64 位 ASCII 字母、数字、短横线或下划线，拟定有效期 24 小时）。指纹覆盖规范标题、来源格式及原文字节。并发由唯一键与事务裁决；提交结果未知时允许同键重试，查到已提交结果便重放首个业务结果并分配新请求标识。键冲突或对应资料已删为 409/1400。数据库无法判断提交结果时仍返回依赖错误，恢复后按键核对。
- 文件存储取舍采用数据库作为唯一在线原文存储，避免文件与事务脱节。若后续改为独立原文件，启用前须增订规约：先持久化不可见操作记录与预定存储键，再在事务外有界写私有同卷临时文件，以服务端生成的键原子改名；元数据、正文与可读状态同事务提交。正文或提交失败时先核对提交状态，确定未提交则清理暂存和最终文件；失败或进程中断由持久化记录保留键、阶段、重试次数与下次重试时间。恢复器按操作键互斥核对已提交状态，幂等回收孤儿文件，禁止删除已就绪文件。删除先撤销可读性并记清理任务，再幂等删除文件，失败重试并告警，达到上限交运维处理。该方案还需验证路径限制、并发、断电恢复及无残留后方可启用。

## Risks / Trade-offs

- Cookie 会自动随同源请求发送 → 所有写入在解析请求体前校验可信源与规定请求头，覆盖跨站和同站不同子域；过期后引导重新登录，错误响应不泄露会话。
- 数据库正文增长与删除复活 → 入库和下载保持同步且有界，删除事务同时记凭证。正文和资料按 DATA-07/08 与 OPS-10 留存，原文所属学期结束后 30 天内清理，备份 14 天轮转。隔离介质可定向清除时清除，否则到期销毁；删除清单在独立恢复介质保留至覆盖备份窗口，恢复上线前重放删除与到期清理，缺清单阻断上线。
- 日志与验收取证泄漏 → 延续单行 JSON 及请求标识，日志仅记状态、阶段、耗时、故障类别和脱敏主体；证据记录正文长度和测试字节比对结果，不记录凭据、摘要或原文。去内容审计覆盖登录换发、注销、账号变更和资料写删。

## Migration Plan

1. 在已运行验证的骨架基线上核对授权、Compose 与门禁，确认 MySQL 迁移入口、UTC 和容量。先登记数据字典、学期截止、到期时间及实名责任人。
2. 以新增表、约束及索引的版本化迁移扩展空库与骨架库，验证重跑。仅在隔离环境写合成种子，执行真实 MySQL 权限、事务、并发、清理与恢复验收。
3. 应用回退至上一个可运行骨架制品时保留新增表和删除凭证，先验证旧版能对扩展后的库启动。仅在隔离副本演练数据库降级，记录新增表移除导致的数据丢失与恢复步骤。生产或课程共享实例按实际授权执行。
