# 认证与班级资料原文设计

## Context

第 7 课代码当前提供 Flask 工厂、基于端点及方法的授权登记、`Identity` 与 `ResourceScope`、失败关闭、请求标识及 MySQL/Qdrant 健康检查。当前身份解析器默认为空，骨架没有登录或资料持久层。本课复用 [骨架授权规约](../2026-11-04-add-skeleton/specs/skeleton-access/spec.md) 的策略入口和资源边界。实施前以实际运行基线核对 AC-01/02 的装配范围，尤其是探针独占公开的条款。若届时主规格仍将其限定为全应用永久规则，先更新变更规约并重新送审。

## Goals / Non-Goals

- 形成统一的当前身份解析、班级作用域、可撤销令牌及原文生命周期，覆盖认证、授权、入库、下载与清理四组。
- 原文及元数据使用同一业务数据库；Qdrant 健康降级沿用骨架，资料业务无需访问 Qdrant。章节、向量、出处和索引副本生命周期由后续变更引入。

## Decisions

### 1. 可吊销 Bearer 与课程口径

- 使用高熵不透明令牌（32 字节随机数，base64url 表示），只在登录提交成功后返回原值，服务端存唯一 SHA-256 摘要。过期判断使用 UTC，拟定绝对有效期 30 分钟，到期即失效。每账号一条当前会话，以账号唯一键及账号行锁串行化登录、注销和口令重置。换发在事务内替换当前会话；并发登录只有最后成功提交的令牌有效，故 UI 禁止重复提交且登录请求不自动重放。注销仅撤销请求所对应的当前令牌；旧令牌的迟到注销不得撤销新会话。
- 口令使用现有 Werkzeug 的加盐 scrypt，拟定 1–128 个 UTF-8 字节，按原样比较。登录名使用 1–64 个 ASCII 字母、数字、下划线或短横线，小写规范化后全局唯一。未知账号使用相同算法和参数的固定占位哈希；错误口令、停用和未知账号均走哈希验证并统一公开响应。口令校验在事务外执行，进入换发事务时重新核对账号状态与已验证的口令哈希。账号停用和重置口令同事务撤销会话。每次受保护请求按令牌摘要联查当前账号与班级，角色或班级不从令牌读取。鉴权使用一致的读取快照，已授权的在途读可完成，撤销后的新授权请求失败。写入事务再次核对当前会话和权限，以账号行锁与撤销、降权等身份变更序列化。
- 通过 Cookie 示例的四项语义核对拟议映射。登录换发对应令牌替换，注销对应数据库会话撤销，当前数据库身份对应逐次联查，枚举防护对应统一结果和等成本口令工作。传输由 Cookie 自动携带改为显式 Authorization 头；页面关闭或刷新即丢失令牌。浏览器与 API 同源，令牌只存 JavaScript 内存，响应禁止缓存，经 HTTPS 传输。后续 Swagger 临时填入同一 Bearer 且禁用持久授权；SSE 采用可附 Authorization 头的 Fetch 读取，订阅和重连重新校验。放弃纯自包含 JWT，以支持即时撤销。
- 课程联络人实施前核对第 3 课认证与实践页，提交四项等价证据设计、浏览器行为差异和三条验收给课程评审。关闭条件为记录评审人、日期、是否接受及出处；要求原样 Cookie 时，先修订方案、规约和任务并重新校验。

### 2. 路由、权限与页面

| 方法及路径 | 许可 | 成功契约 |
| --- | --- | --- |
| GET/HEAD `/login`、POST `/api/v1/auth/sessions` | 登录例外逐方法登记 | 空数据登录界面；POST 接收 JSON 登录名与口令，返回 200/0、`access_token`、`token_type=Bearer`、`expires_at` |
| GET、DELETE `/api/v1/auth/sessions/current` | 有效身份，仅当前会话 | 200/0；GET 返回当前账号公开标识、角色与班级标识；DELETE 确认撤销 |
| GET `/api/v1/materials`、GET `/api/v1/materials/{id}` | 本班师生 | 200/0；列表只有公开资料元数据，详情附预览正文 |
| POST `/api/v1/materials` | 教师 | 201/0；返回资料 ID、标题、顺序、原文版本与元数据修订号 |
| PATCH、DELETE `/api/v1/materials/{id}` | 本班教师 | 200/0；PATCH 更新标题或顺序，DELETE 确认删除 |
| GET `/api/v1/materials/{id}/download` | 本班师生 | 200 附件字节，`Content-Type: application/octet-stream`、安全的 `Content-Disposition: attachment`、`X-Content-Type-Options: nosniff` |

- 复用骨架 `X-Request-ID`、统一响应和路由错误。公共探针仍独立。登录是唯一新增匿名例外，受保护方法逐项登记，未登记入口维持 403/1200，非法方法维持 405/Allow。受保护 API 的校验顺序为身份→功能权限→参数→资源归属与业务状态→原文或持久化动作；依赖错误失败关闭。客户端身份头忽略，未声明查询、表单或 JSON 字段返回 400/1000。格式合法 ID 在当前班级过滤后找不到时返回 404/1300，与已删除或跨班同构。下载失败使用同一 JSON 错误，先取完有界正文再发送附件头。含凭据或资料的响应使用 `Cache-Control: no-store`。
- 页面沿用 `/login`、`/materials`、`/materials/{id}`、`/console`。登录页载入同一文档的应用界面，登录后通过 History API 切换视图，统一用 Fetch 注入内存 Bearer；下载同样经 Fetch，临时对象 URL 使用后撤销。直接导航或刷新受保护页面时由页面入口的认证拒绝分支引回 `/login`，只返回固定重定向，不带班级数据，业务 API 仍返回 401。教师工作台在角色变化时按当前身份刷新。资料视图具备加载、正常、空、错误四态，预览只写文本节点，错误提示关联请求标识。登录页不依赖额外匿名数据接口。
- 列表 `page=1`、`page_size=20`，上限 100，超过上限截断；非正整数或未知筛选返回 400。按顺序值、资料 ID 升序排列，默认顺序 0。标题去首尾空白后 1–120 个字符；顺序为 0–1000000 的整数。PATCH 提交当前元数据修订号及标题或顺序，事务内比较版本，旧版本为 409/1400；相同目标值的有效请求可返回当前行且无写入。正文不可经 PATCH 修改，元数据更新独立递增修订号。删除重复请求返回 404，无新增副作用。

### 3. 数据、输入与幂等

| 实体 | 计划字段和约束 |
| --- | --- |
| 班级 `classes` | 主键、唯一班级编码、名称、UTC 创建时间 |
| 账号 `accounts` | 主键、全局唯一规范登录名、口令哈希、启用状态、单一 `class_id` 外键、教师或学生角色、UTC 创建和更新时间 |
| 登录会话 `auth_sessions` | 账号唯一外键、唯一令牌摘要、签发/到期/撤销 UTC 时间。到期、撤销的记录在下次换发覆盖或在失效后 24 小时内清理，保留去内容审计 |
| 资料 `materials` | 稳定主键、班级与创建人外键、标题、排序值、来源格式、媒体类型、字节数、原文版本、元数据修订号、UTC 创建/更新时间；班级与排序及 ID 联合索引 |
| 正文 `material_bodies` | 资料主键兼外键，原文字节以 MEDIUMBLOB 保存，主键保证一对一；元数据与正文同事务创建和删除 |
| 上传幂等与删除凭证 | 上传幂等按班级、创建人、键唯一，保存请求指纹、结果标识及最小响应字段，删除时标记失效；删除凭证只保留去内容的资料标识和时间，支持审计及恢复 |

- 班级、账号、资料 ID 采用服务端生成的不透明 UUID；班级和资料归属由服务端赋值。种子命令仅允许隔离开发/测试环境，使用固定合成班级编码及四个合成账号标识，口令从测试私有环境读取，重跑无重复且不覆盖现有角色或口令。实施时补集中数据字典和留存责任。
- JSON 接受 `title` 与 `text`，按 UTF-8 编码；multipart 仅接受标题和单个文件。原文按实际字节累计，上限 1 MiB。拟定 JSON 请求体上限 8 MiB、multipart 2 MiB（含封装）；应用对超限统一 400/1000，并在进入解析及读取时限定资源。文件只允许大小写不敏感的 `.txt`、`.md`、`.markdown`；对应允许 `text/plain`、`text/markdown`（Markdown 可由客户端声明 `text/plain`），或通用 `application/octet-stream`。声明校验后仍按实际字节严格 UTF-8 解码，检查空白与 NUL。UTF-8 BOM 仅在预览解码时忽略，保留原始字节及换行供下载和版本追踪。文件名限单一基名、最多 255 UTF-8 字节，拒绝分隔符、驱动器/冒号、控制字符及 `.`、`..`。下载名由服务端资料 UUID 加允许扩展名生成，绝不以客户端文件名构造路径或响应头。
- 鉴权在读取上传体之前完成；有界解析使用内存流，核对应用、WSGI 和网关的 multipart 缓冲配置，避免自动落盘。事务内写元数据、正文和幂等结果，失败共同回滚。上传必须提供 `Idempotency-Key`（1–64 位 ASCII 字母、数字、短横线或下划线，拟定有效期 24 小时）。指纹覆盖规范标题、来源格式及原文字节。并发由唯一键与事务裁决；提交结果未知时允许同键重试，查到已提交结果便重放首个业务结果并分配新请求标识。键冲突或对应资料已删为 409/1400。数据库无法判断提交结果时仍返回依赖错误，恢复后按键核对。
- 文件存储取舍采用数据库作为唯一在线原文存储，避免文件与事务脱节。若后续改为独立原文件，启用前须增订规约：先持久化不可见操作记录与预定存储键，再在事务外有界写私有同卷临时文件，以服务端生成的键原子改名；元数据、正文与可读状态同事务提交。正文或提交失败时先核对提交状态，确定未提交则清理暂存和最终文件；失败或进程中断由持久化记录保留键、阶段、重试次数与下次重试时间。恢复器按操作键互斥核对已提交状态，幂等回收孤儿文件，禁止删除已就绪文件。删除先撤销可读性并记清理任务，再幂等删除文件，失败重试并告警，达到上限交运维处理。该方案还需验证路径限制、并发、断电恢复及无残留后方可启用。

## Risks / Trade-offs

- 页面刷新重新登录 → 登录界面明确说明会话已结束，跨页面在同一文档内导航；有效期、体积上限与幂等窗口由小组评审用时钟边界及并发大文件测试确认。
- 数据库正文增长与删除复活 → 入库和下载保持同步且有界，删除事务同时记凭证。正文和资料按 DATA-07/08 与 OPS-10 留存，原文所属学期结束后 30 天内清理，备份 14 天轮转。隔离介质可定向清除时清除，否则到期销毁；删除清单在独立恢复介质保留至覆盖备份窗口，恢复上线前重放删除与到期清理，缺清单阻断上线。
- 日志与验收取证泄漏 → 延续单行 JSON 及请求标识，日志仅记状态、阶段、耗时、故障类别和脱敏主体；证据记录正文长度和测试字节比对结果，不记录凭据、摘要或原文。去内容审计覆盖登录换发、注销、账号变更和资料写删。

## Migration Plan

1. 在已运行验证的骨架基线上核对授权、Compose 与门禁，确认 MySQL 迁移入口、UTC 和容量。先登记数据字典、学期截止、到期时间及实名责任人。
2. 以新增表、约束及索引的版本化迁移扩展空库与骨架库，验证重跑。仅在隔离环境写合成种子，执行真实 MySQL 权限、事务、并发、清理与恢复验收。
3. 应用回退至上一个可运行骨架制品时保留新增表和删除凭证，先验证旧版能对扩展后的库启动。仅在隔离副本演练数据库降级，记录新增表移除导致的数据丢失与恢复步骤。生产或课程共享实例按实际授权执行。
