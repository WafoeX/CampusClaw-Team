## Purpose

在异步教学任务收尾后的固定候选版本上，为实施人和复验人规定可重复的安全检查和证据交接流程，使后续课次能在相同前置条件下验证缺陷、对比修复结果并复核课程验收。

## ADDED Requirements

### Requirement: PSC-01 冷启动与检查准备

实施人 MUST 在异步任务收尾后按 README 冷启动隔离候选，验证 A/B 两班、教师 A、学生 A1/B1、两班资料及可检索数据，列出不少于五个受保护的 HTTP 方法与路径，以及技能、提示词、助手和批改相关写入面。实施人 MUST 补齐缺失的合成身份和数据，再执行受影响的检查。课程 SEC 编号与仓库安全规范编号分别使用。

#### Scenario: PSC-N01 就绪及正向对照
- **GIVEN** 已固定候选版本，独立测试数据和三名账号已准备
- **WHEN** 实施人按 README 冷启动，登录三名账号并分别验证合法资料访问、索引命中及教师配置操作
- **THEN** 清单标明实际路由、可用身份、合成数据标识及复跑步骤，正向对照成功后才开始相关负向探测

#### Scenario: PSC-F05 参数错误使探测无效
- **GIVEN** 配置权限测试的正向对照返回 400，或检索请求携带不受支持的作用域参数
- **WHEN** 实施人复核载荷与已登记契约
- **THEN** 将受影响检测记为未取得有效结果，修正测试输入后重跑；参数拒绝不能用作权限或检索隔离通过证据

### Requirement: SEC-01 未登录访问受保护接口

实施人 MUST 逐一重放受保护接口清单中的请求，逐接口记录 HTTP 状态及适用业务码。所有请求均返回 HTTP 401 且无业务数据或写入时判绿，任一有效探测偏离时判红。

#### Scenario: PSC-F01 匿名访问受保护接口
- **GIVEN** 至少五个真实路由及有效请求已由授权身份验证可用
- **WHEN** 去掉 Cookie 和令牌后逐个重放，保留其他合法请求条件
- **THEN** 每个受保护 API 预期 401，无业务数据或写入，逐条记录实际 HTTP 状态及适用业务码，任何偏离判红

### Requirement: SEC-02 跨班访问与跨班检索

实施人 MUST 分别验证讲义按标识访问和知识库检索两条链路，并将可在演示机复跑的命令、检查对象、判据和实际结果归档至 `reports/risk-authz.md`。两条链路均满足预期时判绿，任一有效探测偏离时判红。

#### Scenario: PSC-F02 跨班资源和检索
- **GIVEN** B 班讲义存在且 B1 可读，A 班专属检索词在 A1 账号下能命中
- **WHEN** A1 用 GET `/api/v1/materials/{id}` 分别请求 B 班讲义和不存在的合法 ID，再用 B1 身份向 POST `/api/v1/searches` 提交已由 A1 验证命中的关键词查询，使用相同模式并省略章节范围
- **THEN** 两个讲义请求预期均为 404/1300，公开文案及 data 一致，B1 检索成功且结果为空，无他班片段、出处或数量；记录实际状态、结果数及判定

### Requirement: SEC-03 学生修改技能、提示词与助手配置

实施人 MUST 分别对技能、提示词模板及助手的真实教师写入口执行学生越权检查。三个入口均返回 HTTP 403 且无写入时判绿，任一有效探测偏离时判红。

#### Scenario: PSC-F03 学生调用教师配置写入
- **GIVEN** 三类合成配置存在，教师正向请求证明载荷、版本及写入入口有效
- **WHEN** A1 使用有效会话和同源条件，分别向候选的技能、提示词与助手配置写入口发送合法更新请求，当前规约对应 PATCH `/api/v1/skills/{id}`、`/api/v1/prompt-templates/{id}`、`/api/v1/assistants/{id}`
- **THEN** 预期均为 403/1200，前后配置、版本和相关业务副作用一致；若发生写入，记录受影响记录与变化

### Requirement: SEC-04 绕过技能直接调用批改写入

实施人 MUST 使用学生身份直接调用实际批改写入入口，比较请求前后的库内记录。按入口契约拒绝且无写入时判绿，入口放行或发生未授权写入时判红。若候选仅在内部服务评分，路由清单、直接探测与快照作为候选替代证据，课程等价结论须经任课教师确认。

#### Scenario: PSC-F04 学生直接调用批改写入路径
- **GIVEN** A1 拥有正常提交资格，另有一条可读的合成提交与已知评分、任务和发件箱基线
- **WHEN** A1 不经过技能或正常提交入口，直接尝试触发批改写入
- **THEN** 预期无未授权评分、提交、任务或发件箱变化；存在公开入口时按其实际契约验证权限拒绝；若评分仅在内部服务执行，则核对路由清单及直接 HTTP 探测的 404/405，并记录该复现方式的课程确认状态

### Requirement: PSC-02 一键资产检查

仓库 MUST 提供 README 可复现的一键入口，同时尝试课程 SEC-05 和 SEC-06 并报告分项范围、版本、发现数量与执行状态。工具错误、漏扫或阻断项 MUST 使入口非零退出，且保留现有门禁。

#### Scenario: PSC-N02 一键入口记录两个扫描结果
- **GIVEN** 候选 Git 历史、前端产物、运行日志、镜像及锁定依赖均可用
- **WHEN** 实施人按 README 运行 `make check-security`
- **THEN** 命令分别执行秘密扫描和依赖审计，即使一项失败仍记录另一项的执行结果；报告保留各项范围、实际命令、工具版本、退出码和数量

#### Scenario: PSC-F09 依赖或扫描范围不可用
- **GIVEN** 漏洞库不可达、Git 历史不完整、候选产物缺失或技能依赖无法启动
- **WHEN** 运行检查并收集可用项
- **THEN** 其余可执行项仍保留结果，受影响项记未执行或证据不足并注明原因，扫描入口对漏扫或工具故障非零退出

### Requirement: SEC-05 密钥明文泄漏扫描

实施人 MUST 扫描候选完整提交历史、前端产物和运行日志，并按项目要求补扫候选镜像。各范围完整扫描且确认命中数为 0 时判绿。报告 MUST 记录覆盖范围、命中数与脱敏处置结果。

#### Scenario: PSC-F06 命中明文秘密
- **GIVEN** 已执行秘密扫描并确认命中明文凭据
- **WHEN** 实施人记录脱敏命中范围并移交运维责任人
- **THEN** 保留该次红项和非零退出，立即撤销轮换并验证旧凭据失效，按授权清理提交历史及相关副本并复扫确认清除，保留处置与复扫记录；清理未完成时保留课程缺项

### Requirement: SEC-06 依赖漏洞基线

实施人 MUST 审计候选锁定依赖，在 `reports/security-baseline.md` 保存基线报告，分别记录 High 与 Critical 数量。审计有效且两类均为 0，或所有发现均已书面登记处置时，课程项判绿。课程判定与仓库门禁结果分别记录。

#### Scenario: PSC-F07 依赖高危或严重漏洞
- **GIVEN** 依赖审计已完成且发现 High 或 Critical 漏洞
- **WHEN** 实施人核对漏洞编号、受影响版本及书面处置
- **THEN** 未登记处置的发现判课程红；每条均已登记时按课程规则判绿并列出处置依据；合并与发布继续适用仓库 SEC-16 和 REV-06

### Requirement: SEC-07 技能审计日志可追溯

实施人 MUST 通过获准入口执行一次技能，由获授权人员按技能标识及关联请求标识回查实际日志。能追溯操作者、技能标识、结果状态、耗时和用量五类字段时判绿。每个缺口 MUST 单独记录字段名和拟补层级。

#### Scenario: PSC-F08 技能审计记录不可追溯
- **GIVEN** 一次真实的合成技能调用已发生，并有对应的调用标识或关联请求
- **WHEN** 获授权人员按标识回查运行日志或去内容化审计记录
- **THEN** 缺少记录或任一必需字段均判红，记录实际可查字段和拟补层级，无权读取的私人记录不会进入报告

### Requirement: PSC-03 证据归档与后续复测

实施人 MUST 在 `reports/security-precheck.md` 登记候选和接口清单，逐项记录前置条件（身份、数据、环境）、可直接复现的操作、可观测预期、具体实际值、红绿判定和执行者。SEC-01–04 另须说清检查手段、对象、判据和结果。未执行或证据不足属于执行状态，已完成的有效检查只判红或绿。

本课 MUST 保留原始结果，修复留待后续课次，唯一即时修复例外为 SEC-05 命中明文凭据。课程交接 MUST 保留至少一条真实红项，以及后续复跑所需的命令和候选版本。后续课次将修复前后输出和实际提交号归档到 `reports/`。安全自查证据 MUST 单独提交，提交说明注明依据的课程 SEC 编号。

| 固定路径 | 最低证据 |
| --- | --- |
| `reports/security-precheck.md` | 候选环境、身份与数据、受保护和写入接口清单、SEC-01–07 实际记录及 SEC-07 字段缺口。 |
| `reports/risk-authz.md` | SEC-02 四项记录和可在演示机原样复跑的命令。 |
| `reports/risk-concurrency.md` | 重复提交和重复投递的实际计数，生效结果仅一份。 |
| `reports/risk-transaction.md` | 提交与任务同事务的证据；停消费者提交、恢复后正常路径投递恰好一次、零孤儿任务。回执丢失等故障重投另列计数。 |
| `reports/security-baseline.md` | SEC-05 各范围命中数、SEC-06 High/Critical 数量、扫描输出摘要和脱敏处置。 |
| `reports/review-01.md` | 同伴的独立复验、实际判定及署名。 |

#### Scenario: PSC-N03 报告交叉复验
- **GIVEN** 七项检测有实际证据，异步变更已提供并发和事务记录
- **WHEN** 同伴按同一候选、README 和记录独立复现至少两条，再核对异步演示素材
- **THEN** 组内另一人在另一台机器独立复验至少两条，判定一致，并在 `reports/review-01.md` 署名记录手段、对象、判据和结果；六份固定报告均能从仓库打开

#### Scenario: PSC-B01 真实全绿
- **GIVEN** 七项均已取得有效实际结果且全部符合预期
- **WHEN** 核对课程至少保留一条真实红项的要求
- **THEN** 保留真实全绿结果，将至少一条真实红项标记为未满足，交课程方确认后续安排

#### Scenario: PSC-F10 复验不一致或证据不完整
- **GIVEN** 同伴复验结果有分歧、少于两条一致复验，或六份固定报告缺少可复现记录
- **WHEN** 评审人核对候选版本、环境、证据路径和原判定
- **THEN** 保留双方记录和缺项，安排按同一基线复测，课程交接保持待验收

### Requirement: PSC-04 异步演示与后续素材

实施人 MUST 保存课程演示命令，覆盖登录、提交作业返回 202 与任务标识、轮询 `pending → running → succeeded`。同时 MUST 准备有答案、无答案、跨班三类知识库测试问题草稿。

#### Scenario: PSC-N04 复现作业异步提交
- **GIVEN** 候选已提供异步作业提交入口，演示机已按 README 启动且已准备可提交作业
- **WHEN** 学生登录并使用有效认证提交作业，按返回标识轮询
- **THEN** 保存实际 HTTP 202、任务标识、三个状态和可复跑命令；若候选仅能演示 AI 候选题的 202，单列课程差异，任课教师确认等价前作业演示条件保持未满足

#### Scenario: PSC-B02 选做 SEC-08 仅准备注入素材
- **GIVEN** 小组选做课程 SEC-08
- **WHEN** 整理后续课堂使用的合成测试素材
- **THEN** 将一份含指令覆盖的文档与索要提示词原文、改变评分规则、绕过权限各一条提问归入同一目录，本课运行记录保持未执行
