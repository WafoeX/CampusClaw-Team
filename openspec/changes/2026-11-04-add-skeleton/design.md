# 第 7 课运行骨架设计

## Context

[既有规范提案](../establish-project-standards/proposal.md)、[设计](../establish-project-standards/design.md)、[任务](../establish-project-standards/tasks.md)和[证据](../../../docs/changes/establish-project-standards.md)保留原名和历史。[README C7-01–07](../../../README.md#第-7-课任务与当前缺项)与[课程缺口](../../../docs/lesson-07/README.md)是本变更的验收输入。本地仓库已有 Git 和文档，主规格为空，无应用、测试、构建文件或本地运行标签。远程权限、保护规则和教师实际访问属于待核验事实。

## Goals / Non-Goals

建立一个可从干净克隆运行、可探测和可回退的非业务服务，给后续业务提供配置、授权、响应和日志的落点。MySQL 8 与 Qdrant 本课只作运行依赖，使用独立卷和连通探测。业务表、索引集合、真实用户、身份签发、模型接入、队列和教学流程由后续课次建立。

## Decisions

### 一、Flask 分层与显式授权

在 `app/` 内用应用工厂作装配入口，路由层处理 HTTP、输入和响应，业务服务处理授权范围与就绪聚合，仓储和外侧适配器负责 MySQL、Qdrant 实际探测；依赖由装配层注入。路由不直连依赖，业务层不导入 ORM 或外部客户端。使用统一前置检查按匹配到的路由和方法查询授权声明，关闭隐式静态和自动 OPTIONS 入口。先初始化请求标识，再处理 HTTP 错误和授权，使 404、405 和拒绝也能关联日志。应用默认装配无可用身份来源；后续业务接入以当前数据库身份为准，接口检查功能权限，业务服务负责按资源校验归属、限制查询范围，并在写前完成校验。隔离测试注入身份来源和合成资源，正式装配不接受测试身份头、环境开关或透传权限。采用集中检查以避免逐路由手动调用造成遗漏。依据 BE-01–04/05、SEC-01–04。

### 二、锁定构建、外置配置和双探针

多阶段 Dockerfile 按已审阅的版本和摘要构建，锁定 Python 依赖与测试工具，运行层仅含应用及生产运行依赖。Compose 管理应用、MySQL 8、Qdrant 的内部网络、各自独立卷和健康检查，默认仅在宿主回环发布应用端口。容器的进程健康用 `/live`；README 的启动验收和接流量判断使用 `/health`。MySQL 用应用账号做带超时的只读探测（如 `SELECT 1`），Qdrant 通过带认证的只读探测验证可达，不创建集合。健康聚合为每次请求采样，按有界截止处理连接和读取，限制探测并发资源，慢探测不得独占存活处理能力。核心未就绪或排空时，演练切换入口按就绪停止转发；应用若有受保护测试入口，也须在未就绪时拒绝新业务动作。依赖中断保留进程以便恢复和诊断。按 OPS-01–06、BE-11 验收。

| 拟登记的配置 | 入口与约束 |
| --- | --- |
| `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD` | 应用必需；端口为 1–65535，启动诊断仅给键名；Compose 注入内部主机/端口及外部库名、账号、口令 |
| `MYSQL_ROOT_PASSWORD` | Compose 初始化 MySQL 必需；只传数据库容器，应用使用单独账号 |
| `QDRANT_URL`、`QDRANT_API_KEY` | 应用必需；URL 为 HTTP(S) 基址，Compose 注入内部地址，密钥由外部提供并传给向量服务 |
| `APP_HOST_PORT` | Compose 宿主应用端口，可选；在 README 登记默认 8000 和端口冲突处理 |
| 版本元数据 | 构建时由实际源提交标识注入并持久化在制品中，部署不通过环境覆写；缺失或空白按启动失败处理 |

`.env.example` 只含操作者需要提供或可调整的 `KEY=` 行，内部连接默认值在 README 单列。私有值通过未跟踪环境配置注入；构建上下文、Compose 输出、日志、测试报告和镜像检查不得暴露原值。启动时只校验配置形状和构建标识，依赖暂未就绪由探针报告。应用与运行服务器的请求日志都须符合 JSON 契约，关闭会记录原始请求行的重复访问日志。

### 三、统一门禁和隔离验收

本地与 PR 合并检查调用同一 `make check`。按 TEST-01–13 与 SEC-16 实现格式/静态、分层、机密、依赖许可与漏洞、制品扫描、严格规约/追溯、pytest 和真实集成检查。依赖与扫描工具版本入锁，High/Critical 阻断，Medium/Low 按 SEC-16 登记。扫描输入不可用时失败并区分工具故障与真实发现。采用明确的失败传播和报告汇总，避免每人手选检查得到不可比结果。

测试由门禁创建唯一 Compose 项目、私有网络、动态端口或网络内探测、临时卷和合成凭据。检查目标归属本次项目后再连接；不用开发或生产环境变量，不接受任意外部集成端点。单元断网、时钟可控；接口用合成授权夹具，真实 MySQL/Qdrant 集成验证启动、停机、恢复并单列证据。用例标注场景编号，默认和记录随机种子的乱序运行均需通过；清理只回收本次创建的资源。日志报告按环境、提交、子项退出码和测试数量留脱敏摘要。性能检查区分健康探测的专属截止和教学普通查询的容量基线，后者待相应业务适用时核验。

### 编码前核验顺序

1. 组长登记实施、评审、运维实名及协作权限，核对三人接受邀请或已有成员身份，以真实克隆和短分支/PR 操作证明相应能力，安排教师实际访问。保留历史偏差记录，命名整改如需迁移另由组长获授权办理，首次提交历史保留。
2. 有管理权限的运维在真实 `origin/main` 配置必经 PR 和人工评审，禁强推、删除及绕过，保存生效范围和例外清单。门禁尚未创建时先锁定 PR/审查，等首次有效检查在候选 PR 产出后即设为必需，首次代码合并前复核缺失或失败的门禁确实阻断。
3. 获授权的普通成员用同一凭据先证明可写短分支，再基于刚取回的远端 `main` 制作只含无害文档标记的快进探针提交。在确认目标和身份后实际尝试普通 `git push origin <探针提交>:refs/heads/main`。保留时间、脱敏角色、命令退出码、明确的规则拒绝信息、推送前后远端引用。无变更推送、dry-run、网络/认证失败或非快进拒绝均不能证明保护生效。意外成功立即停在编码前，记录失败，由获授权人员经 PR 清理探针并修复保护后复测，保留历史。评审确认规则、拒绝证据和远端引用，再放行编写第一行应用代码。旧单次文档直推授权已结束。

### 规则生效与课程留证

遵循[评审规范 V1–V4](../../../docs/standards/08-评审与完成定义规范.md#规范生效的四层验证协议)。

- V1 载体。重新核对根入口、八规范、五技能、规则编号、链接和五类最小集合；使用既有文档核验作追溯，注明本次实际核查范围。
- V2 独立会话。授权后由组员用仅含仓库路径、变更名的无历史会话先核验读取；有可运行候选后，两次无历史会话分别从同一干净提交按任务做相同的合成接口改动。记录各会话输入、标识、实际阅读文件、范围复述、基线、分层/命名/响应对照和评审人。
- V3 正向生成。经批准在独立、可丢弃的测试分支与 Compose 项目制作一张合成资源页和一读一写接口。按产品规范验术语、组件、四状态、键盘操作和重试，按后端与安全规范验路径、统一返回、输入、分层、同一合成键的幂等写入、合法访问和越权配对。合成身份与资源只存在于测试装配，样本不在可发布路由中。
- V4 故意违规。从 V3 已通过基线逐一引入自造样式、业务层直连 ORM、未登记入口、移除已有资源归属或功能检查、核心故障时误报就绪。产品审查指出 PROD-07，分层检查或评审指出 BE-01/05，未登记请求必须拒绝；移除已有授权后以另一合成账号重放同一已登记接口并跑原有回归，必须发现原权限断言失败；错误就绪必须让原健康断言及门禁变红。每次单独还原后重跑对应检查及完整门禁。保留基线、最小差异、命令和退出码、审查发现、修复和复测。结束后回收隔离资源及实验样本，枚举候选路由并重跑门禁和冷启动，确保主干合并候选只有非业务骨架和常驻测试夹具。

## Risks / Trade-offs

- 远端权限、教师或会话授权未到位 → 由组长协调，保留缺项。编码前保护缺证时不进入代码组，V2/V3/V4 缺证时不关闭课程对应项。
- 容器启动早于核心可用 → 以实际探针状态和依赖恢复作为验收，单独记录端口、超时和故障类型。
- 首次交付没有上一运行版本 → 先在同一变更分支构建并验收基线，再保留后继制品，回滚使用不可变标识。两份制品同时保留会增加磁盘占用，由运维记录位置与留存期限。
- 依赖许可或漏洞阻断 → 评审确认许可与扫描结果；调整锁定输入并重跑完整门禁，或按 REV-06 取得具体、限时的人工例外及缓解证据。

## Migration Plan

1. 在同一受保护流程的变更分支内建立可运行的前一里程碑 A，至少具备真实 Compose 启动、两个探针、默认拒绝和可关联日志。用对应门禁和实际运行记录验证 A，保留源码提交、不可变镜像 ID 或 registry digest、构建输入与外部配置说明。A 的里程碑检查单列，课程全部能力由后继候选验收。
2. 完成候选 B 的故障、边界及门禁验收，按同法保存与 A 不同的真实制品。两者均可用同一环境契约启动，无业务迁移。建立可重放的隔离蓝绿演练，A、B 使用不同应用实例，连接隔离的课内依赖；切换入口只把请求送往已就绪的一侧，避免仅用 Compose 退出码判断切换。
3. 用不可变制品启动 A，记录 `/health`、`/live`、版本与关联日志；预热 B，确认 B 就绪后切到 B，验证同一访问入口确实报告 B 版本。对 B 注入仅影响 B 的核心探测故障，观察 503 并撤流，确认 A 就绪后将同一入口切回 A。从发现故障到恢复同一入口记录实际耗时，分列检测、切换、恢复验证和总耗时。验收条件为同一入口匿名 `/health` 恢复 200 且报告 A 版本，依赖状态、请求标识、A 的日志和实际镜像标识一致。保留失败与复测，避免清库、重建镜像或把文档提交充作回退。
4. 修复演练故障、回收隔离资源。全员冷启动、交叉评审与各层证据齐全后，按短分支和 PR 合入可启动的 B，核对主干版本和制品。获授权后按 OpenSpec 归档并同步主规格；拟用 `v0.0.1-skeleton` 标记已验收的 B 源码提交，记录归档提交与 B 的对应关系及真实标签引用。实际发布记录、回滚详单和跨成员证据归入变更记录，并在 [课程证据入口](../../../docs/lesson-07/README.md) 汇总，更新 README 的复现与回退步骤。
