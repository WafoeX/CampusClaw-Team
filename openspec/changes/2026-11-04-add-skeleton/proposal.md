# 第 7 课运行骨架

## Why

让 Freebird 小组从同一份可运行的工程基础开始开发班级认证、资料入库和后续检索。成员按 README 即可启动 Flask、MySQL 和 Qdrant，并能从应用工厂找到路由、服务和适配器的接入位置，避免每个功能重复搭建环境和通用代码。

## What Changes

- 提供 Flask 应用工厂、HTTP/服务/适配器分层、统一响应与请求日志，以及供后续身份和资源策略接入的通用接口。
- 分离业务流量与依赖探测，补充精确公开路由装配，分层检查允许后续仓储在适配器中使用 SQLAlchemy。
- 提供锁定依赖、空值配置样例、Dockerfile、Compose、存活与就绪探针，以及首次启动和日常迭代说明。
- 提供现有测试目录和 `make check` 入口。用 CK-03 明确业务实现组的可运行交接及收尾验收条件，复用现有启动、探针和自动化入口。
- 以主干现有代码、干净源码启动和开发交接说明确认骨架交付。仓库规则演练、成员取证、人工评审和课程归档由[课程验收页](../../../docs/lesson-07/acceptance.md)单列。

选用 Compose 提供一致的依赖环境，减少每名成员手动安装和配置服务的差异。业务表、登录、资料、索引、模型和教学页面随对应功能变更实现。

## Capabilities

### New Capabilities

- `skeleton-runtime`：配置校验、可复现启动、存活与就绪、请求关联日志。
- `skeleton-access`：路由授权登记与默认拒绝、服务端授权落点、协议错误和无副作用断言。
- `skeleton-check`：可执行、可追溯、隔离且失败非零的统一门禁。

### Modified Capabilities

当前主规格无既有能力。

## Impact

后续变更从已合入主干的开发基础接入业务。公开探针、外置配置和现有检查行为见三项能力规约。开发交付项以[骨架任务](tasks.md)为准。核心业务齐备后的跨功能验收由[独立的最终验收变更](../2026-11-04-project-final-acceptance/proposal.md)执行。

2026-11-05 按用户安排，人工复核与功能操作测试集中到全部交付功能完成后的[项目最终验收](../2026-11-04-project-final-acceptance/tasks.md)。本变更完成实现与自动化验证交付，人工批准和合并状态单列。

2026-11-05 调度修订：本变更交付功能与自动化运行/错误回归；专项安全检查归安全预检及修复，人工测试归项目最终验收。可运行候选可供下游开发，人工批准、合并及归档状态独立记录。
