# 第 7 课运行骨架

## Why

服务 Freebird 三名成员、仓库运维与课程评审。当前只有规范载体，成员无法从干净克隆启动服务，也无法复现依赖故障、授权回归和回滚。统一启动、就绪和门禁契约后，成员可按同一 README 得到可观察结果，评审可以独立复现，减少口头补配置与把进程启动误判为服务就绪的情况。

## What Changes

- 本课只设这一项运行骨架变更。编码前由组长、运维和评审核验成员协作、教师访问和 `main` 保护，保留实际直推拒绝证据。保留 `establish-project-standards` 的名称、历史记录和纯文档例外，继续使用既有八规范、五技能。
- 建立 Flask 分层装配、外置配置、显式公开的就绪与存活探针、请求关联日志、默认拒绝的通用授权落点，以及 Dockerfile、Compose、锁定依赖与真实 `make check`。
- 本课按 C7-01–07 收集载体、独立会话、正向生成、故意违规四层证据及每名成员的独立冷启动记录。用隔离样本验证规则后清理样本，以可启动的非业务主干验收。
- 本课交付前建立前一可运行基线和后继候选制品，实测回滚、记录耗时。验收与人工评审后按授权归档及打标签，证据汇总到课程目录。
- 登录与会话签发、教学页面、资料及索引、模型、工具、队列、测验和学期检索评价留给各自业务课次。骨架不引入业务 schema 或业务数据。

放弃文档提交充当前一运行版本、单探针同时判断进程与核心依赖、先开放入口再补权限，以及借正向演示提前交付业务。前两项无法复现真实切换或准确判断故障，后两项会扩大未审查的访问面。

## Capabilities

### New Capabilities

- `skeleton-runtime`：配置校验、可复现启动、存活与就绪、请求关联日志。
- `skeleton-access`：路由授权登记与默认拒绝、服务端授权落点、协议错误和无副作用断言。
- `skeleton-check`：可执行、可追溯、隔离且失败非零的统一门禁。

### Modified Capabilities

当前主规格无既有能力。

## Impact

实施阶段涉及 Flask 应用、测试、构建/运行文件、门禁及合并检查、README 和证据目录。公开应用入口仅登记 `GET /health`、`GET /live` 及同一探针的 HEAD；数据库和向量服务留在 Compose 内部网络。仓库设置、教师和成员身份实测、独立会话、合并与归档标签由对应角色按授权执行。验收以 [C7 完成矩阵](design.md#c7-完成矩阵) 和正式场景为准。
