## Purpose

在后续业务接入前提供统一的服务端授权落点，使公开例外可枚举，未经授权的路由和资源调用在执行业务动作前即被拒绝。

## ADDED Requirements

### Requirement: AC-01 显式登记与默认拒绝

匹配到的入口 MUST 按路由及 HTTP 方法显式登记，匿名例外仅为两个探针的 GET/HEAD。已匹配但未登记的入口返回 HTTP 403、业务码 1200；已登记受保护入口缺少有效服务端身份返回 HTTP 401、1100。不存在的路径返回 HTTP 404、1300；存在路径的不支持方法返回 HTTP 405 和 HTTP 协议所需的 `Allow`。业务拒绝按 BE-03 返回 `code`、`message`、`data=null`、`request_id`；405 使用协议错误体 `{"status":"method_not_allowed","request_id":"…"}`。应用生成的响应均带 `X-Request-ID`。拒绝不执行处理器或产生写入。

#### Scenario: AC-N01 仅登记探针公开

- **GIVEN** 使用最终骨架的默认启动入口
- **WHEN** 枚举应用路由表并匿名访问公开路径
- **THEN** 仅探针 GET/HEAD 公开，探针请求进入处理器，无样本、静态文件或调试入口对外开放

#### Scenario: AC-F01 已匹配路由未登记

- **GIVEN** 隔离测试中注册了可计数的入口且没有授权声明
- **WHEN** 访问该入口，包括提供合成有效身份的情况
- **THEN** 返回 403/1200、`data=null`，处理器计数与存储均未变化

#### Scenario: AC-F02 未认证或伪造角色

- **GIVEN** 隔离测试中有显式登记的受保护入口，服务端未解析出有效身份
- **WHEN** 匿名请求，或提交伪造的 role、class_id 和身份头后请求
- **THEN** 均返回 401/1100、`data=null`，处理器未执行，客户端值未变为身份

#### Scenario: AC-F03 未知路径与非法方法

- **GIVEN** 仅骨架公开探针已登记
- **WHEN** 请求不存在的路径，再分别以 POST 和 OPTIONS 请求 `/health`
- **THEN** 未知路径为 404/1300，两种方法均为 405，`Allow` 不宣告 POST 或 OPTIONS，未执行探测或业务处理器

### Requirement: AC-02 服务端身份和资源策略

受保护入口 SHALL 先使用统一入口解析当前服务端身份并检查功能权限，再在业务层读取和检查资源归属后才能返回内容或写入；无可用身份来源时拒绝，已接入来源出错时失败关闭。功能权限不足返回 403/1200。跨班、他人私有资源和真正不存在统一返回 404/1300，公开文案与数据一致。骨架的合法与非法资源访问使用隔离合成夹具验证，默认运行实例没有已认证的业务入口。

#### Scenario: AC-N02 合法主体通过授权

- **GIVEN** 测试装配提供有权限的当前服务端身份与该身份有权访问的合成资源
- **WHEN** 请求已登记的测试资源入口
- **THEN** 成功码为 0，仅返回允许的数据或执行一次约定内写入

#### Scenario: AC-F04 功能权限不足或撤销

- **GIVEN** 合成主体曾可访问测试功能，服务端身份现已被降权
- **WHEN** 重发相同请求并附带旧角色
- **THEN** 按当前服务端权限返回 403/1200，无读取结果与写入

#### Scenario: AC-F05 资源不存在与越界等价

- **GIVEN** 隔离夹具有同班自有、同班他人私有、跨班及不存在的资源标识
- **WHEN** 同一身份用相同读写方法分别访问后三类标识
- **THEN** 每次均为 404/1300，排除请求标识后的公开文案和数据一致，写入计数不变

#### Scenario: AC-F06 身份解析依赖失效

- **GIVEN** 隔离装配已接入服务端身份来源，且该来源故障
- **WHEN** 请求受保护测试入口
- **THEN** 返回 503/1500 与脱敏错误，不使用旧权限放行，不执行处理器

#### Scenario: AC-B01 合法探针与受保护入口方法隔离

- **GIVEN** 两类入口在同一测试应用运行
- **WHEN** 交错执行匿名 HEAD 探针和匿名访问受保护入口
- **THEN** 公开例外只作用于匹配的探针方法，后者仍为 401/1100，访问结果与请求顺序无关
