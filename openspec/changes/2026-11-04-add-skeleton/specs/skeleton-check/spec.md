## Purpose

为开发者与合并评审提供同一条可复现的工程检查命令，使遗漏用例、环境污染、供应链阻断和关键逻辑回归产生可观察的失败信号。

## ADDED Requirements

### Requirement: CK-01 统一门禁与退出语义

`make check` MUST 执行格式及静态检查、分层、机密、依赖与制品安全、严格规约与场景追溯、适用的 pytest 及独立真实依赖集成。全部必需检查通过才返回 0。任何子项失败、不可运行、缺报告、空测试收集或缺必测场景均非零退出，输出可定位的失败项；不要求 make 原样转发子进程退出码，证据分别保留。未执行、失败、跳过和不适用分别记录，禁止以新增跳过、隐藏失败、过期扫描数据或替身通过替代必需结果。

#### Scenario: CK-N01 完整门禁成功

- **GIVEN** 锁定工具、独立测试依赖、候选制品和规定扫描数据均可用
- **WHEN** 执行 `make check`
- **THEN** 每个必需阶段有可查结果，pytest 覆盖场景编号，命令退出 0

本地、PR、`change/**` 推送和 `main` 推送均调用同一门禁；主干推送的检查针对实际合并提交执行，结果与合并前候选检查分开记录。

#### Scenario: CK-F01 运行前提非法

- **GIVEN** 本地存在开发服务，且其地址或卷被误传为测试目标
- **WHEN** 执行 `make check`
- **THEN** 隔离校验拒绝并非零退出，对开发服务和卷无读写或清理副作用

#### Scenario: CK-F02 缺少必测资源

- **GIVEN** 隔离副本缺少一个必测场景的测试文件，或 pytest 未收集到任何测试
- **WHEN** 执行 `make check`
- **THEN** 缺场景映射或空收集产生明确失败，命令非零退出

#### Scenario: CK-F03 必需检查工具或依赖故障

- **GIVEN** 隔离环境的必需漏洞扫描数据不可用，或无法建立真实集成依赖
- **WHEN** 执行 `make check`
- **THEN** 标明不可运行的阶段，命令非零退出，不写通过报告

#### Scenario: CK-F04 逻辑被改坏

- **GIVEN** 同一隔离候选和门禁已真实通过，测试断言保持原样
- **WHEN** 单独让 MySQL 不可用时就绪误返 200，或移除隔离样本的既有授权，再运行门禁
- **THEN** 相应状态或权限回归断言失败，门禁非零；还原后同命令恢复通过

#### Scenario: CK-F05 安全扫描触发阻断

- **GIVEN** 在隔离校验环境中存在已知 High/Critical 扫描发现或测试用伪造秘密样本
- **WHEN** 执行对应真实扫描并通过 `make check` 汇总
- **THEN** 命令非零并标明阻断类别，报告不回显秘密原值；清理后重跑恢复

#### Scenario: CK-F06 业务规约错误阻断默认门禁

- **GIVEN** 骨架规约可通过，另一个活动业务变更有非法增量
- **WHEN** 不指定 CHANGE 运行默认规约门禁
- **THEN** 严格校验指出该业务变更并非零退出，恢复合法规约后通过

#### Scenario: CK-B02 ORM 限于持久化适配器
- **GIVEN** 隔离分层检查夹具
- **WHEN** 分别在适配器、接口层和服务层导入 SQLAlchemy
- **THEN** 适配器导入通过；接口层及服务层导入被明确拒绝

### Requirement: CK-02 测试隔离与证据

门禁 SHALL 将断网单元、接口测试和真实依赖集成分开。集成仅使用本次专用网络、卷与合成数据；回收只能作用于本次创建的资源。测试结果可按场景、提交与运行环境追溯。

#### Scenario: CK-B01 乱序、重复与清理

- **GIVEN** 两次运行使用独立的临时环境与相同候选
- **WHEN** 分别按默认顺序和记录了随机种子的顺序运行，并在故障阶段退出
- **THEN** 未注入故障时结论一致，故障为非零；结束后本次临时资源被清理，原开发环境未变化

此本地命令无应用调用者权限，应用级授权类别不适用，合并权限由仓库保护另行核验。CK-F01 至 CK-F05 为实际失败判据，不适用项由评审确认且不计数。

### Requirement: CK-03 实现组可运行交接

每个改变可运行代码、配置或数据契约的实现组 MUST 使用版本可追溯的上游基线，核对本组直接依赖的接口并执行相关回归。增量完成后 MUST 在隔离环境启用该组的真实功能配置，按需完成兼容迁移，确认 `/live` 响应和 `/health` 核心就绪，再用自动化用例或脚本通过实际入口断言本组变动的业务结果或持久副作用。涉及写入或访问控制时，还须自动化验证相关失败或越权请求及无副作用。可选服务须验证实际接入点及主应用仍可用。记录任务号、候选版本、配置键、执行命令、退出码和实际结果。环境、身份与数据使用隔离夹具。

上述检查通过才可勾选实现组并向依赖该契约的任务交接。各变更指定的收尾任务 MUST 执行完整自动化回归、适用专项检查及必需门禁，并完成合并前代码评审。人工功能走查和课程专项复验由各自验收任务执行。各阶段的结果单独登记。

#### Scenario: CK-N02 实现组通过后交接

- **GIVEN** 上游候选可定位，已具备本组需要的配置、隔离环境、依赖和合成数据
- **WHEN** 实施人启动本组增量，验证就绪、受影响的正常入口与相关自动化回归
- **THEN** 命令、退出码和实际结果可追溯到该候选，该组可交给依赖它的任务，尚待执行的专项人工复验留在相应验收任务

#### Scenario: CK-F07 配置或依赖缺失

- **GIVEN** 缺少启用本组功能的必填配置、所需迁移未应用，或实际依赖不可用
- **WHEN** 实施人执行启动和本组入口检查
- **THEN** 记录未就绪或入口不可用的具体原因，该组保持未完成，仅暂停依赖该能力的任务

#### Scenario: CK-F08 探针通过但入口不可用

- **GIVEN** 探针返回正常，但受影响的入口未注册，或未启用业务装配
- **WHEN** 自动化请求按合法输入和身份访问该入口
- **THEN** 断言报告实际行为与规约不符，该组不得交接

#### Scenario: CK-F09 授权或副作用回归

- **GIVEN** 候选已启动，并具有合法主体和越权主体的合成夹具
- **WHEN** 自动化回归发现合法请求产生错误业务结果、越权请求被放行或失败请求发生写入
- **THEN** 保留失败结果，修复并重跑通过前不得勾选或交接该组

#### Scenario: CK-F10 收尾门禁或代码评审未完成

- **GIVEN** 各实现组均已交接，但收尾候选的必需门禁失败、未执行或缺少合并所需的代码评审
- **WHEN** 核对合并条件与实际证据
- **THEN** 变更保持待合并，已通过的组内检查独立留存，正式候选准入仍按受保护主干规则判定
