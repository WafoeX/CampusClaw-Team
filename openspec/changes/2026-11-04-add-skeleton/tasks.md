## 1. 编码前关闭仓库与规约前置条件

- [ ] 1.1 组长按 [C7 完成矩阵](design.md#c7-完成矩阵) 登记实名实施、评审、运维，收集三名成员真实加入、克隆和短分支/PR 协作结果，取得教师本人或课程方的访问确认；记录许可状态及命名、首提交偏差的审查结论。
- [ ] 1.2 运维在写任何应用代码前启用 `main` 保护，按设计用获授权的普通成员执行真实快进直推拒绝核验；评审核对规则、非零退出、拒绝原因和推送前后远端引用。缺证或探针意外成功即停在本组，复测通过后才准开始代码。
- [ ] 1.3 实施人运行 `openspec validate 2026-11-04-add-skeleton --strict` 并检查 V1 载体；评审核对四类规划、能力—场景映射、每能力至少四条失败及不适用理由。记录严格校验、链接和人工结论；获独立会话授权后，先完成 V2 的只给路径和变更名的读取验证。

## 2. 建立首个可运行里程碑与门禁

- [ ] 2.1 建立 Flask 工厂、配置装配与路由→业务→仓储/适配器的单向依赖；落实默认拒绝、显式公开探针、服务端身份和资源归属接口，按 [AC 场景](specs/skeleton-access/spec.md) 核对路由表及合法、伪造、拒绝和副作用。
- [ ] 2.2 落实外置配置、空值样例、两个探针、单行 JSON 请求日志与关闭就绪的停机流程；按 [RT 场景](specs/skeleton-runtime/spec.md) 验证探针字段、版本、时间、请求标识、脱敏和配置缺失或非法时的退出。
- [ ] 2.3 建立锁定构建输入、多阶段 Dockerfile、Compose 和 README 冷启动，验证空卷下用真实 MySQL/Qdrant 启动、匿名就绪、版本匹配以及仅应用发布宿主端口。
- [ ] 2.4 按测试技能建立场景编号映射与单元/接口/集成套件；建成真实 `make check`，包括静态、分层、机密、依赖/制品、规约与测试检查，按 [CK 场景](specs/skeleton-check/spec.md) 留存退出码和隔离记录。门禁路径应支持变更从活动目录移到归档目录后的场景追溯，归档时复测。
- [ ] 2.5 在变更分支冻结可运行基线 A；运维记录适用于 A 的检查、实际健康和启动结果、提交、镜像标识与可回退配置。候选 PR 首次生成实际门禁状态后，由运维将其设为必需，评审在首个代码合并前验证缺失或红灯均阻断。

## 3. 验证后继候选与规则生效

- [ ] 3.1 完成 A 之后的非业务候选 B 并覆盖全部 RT/AC/CK 场景，尤其是真实依赖断开与恢复、截止边界、未就绪撤流及授权失败；记录完整门禁、乱序复跑及失败时只回收本次资源的验证。运维留存候选版本与不可变制品。
- [ ] 3.2 由组长安排获授权的两次无历史会话在同一干净候选上执行相同合成接口改动，评审记录 V2 一致性；在独立测试分支和运行环境做 V3 的一页、一读一写样本并通过相应门禁与走查。
- [ ] 3.3 实施人与评审逐一验证 V4 样本，含单独移除已存在的授权后另一合成账号重放、误报核心就绪；保持原断言，记录红灯、还原和复测。清理样本及隔离资源，枚举候选公开路由，再跑完整门禁和冷启动。
- [ ] 3.4 三名成员各用自己机器从干净克隆按 README 冷启动同一 B，逐人记录机器、版本、提交、命令、健康与遇阻复测；另一成员独立核查并给出实名交叉评审。若修改候选，记录新旧标识并对最终候选复验。

## 4. 课内回滚、评审和归档

- [ ] 4.1 运维用保存的 A/B 制品按设计实测蓝绿切换、故障撤流、切回 A 和故障恢复，记录镜像/源码对应、同一入口的就绪与版本、关联日志、分段耗时和总耗时；在 README 补齐复现步骤。
- [ ] 4.2 实施人同步 README、变更证据及 [课程入口](../../../docs/lesson-07/README.md)，按 C7-01–07 链接实际门禁、四层验证、跨成员、回滚和评审。评审完成约束文件、角色及外部证明的人工复核，所有阻断关闭后按保护流程合并；核对主干可冷启动且无业务样本。若合并结果改变已验证的运行输入，重新确认制品对应及受影响的验收。
- [ ] 4.3 人工验收后按授权执行归档、同步主规格与标签；复测归档后的严格校验和门禁追溯，核对标签确实解析到已验证制品对应的可达提交。将真实归档位置、标签及制品对应和最终评审补入课程证据。
