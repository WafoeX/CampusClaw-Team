## Context

本仓库有 Flask 应用工厂、默认拒绝的授权服务、MySQL/Qdrant 就绪探测和真实 `make check`。第 3、4 课业务仍在规划。第 4 课 [QA-01](../2026-11-04-add-traceable-retrieval/specs/grounded-material-qa/spec.md) 的 `POST /api/v1/material-answers` 无会话副作用；[检索与出处](../2026-11-04-add-traceable-retrieval/specs/traceable-retrieval/spec.md) 使用班级范围、真实片段与版本。实现前按上游验收后的主规格核对认证、错误、检索范围、出处定位及配置；发现差异先更新本变更。动机和边界见[提案](proposal.md)。

## Goals / Non-Goals

- Goals：用同一业务服务层提供应用编排、版本化配置、本人流式会话和执行记录，分离教师教学反馈视图。保证上游单次问答兼容，新的持久路径可重试并可观察。
- Non-Goals：本课不引入第三方工具、脚本执行、后台队列、题库及测验数据读权限。课堂内的练习生成输出是学习文本，教师题库及审核由后续课实现。

## Decisions

### 1. 应用和会话边界

- 应用目录固定为四项。润色、学习规划、练习生成各走同步有界的应用执行入口，结果和脱敏后的过程统一留在本人执行记录。练习生成是独立练习内容，禁止查询或复现既有测验答案。资料问答默认进入 `/ask`，用户可选择单次问答或开始持久会话。会话锁定本班助手 ID，使用相同应用编排和执行记录，历史只在会话里可见。单次入口既不创建会话也不创建本课执行记录。拆入口便于保持第 4 课兼容并区分数据授权。
- 应用可以有教师版班级模板。首版变量仅 `{{input}}` 和 `{{audience}}`，不执行表达式、属性访问或二次展开。预览与运行共用确定性替换和同一修订，按纯文本展示，预览不调模型、不创建执行记录。可编辑模板和助手提示词分别保留不可变修订；清空助手提示词使用服务端默认角色。历史只记录修订号及当时生效的受控配置。
- 教师维护助手名称（1–64 码点）、提示词（至多 2000 码点）、材料和技能绑定、启用状态。新会话仅接受当前启用助手。既有会话每轮从数据库重读助手启用状态、助手/模板修订、材料及技能绑定、各技能启用状态及修订。停用助手后既有会话可用默认角色，但该轮不给停用助手的提示词或绑定；资料问答按空授权证据走固定文案。停用单个技能或解绑只影响下一次选路；已开始但未完成的流发现生效配置变化时停止发送并废弃该尝试，客户端可用当前配置重试。
- 固定角色和应用政策由服务端控制。教师可编辑提示词和模板在受限字段内参与组装；学生输入、变量值、历史消息、资料与上传 JSON 中的自由文本明确置于数据位置。教学反馈和测验记录从来不加入模型输入。浏览器不接触模型凭据。

### 2. 技能表示与路由

课程示范使用文本头字段和空行后的正文。本组 JSON 对应 `name`、`conditions`、`enabled`、`tools`、`steps`。仅接受 UTF-8 JSON 对象，拒绝重复键、未知字段、脚本、URL 和任意工具；`tools` 只能为空或仅含 `knowledge_search`，由宿主按授权检索一次，清单步骤不得自行调用工具。班内名称归一后唯一，教师写入支持创建、更新、停用与删除，内置定义只读且教师可按班启停或解绑。限制为 8 KiB 文件、1–16 个非空条件词、1–3 步，步骤类型为受控模型步骤；细化字段和限制随 OpenAPI 和 AI 参数登记。

选路只对本班助手当前绑定并启用的技能按本轮问题算命中分，每个不同条件词匹配一次（Unicode 归一和大小写折叠后的子串），最高分胜，同分取较小稳定 ID，零分不选。选中的步骤按声明顺序执行，总预算共用，失败立即停止；上传正文不能变成系统指令。内置「解题引导」和「学习计划拆解」登记独立版本。解题助手模式始终用受控步骤模板及白名单槽位呈现模型选择，无技能命中或命中上传技能时也沿用此输出约束。禁止自由输出最终答案、敏感值及未经审核的任意插值。无课内证据时，只允许展示经审阅的通用步骤并明确标注“以下为一般解题提示，暂无课内资料依据”，不显示出处；资料问答本身仍返回上游固定文案且不调对话网关。该做法兼顾课件的引导回退和上游资料问答语义。

### 3. API、页面与授权

| 接口或页面 | 角色及契约 |
| --- | --- |
| `GET /api/v1/ai-apps`，`/apps` | 师生读取固定四项和本班可用配置摘要 |
| `GET/POST /api/v1/prompt-templates`，`GET/PATCH/DELETE /api/v1/prompt-templates/{id}`，`POST /api/v1/prompt-templates/{id}/previews` | 师生可读取及预览本班可用模板，教师写本班；预览传修订号和白名单变量 |
| `GET/POST /api/v1/assistants`，`GET/PATCH /api/v1/assistants/{id}` | 师生列出本班启用助手摘要，教师管理本班版本、启停及绑定；写入携带期望修订 |
| `GET/POST /api/v1/skills`，`GET/PATCH/DELETE /api/v1/skills/{id}` | 教师管理本班技能；学生从会话只见所选技能摘要 |
| `POST /api/v1/ai-apps/{app_key}/runs`，`GET /api/v1/runs`，`GET /api/v1/runs/{id}` | 三类同步应用，提交需幂等键；本人读执行记录；资料问答仍用单次或会话入口 |
| `GET/POST /api/v1/sessions`，`GET /api/v1/sessions/{id}`，`POST /api/v1/sessions/{id}/messages` | 仅本人管理，创建显式选择资料问答或解题助手模式和启用助手；发送当前问题、可选本班章节与幂等键，返回 SSE |
| `GET /api/v1/sessions/{id}/messages/{message_id}/citations/{ordinal}` | 本人读历史引用，另校验当前来源访问权；版本不同时仅按历史策略展示 |
| `PUT /api/v1/sessions/{id}/messages/{message_id}/feedback` | 学生本人对成功的助手消息评价，有帮助或未解决；只收评价和教学说明（去首尾空白后至多 500 码点，「未解决」须填写，「有帮助」可省略），提交前预览教师可见字段；本人用户消息为状态冲突，缺失消息按资源隐藏规则处理 |
| `GET /api/v1/teaching-feedback`，`PATCH /api/v1/teaching-feedback/{id}` | 教师本班查看未解决并标记已处理，可按状态查询；只返回反馈标识、评价、学生主动填写的教学说明、允许公开的章节、时间和处理状态 |

认证用第 3 课 Bearer，访问令牌只在内存。默认拒绝，数据库当前身份决定班级和角色；访问越界对象及缺失对象同为 404/1300，同班他人私有对象同样隐藏；学生写教师接口 403/1200，匿名 401/1100。未知字段和非法枚举 400/1000，过期版本或幂等冲突 409/1400，依赖不可用 503/1500，无效模型内容 502/1501，配额使用 429/1600。成功创建 201/0，普通成功或回读 200/0。版本化列表默认 20、上限 100，按更新时间和 ID 稳定排序。请求响应遵循 BE 统一结构，SSE 帧以事件载荷表达业务结果并带请求标识。

`/console` 提供助手配置，复用 `/console/templates`、`/console/skills`、`/console/feedback`。师生使用 `/apps`、`/ask`、`/sessions`、`/runs`，各列表和详情具加载、正常、空、错误四态，问答另有无命中与流中未完成态。键盘可操作，出错可回读，未知路由 404；用文本或经净化的内容显示，流中段落先以纯文本呈现。

### 4. 检索、分段校验和流式状态

1. 只给本轮问题做检索，使用当前班级、所选章节和助手绑定材料的交集；空绑定视为空范围，禁止扩大至全班。最多取 4 片且总计不超过上游 12000 码点，不改变单次接口最多 8 片的契约。对话历史仅取最近 6 条已完成消息、每条最多 500 码点，历史本身不能成为当前引用或当前检索词。对话网关与检索故障区分于成功无证据。
2. 用 Bearer `fetch` POST，浏览器增量解码 UTF-8，处理帧跨网络块及多帧合块。响应为 `text/event-stream`、`Cache-Control: no-store`、`X-Accel-Buffering: no`，代理禁缓冲及缓存。先完成鉴权、参数、限流、会话校验、可用检索和事务受理，再发 `meta`。其载荷为运行标识、路由结果及已授权候选出处编号；候选不含原文，最终使用的编号由 `done` 确认。流开始前走普通 HTTP 错误。
3. 模型原始 token 仅进服务端有界缓冲。资料问答按完整结构化段落校验累计上下文、引用编号与数值，再生成纯文本增量 `delta`；不能切开出处标记或绕过跨段校验。解题提示采用受控渲染。模板、技能、检索、历史和运行记录没有测验题库或答案接口能力，系统不得接入待开放答案副本；答案开放防护回归在模拟受保护资源上检查模型请求、原始 SSE 和回读。校验失败不发送该段；已发送的校验段仍是未完成预览，浏览器遇 `error`、断流或异常帧清除预览并允许回读。首版选择段级流，以降低风险并保留实际增量，抓包必须能证明第二段模型尚在执行时第一段已抵达，不能把缓冲完的全文拆帧冒充生成中推送。
4. 每次暴露段落前重验当前身份、配置版本和来源授权，结束时再对组合全文做一次校验。成功将助手消息、出处快照、成功状态和执行记录原子提交后发 `done`，帧载荷含消息 ID、已使用编号；正常流只有一个终态，所有增量拼接与落库正文一致。无证据的固定文案也走流协议并保存对应私有轮次。失败流用唯一 `error` 和公开业务码结束；无助手成功消息、无可访问的未验证回答，已提交成功但终帧丢失时以持久状态为准。连接断开即尽力取消网关请求；提交前确认断开则作中断，提交后不能撤销成功结果。
5. 每个发送必传 1–64 位 ASCII 幂等键（字母、数字、下划线、短横线）。键的作用域是班级、本人、会话、操作（独立应用执行用应用标识）；输入指纹覆盖规范化问题、章节或该应用输入与模板修订。有效期按原记录保留期，单会话仅一轮在途。首次受理以唯一约束写用户消息、尝试行与时间，模型在事务外执行；同键不同输入或仍在途返回 409/1400，无模型重复调用。确认终结失败后同键可再开一次尝试，复用原用户消息并重读权限及配置；为同一轮累计尝试设上限 3。持久成功后的同键回放读取本人当前可访问结果，标记已完成并通过 SSE 回放，无重新生成或写入；来源撤销且无法安全回放时返回 409/1400，提示查看脱敏历史。只读回查无执行副作用。租约过期用条件更新收口，陈旧执行者不能续写或发成功帧。
6. 暂定问答输入最多 500 码点且去首尾空白后至少 2；应用输入最多 4000。温度 0.2、输出 2048 token、单网关调用 15 秒、整个生成 35 秒，每人每分钟最多 6 次模型调用且并发 1。瞬态故障只在发送首段前按预算最多自动重试一次（退避 1 秒），分段送达后由用户显式重试；步骤调用与重试均消耗配额。模型版本、总上下文、段预算、代理读超时、并发和实测首段/总耗时 P95 由实施及运维责任人在实现前登记并验证，关键缺项阻断发布。现有 Gunicorn 为 1 worker、8 threads，生成、技能和工具共用长请求容量。按实测设全局在途上限，昂贵检索、模型或工具开始前申请容量，满额以 429/1600 快速拒绝，部署侧为短请求和探针保留处理容量；若共用线程配置不能达标，则调整 worker/线程或独立流式入口后复测。用代理和实际 worker 配置复现长流满额时登录、资料读取、提交等短请求与探针，并验证排空及槽位回收。请求日志只含请求标识、版本、路由、时长、用量和结果类别，私有内容单独持久化。

### 5. 数据、副本和教学反馈

- MySQL 以第 3 课主键规则及班级组合外键约束，保留 `prompt_templates`、`assistants`、`skills` 及各自修订，`assistant_materials`、`assistant_skills` 与独立班级启停状态。版本、创建人、UTC 时间及审计元数据进字典，写绑定时校验同班，更新采用期望修订。
- `sessions` 记班级、本人及应用/助手绑定；`messages` 记轮次、角色和完成状态；`application_runs` 记尝试、使用修订、网关参数、步骤、耗时和结果。一个逻辑轮次至多一个成功助手消息与一次成功记录，失败尝试只保留诊断元数据，成功记录也剔除凭据、敏感配置和不应复制的原文。执行与会话通过内部引用联查，读取须同时满足当前身份和业务范围。
- 每条最终出处保存版本化资料标识、原文区间、当时标题与经授权的最小摘录，绑定助手消息与编号。原资料重建且依然授权时显示历史版本快照，旧链接不指向新切片；删除显示“来源已删除”，撤权显示不可用，隐藏原文、标题和跳转。受影响的历史回答及运行正文可能复制材料，按来源依赖同时隐藏受影响正文，保留安全状态。删除触发可重跑的副本清理，确保摘要、请求响应、历史快照与重放均不返还已撤销内容。
- `teaching_feedback` 按消息和学生唯一，评价重放无重复；未解决可处理，有帮助不进未解决列表。评价变更与教师处理采用条件更新，已处理反馈被学生实质性改成未解决时重新进入待处理。反馈不含会话或执行记录链接，不自动复制问题、答案、出处或学生身份到教师视图。教师操作留去内容审计。匿名化与留存遵守 DATA-06–08，普通留存到学期结束后 30 天内，日志 14 天、去内容审计 90 天、备份 14 天轮转；恢复接流量前重放删除与过期清单。

### 6. Swagger 和证据

从同源路由契约生成 OpenAPI，在 `/swagger` 试调 Bearer 登录后的主要接口；标注 SSE 的事件、错误与原始流复核方法。按 URL/方法放 `apitest/cases/`，由 `apitest/run_all.py` 调同一批 pytest 场景/断言并生成本地 HTML（报告不随作业提交）；现有门禁的 API 测试调用共享断言，真实服务、浏览器及网关证据分开记录。不得将骨架专用 OpenSpec 检查当成第 5 课检查。实际第 5 课严格校验与行为结果分别归档。

## Risks / Trade-offs

- 短段校验增加首段时延 → 真实代理用分段网关抓帧，分别记录首段和总耗时，验证中断、超限、清屏和并发配额。
- 内容发出后无法撤回网络字节 → 每段出流前校验，权限或版本变化即终止；浏览器丢弃已显示预览，快照与回放重新授权。
- 课件文本技能与本组 JSON 不同 → 对照字段、解析失败、同分和启停复现等价行为，课堂口径交小组评审确认。
- 前课主规格尚未合入 → 实施前跑第 3、4 课回归并复核主规格，发现契约差异先修订文档。

## Migration Plan

只增表、索引和外键，先在真实 MySQL 验证空库、上游库、重复迁移及兼容，再启用新路由，原单次问答可继续用。回退先下线新路由并停止受理，收敛或中断在途流，回到上一应用制品，保留隔离的新表供授权处置；不把删表作为默认回滚。独立环境演练恢复及删除清单重放，缺清单阻断接流量。实施、评审及运维人员由小组按任务确认。
