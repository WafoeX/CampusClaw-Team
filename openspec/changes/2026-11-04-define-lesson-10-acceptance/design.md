## Context

当前 Makefile 提供 `make check`，分别调用秘密和依赖扫描，工作流当前只显式调用此入口。课末安全预检建立独立的 `make check-security`，第 9 课修复复用。Dockerfile 已分构建与运行阶段并写入 OCI 修订标签，最终阶段仍复制 `app/` 源码。Compose 已声明应用、MySQL、Qdrant 和探针，应用等待依赖就绪的正式契约仍需验证。项目已有跨功能验收计划，实际候选尚未齐备。具体业务卡片见[项目最终验收设计](../2026-11-04-project-final-acceptance/design.md)。

## Goals / Non-Goals

统一第 10 课的验收入口、就绪条件和证据索引。在同一候选上完成正式人工评测，按独立的业务变更处理修复或课程差异。

## Decisions

### 先收齐交付，再冻结人工评测候选

| 阶段 | 责任与完成条件 |
| --- | --- |
| 前置交付 | 实施人填命令清单、场景矩阵，补齐功能、双门禁、红绿、容器、构建、真实告警、性能改进及真实试用证据。三组可分别负责测试、容器流水线、观测压测，互查实际结果。 |
| 正式人工评测 | 验收负责人固定提交、镜像摘要、配置版本、两班数据、模型版本和设备清单。验收人按卡片执行。同伴另从干净目录冷启动，独立复现四步。组长依据必做项、结果与复验签署。 |
| 返工与重评 | 按场景 ID 登记问题、责任变更和是否阻断展示。更新候选后核对双门禁、制品版本和证据适用性，重评受影响卡片，保留初次失败。 |

每张人工卡记场景 ID、执行人、时区时间、候选和环境、角色与合成数据、操作、预期、实际、状态、证据和复测关联。判定用通过、失败、未执行、不适用。只允许批准范围内确实不适用的条目使用该状态，记录理由和批准人。独立同伴和真实用户记录单独归因。综合通过采用必做项逐项通过，无平均分补偿。人工确认聚焦教学意图、提示质量、操作体验及证据是否可复现，形成至少一条可执行用例或规则。适用的机器断言先跑再由人复核含义。

同步执行现有最终验收中资料、检索问答与出处、未解决反馈、题库审核、测验、错题、看板、依赖降级、流式容量及冻结题集核对。一次正式验收共用候选与记录，区分自动化、真实用户和人审判据。选做 SEC-08 沿用第 9 课决定。

### 需确认的课程行为

| 需求 | 当前项目契约 | 确认与受影响范围 |
| --- | --- | --- |
| Swagger Bearer 试调 | 复用同源 HTTPS Cookie 和写入防护 | 流式助手 5.1 记录差异。课程方确认后按获准方式取证 |
| 作业提交 202 及任务轮询 | 测验正式提交 201，同一事务确定性评分。AI 候选题返回 202 并提供任务状态 | 异步教学 1.1、5.1 及安全预检 3.1 分别保留契约和演示结果。若作业接口必须返回 202，先修订相关提交与任务规约 |
| 直接评分写入的越权检查 | 当前规则评分随正式提交写入，未规划独立批改写入口 | 安全预检 1.2 记录实际路由、拒绝及持久状态对照。等价由课程方确认 |

### 门禁、制品与启动

在现有 pytest、Gitleaks 和 Trivy 基础上对齐本地与 CI。保证 `make check`、`make check-security` 各有可识别的状态，构建只接受两者成功的同一提交。保留先红后绿的实际本地与 CI 输出及修复提交，隔离演练使用临时分支。查主干保护配置及实际拦截结果，人工签署不能覆盖失败门禁。

构建阶段制作应用运行产物，最终阶段仅安装运行所需代码产物和必要模板、静态资源及迁移资源。以镜像清单和层扫描验证应用原始源码、构建工具及秘密未进入运行镜像。用 CI 提交号生成镜像标签和 OCI 修订标签，记录构建运行号和摘要并核对就绪接口版本。README 说明一次性配置输入及一条启动命令所需制品来源。Compose 用健康依赖条件启动服务，就绪撤流覆盖运行中数据库故障。候选若依赖异步消费者等扩展服务，纳入同一条可复现启动入口。

### 观测、告警与压测口径

调用计数采用稳定技能标识与结果状态，例如 `skill_invocations_total{skill,status}`，从审计派生并避免以账号、请求或会话作为指标标签。错误率用相同时间窗的失败数除以调用数，零样本显示无数据。压测与告警前登记状态归类及数据窗口。初拟告警采用指定技能的五分钟滚动错误率，在窗口至少有 20 次调用时，连续五分钟高于 1% 即通知负责人，附面板链接，触发后两分钟内送达。隔离演练使用可计入该技能失败状态的安全样本。面板和收件端同时取证，记录开始、触发、送达、恢复、链接及执行人。阈值以实施前评审确认并入库的配置为准。

固定脚本版本、数据、并发阶梯、预热、采样窗口、环境、消费者数量和压测目标。事前按 OPS-11 和已批准指标登记饱和条件，至少覆盖吞吐增幅停滞、P95 或错误率触及上限的判断。提交压受理，后台按固定消费者数另测完成吞吐和积压。单独运行查询与检索并记录环境、参数和三数。只改变被验证的索引或缓存方案。对照报告给出瓶颈、改进提交及对授权隔离的回归结果。

### H5、试用与证据索引

优先复用同源 HTTPS 与现有 Cookie 及 CSRF，服务端记录精确来源及请求条件。需要跨源时按获准契约使用显式来源白名单和对应预检规则，不能用通配符放开带凭据请求。反馈使用不具备认证能力的脱敏会话代号，清理截图、日志、响应中的私人信息。使用者反馈给出任务或拒绝理由，新问题的复现用例关联矩阵。

| 归档路径 | 内容 |
| --- | --- |
| `reports/acceptance-matrix.md` | 可重复命令与上次运行时间、规约到用例及证据的矩阵、责任与缺项。 |
| `reports/gate-red-green.md` | 保留第 9 课资产门禁证据，追加第 10 课故意改坏、CI 拦截和恢复。 |
| `reports/delivery-runtime.md` | 启动记录、镜像检查、CI 与提交关联、探针、三张面板和告警送达。 |
| `reports/bench.md`、`reports/feedback.md` | 两轮压测对照及真实用户反馈与处理去向。 |
| `reports/manual-acceptance.md` | 候选与人工卡片、签署、同伴复现和展示前待修项。 |
| `reports/review-01.md` 起的连续记录、高风险三查 | 复用第 8、9 课可核对的记录，补齐三份评审和本轮适用的授权、事务、并发复测。 |
| 根目录 `report.md` | 实际验收时写候选、结论及证据指针。原始数据与细节在报告链接目标中。 |

仅对确定的脱敏 Markdown 文件设置精确跟踪规则，核对文件可由验收机器打开。报告、审批和复验以真实发生为准。

## Risks / Trade-offs

- 上游课程差异未确认 → 教师改分、作业 202 与登录方式逐项留缺口，依据课程方书面口径复验。
- 指标只有截图或性能两轮不可比较 → 补送达记录或同口径复跑，保留首次失败。
- 候选变更或证据失联 → 新候选补齐版本与受影响复测，最终结论指向可打开的记录。

## Migration Plan

如采用数据库索引改进，本课只实施扩与迁，登记所处阶段、回填或索引上线验证及回退。先保留旧结构并验证旧候选仍可运行，缩减留待回退窗口关闭、影响核验及批准后。按就绪切流并保留可追溯的上一制品。
