## Purpose

为小组、独立复验人和课程评审规定第 10 课的交付前置、运行证据及人工评测方法，使最终结论可以从同一候选的提交、镜像、用例与真实观察逐项复核。

## ADDED Requirements

### Requirement: L10-01 前置盘点与场景追溯

小组 MUST 盘点所有可重复命令，至少含双门禁、异步三判据及其上次真实运行时间、版本、退出码和证据。已批准交付范围内的每条规约场景 MUST 对应至少一条可执行用例，登记场景 ID、用例路径或人工卡片、执行入口、判据、负责人和结果。优先补齐空白；未运行的命令须明确标记。第 9 课 SEC-08 按必做四步实验登记。

实施组的可运行证据与变更收尾的门禁、代码评审、课程专项复验 MUST 分列。进入正式人工评测前，验收负责人 MUST 核对纳入交付范围的实现组可运行证据、候选双门禁和适用安全技术结论，并登记待最终验收执行的人工复验与合并评审，并对已批准的课程等价与待确认差异分别标记。组内通过只表示该增量可供开发交接。

#### Scenario: L10-F01 盘点有缺口或证据来自旧候选
- **GIVEN** 任一必做技术前置任务未完成、技术场景无用例或自动化证据无法关联本轮候选
- **WHEN** 验收负责人核对矩阵、最新运行记录及候选清单
- **THEN** 将该项登记为失败或未执行并指派补齐责任，正式人工评测保持待启动

### Requirement: L10-02 四项技能行为

每项课程技能 MUST 有可追溯的常驻回归及人工评测卡。确定性决策与模型等待的测试使用可控替身验证，真实候选的人工评测另外记录实际结果。

#### Scenario: L10-N01 解题引导给出可继续的提示
- **GIVEN** 学生打开解题引导，题目及标准答案在测试夹具中可核对
- **WHEN** 学生直接索要答案并继续追问
- **THEN** 给出可操作的下一步提示，输出、流式增量和引用不泄露最终答案

#### Scenario: L10-N02 教师改分在迟到模型结果之后仍生效
- **GIVEN** 本班授权教师可改分，存在尚未完成的模型批改或可控迟到结果
- **WHEN** 教师保存修订分数，再释放迟到模型结果
- **THEN** 最终显示、持久结果与相关汇总采用教师分数，保留修订和审计，重放不会覆盖人工决定

#### Scenario: L10-N03 错题讲解依据学生错误给出提示
- **GIVEN** 学生有本人错题，测试夹具含标准答案和错误原因
- **WHEN** 打开错题讲解并索要标准答案
- **THEN** 讲解解释错因或给出改进提示，技能输出、增量和引用不直接贴标准答案，并遵守上游的答案开放规则

#### Scenario: L10-F02 知识库跨班检索为空
- **GIVEN** A 班专属资料可被 A 班账号检索，B 班检索链路经本班数据验证可用
- **WHEN** 用 B 班身份请求同一专属查询
- **THEN** 结果为空且无跨班出处、计数或内容，A 班正向对照仍成功

### Requirement: L10-03 双门禁和主干准入

`make check` MUST 全量执行接口和单元用例及既有适用门禁。安全反例、秘密扫描和依赖审计 MUST 可独立通过 `make check-security` 执行，秘密命中或 High/Critical 非零、工具故障或必做项未执行均应阻断。CI MUST 用与本地一致的两个命令在构建前检查，主干保护必须要求两项实际通过。准入顺序为 AI 初稿、按七类规则自审、脚本门禁、人工确认需求意图并补用例或规则、独立交叉评审、合入主干。

#### Scenario: L10-F03 故意改坏时门禁真实阻断
- **GIVEN** 隔离分支有已知可通过的候选和可复跑用例
- **WHEN** 故意改坏一个期望值或比较条件，本地运行并在获准的临时远端分支验证 CI，再恢复并重跑
- **THEN** 红样本在本地及 CI 非零，构建及合入条件未通过。保留改坏位置、红屏及退出码、修复提交、绿屏及退出码 0，命令可复跑，归档 `reports/gate-red-green.md` 并保留第 9 课原记录

### Requirement: L10-04 冷启动、构建追溯与数据库兼容

Dockerfile MUST 分离构建与运行，最终镜像只含运行所需产物，无项目原始源码、构建工具、环境专用值或秘密。Compose MUST 声明应用、MySQL、Qdrant 的健康与依赖，并为候选所需的其他服务提供同一文档入口。运行配置从环境注入。推送 MUST 自动检出、跑双门禁并构建带源提交标识的镜像。数据变更按扩、迁、缩登记，仍需回退时保留旧结构。

#### Scenario: L10-N04 干净目录启动并反查运行提交
- **GIVEN** 有干净目录、README 列出的环境输入和 CI 成功构建记录
- **WHEN** 仅按 README 准备配置，执行一条 `docker compose up -d`，核对镜像标签、修订标签及运行版本
- **THEN** 全部必需服务就绪，无口头补充。镜像摘要、流水线运行号及完整源提交互相可查，镜像检查满足运行产物约束

#### Scenario: L10-F04 配置或数据库故障时阻断流量
- **GIVEN** 新实例缺少必填配置，或启动后 MySQL 暂不可用
- **WHEN** 启动实例并检查路由是否接流量，再恢复配置和依赖
- **THEN** 配置无效时启动明确失败，依赖未就绪时探针失败并撤流，恢复后仅在就绪检查通过时接流量

### Requirement: L10-05 技能观测与真实通知

指标 MUST 与第 9 课审计的技能标识、状态、时间和耗时口径一致。面板至少展示三种独立技能的调用量分线、逐技能错误率，以及接口 P95 和队列深度并排。错误率在面板用调用计数计算。告警 MUST 定义观察量、持续条件、通知动作和负责人。

#### Scenario: L10-N05 可见指标和真实告警送达
- **GIVEN** 隔离候选已登记三个技能、告警持续条件及获准测试收件端
- **WHEN** 分别触发三个技能及持续失败，检查面板并等待通知
- **THEN** 三张图可核对实际指标，告警在规定时限内送达，通知附面板链接，归档触发、送达及恢复记录

#### Scenario: L10-F05 告警仅触发而通知未送达
- **GIVEN** 连续失败达到阈值
- **WHEN** 查询告警状态、通知通道和收件记录
- **THEN** 缺送达记录时保持失败，记录路由和时限偏差，修复后重新触发并取证

### Requirement: L10-06 压测改进与可比较证据

仓库 MUST 保存使用环境参数的压测脚本，分别对提交、查询、检索递增负载，记录并发、吞吐、P95、错误率及饱和点。受理吞吐与消费者处理吞吐 MUST 分开记录。至少一项索引或缓存改进须在相同脚本、参数、夹具与环境下复测，并关联瓶颈归因、改进提交和可观察改善。

#### Scenario: L10-N06 对照跑出可归因的性能改进
- **GIVEN** 固定了基线、改进候选、负载级别、消费者数和饱和判据
- **WHEN** 分别运行两轮相同负载并比较提交、查询和检索
- **THEN** `reports/bench.md` 有两轮吞吐、P95、错误率、饱和点、受理与消费口径、脚本和改进提交，至少一项达到预先登记的改善判据且无硬档退化

#### Scenario: L10-F06 压测环境变化或改进未达标
- **GIVEN** 两轮数据、消费者数量或脚本参数不一致，或没有可观察改善
- **WHEN** 验收人核对原始运行和预登记判据
- **THEN** 保留实际数据并判不可比较或未达标，补做同口径复测

### Requirement: L10-07 移动端流程与真实用户

H5 MUST 复用现有 API 和认证，服务端明确声明允许来源并拒绝未授权来源。至少三名实际使用者 MUST 在候选上试用。每人至少一条反馈写入 `reports/feedback.md`，使用脱敏会话标识，记录接口、实际返回、预期差异和处理去向。已复现的新问题须进入用例套件。

#### Scenario: L10-N07 手机四步与审计
- **GIVEN** 手机浏览器可访问已就绪的候选，两班账号和已发布作业可用
- **WHEN** 登录取得候选认证，提交作业、轮询任务，然后换班访问他班讲义
- **THEN** 留存登录成功、HTTP 202 与任务标识、`pending → running → succeeded`、HTTP 404/1300 四步实际结果及七列审计关联，证据不含认证秘密

#### Scenario: L10-F07 未授权来源或未找到资源
- **GIVEN** 已登记可信 H5 来源及两个班级
- **WHEN** 从未登记来源重放带凭据请求，并从合法来源查询他班讲义与不存在讲义
- **THEN** 未授权来源不得读取受保护数据或写入，两次合法来源的讲义查询同为 404/1300 且公开内容一致

#### Scenario: L10-F08 真实试用反馈缺人或无去向
- **GIVEN** 试用反馈不足三名实际使用者，或有反馈缺接口、观察结果或处置
- **WHEN** 验收负责人复核原始记录与任务或用例关联
- **THEN** 记录缺口与责任人，补齐真实试用和处理证据后再判定

### Requirement: L10-08 正式人工评测与归档

必做功能及前置自动化交付验证任务 MUST 先完成，随后冻结候选和证据开展正式人工评测。人工意图确认、跨机器复验、SEC-08 真人观察和三名用户试用统一由项目最终验收执行，不作为冻结候选前置，但全部仍为最终通过所需条件。同一候选的跨功能卡由项目最终验收任务执行，其结果进入本次人工评测记录。人工评测 MUST 覆盖四项技能、H5 四步、既有项目跨功能主路径及关键反例。评测人确认教学意图、体验与复现材料，每项按前置条件、操作、预期和实际记录。同伴 MUST 从干净目录按 README 独立启动并重跑四步，登记实际设备、版本、角色和返回。任一必需结果失败、缺证据或差异未获课程方确认时，候选保持待验收。

#### Scenario: L10-N08 人工签署同一候选
- **GIVEN** 所有必做前置任务有实际通过证据，选做状态清楚，候选已冻结
- **WHEN** 验收人与独立同伴执行对应卡片，逐项核对结果及文件
- **THEN** 记录评测人、同伴、时间、候选、各项判定及实际签署。根目录 `report.md` 只列结论及可打开的证据指针

#### Scenario: L10-F09 课程差异、展示失败或候选变更
- **GIVEN** 教师改分或作业 202 等课程行为缺失、同伴结果不符、报告打不开或候选已变化
- **WHEN** 核对课程判据、实际证据和批准的等价口径
- **THEN** 登记展示前待修项。差异未获课程方确认前保留缺项。新候选重新固定版本并复测受影响项，保留原失败记录

最终证据 MUST 包含至少三份 `reports/review-01.md` 起编号的评审记录，其中至少两份记录由 AI 自审或脚本门禁实际发现的问题及处置，另附独立同伴走查。发现数不足时记录缺口。每份记检查手段、对象、判据、结果。高风险三查使用 `reports/risk-concurrency.md`、`reports/risk-transaction.md`、`reports/risk-authz.md`。所有报告只跟踪脱敏证据。
