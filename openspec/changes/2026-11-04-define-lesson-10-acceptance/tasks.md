## 实施交接与验证责任

前置任务中涉及代码、配置或迁移的实现组按 [CK-03](../2026-11-04-add-skeleton/specs/skeleton-check/spec.md#requirement-ck-03-实现组可运行交接) 交接。第 5 组以全部必做前置验证和专项证据为输入，正式人工评测使用同一冻结候选。

## 1. 盘点与可追溯矩阵

- [ ] 1.1 在 `reports/acceptance-matrix.md` 盘点所有可重复命令、最近实际执行时间和候选，至少包含双门禁和异步三判据。列出已批准交付范围内全部场景与用例、入口和负责人。按实现组可运行、变更收尾、课程专项、正式人工评测分列证据，核对无空白场景，记录缺证据和选做状态。验证 L10-F01。
- [ ] 1.2 核对四项技能的实际入口、课程差异和批准口径。用 `project-add-tests` 补接口或单元用例及测试替身，验证解题引导、教师改分优先、错题讲解与知识库隔离。保留教师改分或等价未确认的缺项。验证 L10-N01、L10-N02、L10-N03、L10-F02。

## 2. 双门禁、准入与红绿演练

- [ ] 2.1 收集全量接口和单元测试及既有门禁。复用课末安全预检建立并经第 9 课修复回归的安全入口，接入反例、秘密扫描及依赖审计，核对两条命令均按实际判据退出。将同名命令接入 CI 并验证两项均为主干准入条件。验证 L10-03。
- [ ] 2.2 按 AGENTS 和 Cursor 规则完成七类自审，保留所读规则、对象、判据与实际结果。核对脚本门禁；人工意图确认与独立评审由项目最终验收 1.3 执行并形成用例或规则。验证 L10-03。
- [ ] 2.3 在隔离分支改坏一条比较或期望，本地和获准的临时远端验证非零，核对构建与准入阻断，再恢复并取得绿灯。把改坏位置、前后输出及退出码、命令、修复提交和 CI 记录追加至 `reports/gate-red-green.md`。验证 L10-F03。

## 3. 制品、容器与迁移

- [ ] 3.1 完善多阶段运行制品及 Compose 健康依赖，README 明确环境、镜像与一条启动命令。在干净目录逐步核对服务就绪、镜像无项目源码、构建工具和秘密。分别验证缺配置和数据库不可用时阻断。验证 L10-N04、L10-F04。
- [ ] 3.2 验证推送后自动双门禁与构建，归档运行编号、源提交、镜像标签与摘要及运行版本。索引改进涉及改表时使用 `project-data-change` 记录扩与迁、兼容及回退证据。写入 `reports/delivery-runtime.md`。验证 L10-04。

## 4. 观测、性能与真实试用

- [ ] 4.1 复用第 9 课审计口径接入至少三个技能，验证调用量分线、错误率与 P95/队列深度。用获准的连续失败演练触发实际告警，保存通知送达、时限和恢复记录到 `reports/delivery-runtime.md`。验证 L10-N05、L10-F05。
- [ ] 4.2 入库可通过环境配置的压测脚本，分别测提交、查询、检索及异步完成吞吐，预登记并发梯度、饱和与改善判据。实施一项索引或缓存改进并在相同条件复测，归档两轮三数、改进提交、瓶颈和饱和点到 `reports/bench.md`。验证 L10-N06、L10-F06。
- [ ] 4.3 完成 H5 复用认证、明确来源及七列审计的自动化四步回归，准备 reports/feedback.md 的会话代号、接口、实际/预期和处置字段。三名真实使用者试用、手机人工走查与反馈去向由项目最终验收 4.5 执行，不作为 5.1 冻结候选前置；真实试用及反馈仍为最终通过必做项。验证 L10-N07、L10-F07、L10-F08。

## 5. 技术交付通过后调度最终人工评测

- [ ] 5.1 核对前四组技术任务及全部纳入交付功能的自动化交接、安全预检/修复技术证据，固定唯一候选提交、镜像摘要、配置、数据和评测人员。未执行的真人测试、试用和课程确认登记到项目最终验收对应任务，不要求它们在冻结前完成。冻结只允许启动人工验收，不代表已批准合并或最终通过。验证 L10-F01。
- [ ] 5.2 将设计中的四项技能、手机四步及全部真人复验统一交给同一候选的[项目最终验收任务](../2026-11-04-project-final-acceptance/tasks.md)的跨功能主路径、失败与边界场景，共用一次业务走查。记录每条前置、操作、预期、实际和证据。判定差异、课程等价及体验缺口，归档 `reports/manual-acceptance.md`。验证 L10-N01、L10-N02、L10-N03、L10-F02、L10-N07、L10-F09。
- [ ] 5.3 由项目最终验收 4.4 执行组内另一人从干净目录按 README 独立启动并完整重跑四步，登记实际返回、候选及演示前待修项。换候选后保留旧记录并复验受影响场景。验证 L10-N08、L10-F09。
- [ ] 5.4 用 `project-review` 核对至少三份评审记录、其中两份记录由 AI 自审或脚本门禁实际发现的问题和处置、高风险三查、实际人工签署和全部脱敏报告。以 `git check-ignore` 核对固定报告可跟踪、原始产物仍忽略。根目录 `report.md` 仅写真实结论与可打开的证据指针。验证 L10-08。
