# 最终验收设计

## Context

骨架已提供 Flask、MySQL、Qdrant 和统一检查入口。认证、资料入库和检索已有规划，其他教学流程的验收依据随各自业务规约确定。最终验收以批准纳入交付的核心功能及一个可追溯的候选版本为输入。

## Goals / Non-Goals

确认候选可从干净环境启动，教师和学生能完成跨功能主流程，并取得真实、可复核的交付结论。业务缺陷修复走对应实现变更。发布、归档和标签按各自授权办理。

## Decisions

### 实现与正式验收的验证责任

| 阶段 | 执行与证据 |
| --- | --- |
| 实现变更 | 实施人按本变更规约执行适用的单元、接口、真实依赖集成及适用的自动化浏览器回归。覆盖正常、失败和边界，按仓库规则运行自动化门禁及适用的模型评测、迁移检查。留存对应候选、命令、退出码；人工复核调度见下文，合并前仍须代码评审。 |
| 最终验收 | 第 10 课前置任务齐备并由 5.1 冻结候选后，验收人在隔离环境用同一候选提交和制品手工执行各功能主路径、越权和失败场景，再走通跨功能流程。复用已具备的单项证据，核对同一候选的集成结果，按发布范围记录通过、失败、未执行、不适用和人工评审。 |

第 10 课第 5 组调度走查并复用本变更的结果，使用同一份 `reports/manual-acceptance.md`。选择一个候选贯穿最终验收，避免拼接多个版本的通过结果。核心能力未齐或缺实现证据时登记缺口，交回对应变更补齐。第 7 课的启动与回滚证据继续在课程内留存，可供最终验收复用。

### 候选的可观察结果

| 前置条件 | 操作 | 可观察结果 |
| --- | --- | --- |
| 干净环境、锁定配置和制品可用 | 按 README 启动并请求就绪接口 | 报告候选版本，核心依赖可用，日志可用请求标识关联。配置或核心依赖缺失时记录原因与实际状态。 |
| 两个合成班级及师生账号已就绪 | 教师创建章节并录入资料，学生按章节检索、提问并回查引用，再提交一条无证据问答的未解决反馈 | 同班学生可追溯到原文；无证据时明确提示、无出处，教师能凭学生主动填写的说明处理反馈。跨班与不存在的资料按业务规约返回结果。 |
| 题库、测验和反馈功能已纳入候选 | 教师生成或手工建立候选题、审核并发布，学生保存草稿、正式提交并在开放后查错题，教师核对看板 | 未审核题不能发布，重复和截止后提交被拒；开放后可查答案、解析、出处和错题；看板提交率、平均分和各题正确率与冻结样本的手算一致。 |
| 分别停 Kafka、模型或向量服务，已有本班资料和发布测验 | 教师手工建题，学生提交并在开放后查成绩，教师上传新资料并构建关键词索引 | 人工建题、资料浏览、作答及确定性评分继续运行，向量故障时首次构建的新资料可以关键词检索。 |
| 冻结评测集及配置已就绪 | 核对不少于 30 题的三路检索与回答评测，关联候选版本及配置 | 分别记录 Hit@5、回答依据充分率、无答案正确率、检索及问答中位数和 P95，以及差距与失败样本。 |
| SSE 按已核定的配置达到在途上限 | 继续发起流式请求，并同时登录、读资料、提交测验和调用探针 | 超额流快速拒绝，短请求和探针仍可用；按 OPS-11 验证短请求时延并记录资源释放。 |
| 验收场景出现失败 | 登记对应候选、输入、预期、实际和修复归属 | 必需场景保持失败状态，修复后在新的候选上复验相关链路并关联原记录。 |

## Risks / Trade-offs

- 候选版本变化会使部分证据失效 → 重新登记候选并复验受影响链路。
- 外部模型或基础设施不可用 → 单列环境故障和未执行项，保留复测结果。

### 2026-11-05 集中人工复核清单

用户授权在全部功能完成后统一安排人工工作。本变更 1.3 承接全部实现与安全变更的人工意图和代码复核，1.4 承接第 7 课尚待人工的专项证明；2.6–2.8 给出认证、资料和骨架交接的操作清单。上游任务仅表示实现及自动化交付完成，未取得人工评审的变更保持待合并，CK-F10 判据保留。

调度依次为功能自动化交接、安全预检技术基线、安全修复技术交接、第 10 课技术交付与候选冻结，随后由本变更统一执行 1.3–1.5、第 2 组及第 4 组全部真人任务。冻结候选不等待尚未开展的人工结果，合并批准仍须实际评审。课程证据仍回填原入口，不宣称课程已通过。

各卡使用同一版本、两班合成身份与独立环境。结果由真人登记，AI 自检与自动化通过单列。用例记录字段、失败归属及换候选复测按 tasks 末尾统一约定；历史报告可复用，但候选不匹配时复验受影响链路。发布、归档及标签仍须对应授权。

### 2026-11-05 人工任务唯一归属

检索人工评测/标注裁决归 2.4；流式与 MCP 原四项同伴验证归 2.9/2.10；第 8、9 课独立安全复验归 4.1/4.2，第 9 课 SEC-08 真人观察归 4.3；第 10 课独立四步和三名用户试用归 4.4/4.5。课程确认统一归 1.5。安全检查与修复的技术脚本、扫描和审计仍由两安全 change 执行，最终验收引用并人工复核，不另建一套安全实现。报告继续使用课程固定路径，来源版本与后继候选分别记录。
