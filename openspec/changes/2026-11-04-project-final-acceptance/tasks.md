## 1. 确认候选和证据

- [ ] 1.1 确认纳入交付的全部功能已完成，核对各实现组可运行交接记录、变更收尾门禁与代码评审结果，以及适用的课程专项证据，登记缺项及其责任变更。使用[第 10 课任务 5.1](../2026-11-04-define-lesson-10-acceptance/tasks.md#5-全部必做任务通过后的正式人工评测)已冻结的候选提交、制品标识、配置与合成数据。
- [ ] 1.2 在隔离环境从干净源码或对应制品启动候选，记录就绪、依赖与版本。核对该候选的适用合并门禁和迁移或评测证据。

- [ ] 1.3 全部交付功能及技术验证齐备并冻结候选后，由小组指定实际复核人，对全部功能变更（含骨架、认证资料、检索、流式、MCP、异步教学、限流追溯）及安全变更的人工复核输入逐项复核。检查应用装配、探测隔离与排空、班级权限、事务幂等、恢复防复活、Cookie 方案及 PSF-2.0 传递依赖许可，明确清理执行责任；核对约束文件差异理由和影响。登记候选、姓名、日期、问题、结论及证据。按 CK-F10 核对未执行/失败门禁或缺代码评审的候选仍不可合并；不得把上游实现任务勾选作为人工批准。合并前必须取得实际同伴代码评审。
- [ ] 1.4 汇总第 7 课尚缺的独立会话、三名成员独立冷启动和实名交叉评审、课程口径确认及正式违规检查。按课程证据原要求核对 CK-F01、F04–F06、B01 的自动化证据，安全破坏验证由安全预检 1.3 执行，保留原有实际技术证据，缺项写明责任人与来源，不用助手本机运行代替成员复现。若需新聊天或远端操作，按当时授权执行。结果回填 docs/lesson-07/acceptance.md；不回填虚构的历史批准日期。

- [ ] 1.5 集中确认课程差异：Cookie 与 Bearer Swagger、测验提交 201 与作业 202、内部规则评分与直接批改写入口、教师改分优先、JSON 技能与课件字段、MCP 部署目录及去内容审计映射。列课程依据、当前契约、影响场景、课程方真实结论和出处；未经确认继续保留缺项。仅受影响路径待定，其他功能继续开发。

## 2. 执行人工功能验收

在同一候选上以共享的两班合成数据人工执行各功能场景。登录与资料覆盖刷新、注销、文字及文件上传、预览、下载、教师组织与删除、学生写入拒绝和跨班隐藏；其他功能按其各自规约记录操作与可见结果。按资料与检索、题库与测验、页面与反馈分配验收责任，在同一候选验证确定性闭环、真实检索问答及异步候选题。课程扩展按交付范围复用同一候选和证据。

- [ ] 2.1 以两班师生走通登录、章节创建、资料入库、检索问答及出处回查；另验证无证据→学生填写卡点→教师处理→章节未解决计数变化。记录同班可用、跨班访问及资源不存在的实际结果。
- [ ] 2.2 走通 AI 候选与人工建题、审核发布、作答草稿、刷新或重新登录后恢复、一次正式提交、截止拒绝、评分、答案开放、错题与出处。以冻结名单和提交手算并核对看板指标。
- [ ] 2.3 分别停 Kafka、模型和向量服务，验证人工建题、已发布测验评分及新资料关键词检索的适用降级；恢复后复验。流式扩展单列，长流满额时验证登录、资料读取、正式提交和探针。
- [ ] 2.4 在功能齐备后的候选上完成至少 30 题（含至少 10 道无答案）的人工标注复核与题集冻结，调参样例隔离，明确跨片段最小证据组合。核对已有同候选自动化指标，缺少匹配证据时重跑三模式评测，人工裁决依据充分率及无答案处理，记录实测与目标差距和失败归因；不能以自动化替身的结果代替真实效果。
- [ ] 2.5 将失败交由对应实现变更修复。在后继候选复验受影响链路，保留初次失败、修复和复测的关联。

- [ ] 2.6 人工复验认证和页面：A/B 班各一师一生在桌面和 390 像素窄屏执行登录、直访资料/工作台、刷新、注销、失效后重登录返回；核对非法外链回退、学生导航及当前角色。用独立浏览器会话核对并发换发仅最后会话有效、旧会话迟到注销不撤销新会话。到期使用隔离时钟或实际等待，记录方式，禁止改共享账号。逐项登记 AUTH-N01/N02、B01、F01–F06 的实际结果；技术属性与故障注入可引用同候选自动化证据，体验判断由真人填写。
- [ ] 2.7 人工复验资料：教师分别文字及 UTF-8 TXT/Markdown 上传，核对预览和实际下载字节、标题排序和旧修订冲突、32,000/32,001 字符提示、1 MiB 边界、删除后列表/详情/下载及同键重放；学生上传/组织/删除被拒，匿名无正文，跨班与不存在同构。覆盖 ACL、ING、IO，核对上传/删除故障回滚、真实备份恢复后删除清单双重放及旧制品回退的同候选证据；需重跑时仅用合成隔离库，记录清理和耗时。桌面/窄屏检查四状态、键盘、脚本文本和下载体验。
- [ ] 2.8 人工复验骨架与交接：按 README 在干净目录启动，核对版本、双探针、请求日志关联和停止排空；核对 CK-N02 首批业务入口与真实持久结果。分别核对 CK-F07 配置/迁移/依赖缺失、CK-F08 探针成功但业务未装配、CK-F09 授权或副作用回归的失败及恢复证据；缺前提只阻断依赖组。涉及停服务或破坏样本时使用专用隔离环境，保留断言，不更改共享运行环境。

- [ ] 2.9 人工复验流式助手原 5.3 四项：同班他人会话隔离、外班助手隐藏及停用后默认角色、伪造班级不扩大检索、技能停用后新轮次读取最新配置。用独立账号留实际结果和身份组合；另核对 SSE 增量、取消、窄屏和操作体验。
- [ ] 2.10 人工复验 MCP 原 4.3 四项：跨班服务/工具列表及直访、凭据只见配置标记、断开后拒绝并记结果、本人记录及教师最小投影。走自建服务→发现审批→技能绑定→对话触发→记录→断开，保留独立身份与网络/调用证据。

## 3. 汇总验收结果

- [ ] 3.1 汇总候选、环境、场景结果、各实现变更证据和未关闭事项。写入第 10 课同一份 `reports/manual-acceptance.md`，由实际评审人记录结论，交第 10 课 5.4 签署与发布结论核对。

每条人工记录统一包含：任务/场景编号、候选提交与镜像摘要、配置键（不含私有值）、合成身份及前置数据、操作、预期、实际、HTTP/业务码或可见副作用、证据路径、执行人、复核人、时间和结论。通过、失败、未执行、不适用（附理由）分别登记。失败关联责任变更和后继候选，复测受影响链路及对应自动化回归；其余原结果保留版本边界。当前所有人工任务均未执行。

调度顺序：功能实现与自动化交接 → 安全预检技术基线 → 安全修复及自动化复测 → 第 10 课技术交付与 5.1 冻结候选 → 本变更统一人工复核/操作/试用 → 第 10 课 5.4 汇总结论。人工结果不是前序技术任务的完成前置；缺代码评审的候选仍不可合并。全部真人任务在功能齐备后的同一候选执行，换候选复验受影响链路。
