## 1. 确认候选和证据

- [ ] 1.1 核对核心功能范围和各实现变更的测试及评审结果，登记缺项及其责任变更。齐备后固定候选提交、制品标识、配置键与合成数据。
- [ ] 1.2 在隔离环境从干净源码或对应制品启动候选，记录就绪、依赖与版本。核对该候选的适用合并门禁和迁移或评测证据。

## 2. 验证跨功能流程

- [ ] 2.1 以两班师生走通登录、章节创建、资料入库、检索问答及出处回查；另验证无证据→学生填写卡点→教师处理→章节未解决计数变化。记录同班可用、跨班访问及资源不存在的实际结果。
- [ ] 2.2 走通 AI 候选与人工建题、审核发布、作答草稿、一次正式提交、截止拒绝、评分、答案开放、错题与出处。以冻结名单和提交手算并核对看板指标。
- [ ] 2.3 停模型验证资料浏览、人工建题和已发布测验评分；恢复后复验。将长流占满已登记配额时同时验证登录、资料读取、正式提交和探针。
- [ ] 2.4 核对与候选版本及配置关联的 30 题以上冻结检索评测证据；缺少匹配证据时在候选上重跑，报告实测与目标差距。
- [ ] 2.5 将失败交由对应实现变更修复。在后继候选复验受影响链路，保留初次失败、修复和复测的关联。

## 3. 汇总验收结果

- [ ] 3.1 汇总候选、环境、场景结果、各实现变更证据和未关闭事项。由实际评审人记录最终结论。
