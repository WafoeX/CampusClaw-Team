## 1. 确认候选和证据

- [ ] 1.1 核对核心功能范围和各实现变更的测试及评审结果，登记缺项及其责任变更。齐备后固定候选提交、制品标识、配置键与合成数据。
- [ ] 1.2 在隔离环境从干净源码或对应制品启动候选，记录就绪、依赖与版本。核对该候选的适用合并门禁和迁移或评测证据。

## 2. 验证跨功能流程

- [ ] 2.1 以两班师生走通登录、资料入库、检索问答及出处回查。记录同班可用、跨班访问及资源不存在的实际结果。
- [ ] 2.2 走通教师审题发布、学生作答提交、评分、答案开放及本班教学反馈，按各业务规约检查结果。
- [ ] 2.3 将失败交由对应实现变更修复。在后继候选复验受影响链路，保留初次失败、修复和复测的关联。

## 3. 汇总验收结果

- [ ] 3.1 汇总候选、环境、场景结果、各实现变更证据和未关闭事项。由实际评审人记录最终结论。
