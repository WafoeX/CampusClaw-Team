## Context

当前工作区的 Flask 授权层已按登记策略解析身份，资料仓储已有班级和资料标识组合条件，登录使用同源 HTTPS Cookie、`Origin`、`X-CampusClaw-Request` 及 `SameSite=Strict`。检索、AI、工具和异步任务还需按实际候选核对。Makefile 已在 `make check` 中分别调用 Gitleaks 和 Trivy，尚无 `make check-security`，pytest 目前按 `tests/` 组织，`apitest/cases/` 待建。第 8 课已形成自查规约，当前工作区尚无实际自查和异步风险报告。

## Goals / Non-Goals

- 将第 8 课记录、代码修复、回归用例及交付证据按课程编号关联。仅补经复测证实的缺口、必做注入回归及本课新增契约。
- 业务权限、评分与任务状态仍以服务端规则决定。明文凭据处置按已授权事故流程执行。SEC-08 按第 9 课清单执行四步实验。

## Decisions

### 原始复测与补充对照

从 `reports/security-precheck.md` 冻结每条前置条件、操作和可观测结果。固定候选提交、镜像、配置名、合成夹具、扫描器及漏洞库版本。原记录中只追加本次实际值，配置写入因新增令牌而需要补充对照时，保留原样重放，再追加满足防伪条件的角色验权探测，确认学生 403 的拒绝原因来自权限层。授权和注入、资产和日志分别提供自动化复测结果，真人互换复验由最终验收 4.2 调度。SEC-08 未执行时保留必做缺项。

### 同一授权边界覆盖 HTTP、数据访问和工具

复用应用工厂的策略登记和当前身份解析，按已登记入口验证匿名 401 和角色 403。写入服务在实际操作时复查当前角色、班级与业务状态，使用归属和版本条件防止验权后的角色或归属变化引发误写。讲义返回前校验归属，现有班级与标识组合条件继续作为数据层保护。SQL 与 Qdrant 各自在召回、取限前按服务端班级约束，继续回表核验版本及授权。对照检索入口、查询计划和过滤参数，删除能先查全表再过滤的旧路径，使用合法请求对照防止空索引误判。工具宿主将真实主体传给同一服务，受限工具不能直连业务库。

### 三条回归进入真实门禁

三条用例按既有 pytest 运行器接入 `apitest/cases/`，在 Makefile 明确收集，并同步格式及目录检查。SQL 注入以两班真实检索数据和合法查询为对照，验证绑定值与排序白名单。XSS 保存纯文本标题后抓取原始 HTML，断言标题所在节点只有已转义文本，并检查渲染副作用。CSRF 令牌由服务端为当前会话和配置写动作签发，短期有效、一次消费，服务端保存摘要并原子校验消费。令牌响应禁缓存，客户端通过同源受保护渠道获取并在请求头提交，保留 Origin、自定义头和 Strict Cookie。使用同源缺令牌、已消费令牌和合法首次写入确认令牌独立生效，另从浏览器或响应头取 Cookie 属性证据。

### 资产处置与门禁判定

复用现有 Gitleaks 与 Trivy，不以新增工具替代既有检查。以第 8 课计划的一键入口为基础，分项覆盖 Git 历史、候选产物、日志、镜像和锁定依赖，合并退出状态并确保首项失败时仍尝试后项。红绿演示使用隔离环境中的合成命中或受控高危样本，证明入口确实阻断，复测记录输入差异及实际提交。真实基线独立保留。高危书面处置附期限与缓解证据，门禁继续非零，合并与发布按仓库 SEC-16、REV-06 独立审批。

泄露处置先撤销和轮换，再用获准的最小请求验证旧值 401 或提供方等价结果，确认新值可用。历史重写及小组通知按明确授权安排，并保留复扫和重新克隆核对记录。默认沿用环境凭据引用，数据库仅存引用。发现有必须持久化的凭据时，先按仓库例外流程复核必要性，再验证认证加密后的密文、外置解密密钥、旧数据迁移及回退；没有此类字段时记录核查范围和不适用理由。

### 审计数据与实验取证

复用已有请求标识和去内容工具审计契约。持久事件有班级、主体、UTC 时间、动作、资源安全引用、结果、技能 ID、用量、耗时及请求标识。七组展示字段中用量和耗时为一组，存储分别计量并标注单位。无模型调用、无技能或无法量测时分别记空值和可诊断原因。先限制字段及长度，再使用 JSON 编码生成单行记录。成功写入和操作审计同事务，403 拒绝记录通过独立短事务写入并以稳定事件键去重。无法留存高风险写入审计时阻断操作。教师按班级及有界时间窗读去内容投影，隐藏私人会话、执行正文和关联链接，学生无查询权限。

必做 SEC-08 时使用隔离合成数据、固定配置和旧版素材执行四步。只记录必要的脱敏模型输出和数据库对照。模型未提议写操作时另以固定请求穿过真实工具授权边界，区分真实模型行为和工具层证明。前三步观察模型表现，评分事实及安全底线按仓库规范独立判定。

### 回归与固定报告

第 8 课三条异步判据分别为快速返回 202、停消费者后恢复和重复提交或投递仅产生一个生效结果。使用同一候选复核当前主体与任务归属、提交和轮询。四步演示取实际认证，当前认证基线用 Cookie，异步规约计划用 AI 候选题返回 202，正式测验提交按上游 201 另记。涉及课程要求的作业提交等价性继承第 8 课确认记录。

报告固定路径按规约。三件套的三段式索引记入 `reports/security-fix-log.md`，实际用例位于 `apitest/cases/`。同伴复验与规则自审、脚本输出分别署名并从 `review-02.md` 顺序编号。沿用固定 Markdown 路径的精确例外，按实际产生的评审文件逐个开放跟踪，通过 `git check-ignore` 核验原始日志、缓存和临时样本仍忽略。

## Risks / Trade-offs

- 基线不绿或记录缺失 → 留存失败，先恢复可复现对照再开始修复，验收继续待定。
- 令牌与客户端部署不同步 → 服务端、页面、同源 API 客户端和 OpenAPI 同步切换，并验证合法请求与任务授权。
- 日志暴露私人数据 → 只增去内容事件，授权投影与私人执行详情独立，核对跨班和同班隐私。
- 门禁红绿演示误当真实事故 → 证据标明隔离输入，真实资产报告单列。

## Migration Plan

实施前按 `project-data-change` 复核审计表、令牌摘要及可能涉及的旧凭据字段。用增量迁移、空库和已有库、重跑与回退验证，登记数据字典、清理、备份与恢复。先部署兼容的存储变更，再同步切换配置写客户端和服务端。回退仅采用保持等效安全限制的候选，无法兼容时暂停相关写入并保留已受理任务。

### 2026-11-05 第 9 课核对与调度

依据实际读取的第 9 课任务清单，SEC-08 四步是本课要求，撤销“可不执行仍通过”的计划。第 8 课仅选做素材准备不构成第 9 课豁免。本变更执行安全修复、三件套与四步实验的自动化技术验证，人工观察/另一机器独立复验统一在项目最终验收 4.2–4.3 执行，报告仍归本课固定路径。开工依赖安全预检的真实技术基线及可复验记录，不等待最终验收人工结果；技术交接后交第 10 课，课程最终结论等待人工要求完成。
