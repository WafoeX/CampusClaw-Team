## Why

小组实施人、复验人和课程验收人需要在同一基线上验证安全缺口是否修复，同时确认权限收紧后正常教学任务仍能完成。逐条保留同一检查的前后观测和提交记录，可复跑并定位哪次修改带来了变化。

## What Changes

- 承接第 8 课的 SEC 记录，按授权、注入、资产、日志分类，保留真实复测基线。逐项定义 SEC-01 至 SEC-07 的修复判据和必做 SEC-08 的实验判据，以及 SQL 注入、XSS、CSRF 三条常驻回归。
- **BREAKING** 使用 Cookie 的配置写入增加服务端校验的一次性 CSRF 令牌。页面和同源 API 客户端同步接入，沿用现有来源校验和 Cookie 防护。
- 完善资产门禁和去内容的操作审计。将红绿输出、复盘、交叉评审及四步实验的实际记录归档到固定路径，并在同一候选上走通异步回归和最终演示。
- 采用应用层逐次验权与数据层约束。放弃页面隐藏、查询后内存过滤、以模型拒绝代替工具鉴权，以及用登记条目直接消除资产扫描的非零结果。

## Capabilities

### New Capabilities

- `security-remediation` — 第 9 课的跨功能安全边界、可复现修复判据和交付证据。

### Modified Capabilities

当前主规格目录无已归档能力。本变更补充横切契约，实施时与尚在途的上游变更同步受影响的接口约定。
