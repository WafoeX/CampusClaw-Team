## Purpose

让小组在固定的教学应用候选上重放第 8 课自查，逐项验证授权、注入、资产和日志边界，并把实际修复前后观测、异步回归及同伴复验保留为可在演示机复现的证据。

## ADDED Requirements

### Requirement: SR-00 固定基线与逐条复测

小组 MUST 在修复前以同一份第 8 课记录重放课程 SEC-01–07 中已测的条目，并重放本次选做且已有记录的 SEC-08，保留前置条件、操作与期望，另记本次实际值和判定。新增盲区 MUST 先建立第 9 课实测基线，并在修复后复用。选做 SEC-08 时，上一课只有素材的条目以本课首次实测作为基线。按授权、注入、资产、日志标记红项，先处理已复现红项再补盲区，授权先于注入，发现活跃明文凭据立即撤销轮换。修复前 MUST 运行完整 `make check` 留存实际结果。

#### Scenario: SR-N01 候选与原始记录可重放
- **GIVEN** 第 8 课记录、两班夹具、候选提交和依赖版本可用
- **WHEN** 在修复前重放每条记录并运行 `make check`
- **THEN** 逐条保存原始判据、本次实际值、真实红绿和执行人，保留基线输出及退出码；此前已变绿的条目标记为基线已绿并附证据

#### Scenario: SR-F01 缺基线或既有门禁非零
- **GIVEN** 原始记录缺失、夹具不可复现或 `make check` 基线失败
- **WHEN** 小组开始第 9 课取证
- **THEN** 保存原始失败与原因，补齐记录或处理基线阻塞再计入同口径前后对照；未执行项保持缺证据状态

### Requirement: SEC-01 统一登录校验

已登记的受保护入口 MUST 统一校验当前身份，保留明确登记的公开例外和默认拒绝。

#### Scenario: SR-F02 匿名请求受保护接口
- **GIVEN** 第 8 课的至少五个受保护方法与路径均可用，且已取得合法请求对照
- **WHEN** 移除 Cookie 和令牌逐个重放
- **THEN** 全部返回 401，无受保护数据或写入，记录每个接口的状态及适用业务码

### Requirement: SEC-02 班级隔离

应用 MUST 使用服务端当前班级。讲义按标识取数时 MUST 在返回前核验资源归属，跨班与缺失公开响应相同。SQL、向量查询及资源写入 MUST 在查询或写入条件中限定当前归属，检索必须在召回与排序取限前应用过滤。

#### Scenario: SR-F03 跨班讲义与双检索分支
- **GIVEN** 两班各有已索引资料，班级专属词有本班命中，B 班讲义存在
- **WHEN** A1 用 B 班讲义 ID 和不存在的合法 ID 分别取讲义，B1 用第 8 课原查询重放并分别覆盖关键词、向量及混合检索
- **THEN** 讲义请求均为 404/1300 且公开文案及数据相同，跨班查询成功但零命中；两种存储查询在召回前可核验班级限制，响应无他班数据或数量

### Requirement: SEC-03 配置写入校验角色

技能、提示词和助手写入 MUST 在业务操作时校验当前教师角色，并在数据层约束班级、对象及预期修订。

#### Scenario: SR-F04 学生写配置
- **GIVEN** 教师可合法写入三类本班配置，A1 具备有效会话，且请求满足来源及适用的 CSRF 条件
- **WHEN** A1 重放三个配置写请求
- **THEN** 均为 403/1200，配置、版本和相关副作用无变化，记录各次结果

### Requirement: SEC-04 批改与写工具完整验权

直接入口、技能和工具 MUST 调用具有同等授权的业务写入边界。该边界逐次验证身份、角色、班级、资源及业务状态，并将适用归属与状态并入原子写入条件。

#### Scenario: SR-F05 绕过技能直接写入
- **GIVEN** 学生 A1 有正常提交资格，评分、作答及任务记录有只读基线
- **WHEN** 沿用第 8 课的直接批改写入检查，并经受控工具入口重放同一未授权操作
- **THEN** 未授权写入被拒且无评分、任务或发件箱残留；若候选无公开批改接口，则保留已确认的等价路径及库对照，未确认时保留课程缺项

#### Scenario: SR-F06 授权依赖不可用或资格变化
- **GIVEN** 请求已进入工具或写入服务，当前身份无法读取、资源已迁班或教师已被撤权
- **WHEN** 在实际写入前重新验权
- **THEN** 依赖故障返回安全的依赖错误，失权请求按契约拒绝，均无写入或外部写工具执行

### Requirement: SR-01 SQL 注入、XSS 与 CSRF 常驻回归

三条反例 MUST 在 `apitest/cases/` 有可执行三段式用例并纳入 `make check`。查询值 MUST 参数化，排序列等结构输入 MUST 使用白名单。HTML 输出 MUST 按上下文转义。使用会话 Cookie 的配置写入 MUST 同时校验一次性 CSRF 令牌和保留同源保护，会话 Cookie MUST 启用明确的 SameSite 策略。

#### Scenario: SR-F07 SQL 注入与非法排序
- **GIVEN** 两班均有可查资料，正常本班检索及排序有对照结果
- **WHEN** 提交检索词 `' OR '1'='1`，再以 SQL 片段作为排序参数
- **THEN** 检索返回空结果或受控格式错误，非法排序返回参数错误，无额外行、查询异常细节或副作用

#### Scenario: SR-F08 讲义标题 XSS
- **GIVEN** 本班教师可保存普通文本标题
- **WHEN** 将 `<script>alert(1)</script>` 作为合成讲义标题保存并打开列表页，查看原始 HTML 和渲染后的页面
- **THEN** 标题以转义后的文本呈现，页面源码无由标题生成的可执行脚本节点，且无执行副作用

#### Scenario: SR-F09 CSRF 伪造表单、缺令牌与重放
- **GIVEN** 教师已登录，配置可合法更新
- **WHEN** 从另一来源提交伪造表单，再用合法同源请求省略令牌或重放已消费令牌，并单独检查登录响应的 Cookie 属性
- **THEN** 各非法请求被拒且无写入，SameSite 属性单独留证；带匹配的首次有效令牌和其他合法条件的更新成功

### Requirement: SEC-05 明文凭据清除与存储检查

实施人 MUST 扫描完整可获取的提交历史、前端产物、运行日志和候选镜像。确认泄露时 MUST 先撤销轮换并验证旧值失效，再按授权清理历史和相关副本，复扫确认零命中，并通知小组重新克隆。对确需落库且已获准的凭据字段 MUST 验证静态密文、解密密钥由环境注入且两者分开保管。

#### Scenario: SR-F10 密钥命中或静态明文
- **GIVEN** 已确认真实凭据命中，或发现本应加密的持久字段为明文
- **WHEN** 运维先轮换并在获准环境验证旧凭据，再执行获准的清理、复扫和静态检查
- **THEN** 留存旧值请求 401 的脱敏证据，服务商使用等价认证错误时记录实际状态及合同口径，新值可用，报告仅含范围和结果；历史复扫零命中后交接重克隆，静态明文字段保持红直至消除

### Requirement: SEC-06 依赖处置与资产门禁

仓库 MUST 通过 README 记录 `make check-security`，同次尝试密钥扫描和锁定依赖审计并记录分项退出码。任何秘密命中、High 或 Critical 发现、漏扫或工具故障 MUST 使该入口非零退出。仍未升级的高危或严重发现 MUST 登记包、版本、漏洞号、延期理由、降险措施、责任人与期限。课程处置与仓库合并、发布判定分别记录。

#### Scenario: SR-F11 资产门禁非零及修复复跑
- **GIVEN** 隔离环境有可复现的受控扫描命中或高危依赖样本，并固定工具和漏洞库版本
- **WHEN** 在同一入口运行红样本，再用修复后的候选或等价隔离样本复跑
- **THEN** 初次非零且两项均有结果，干净复跑零退出；`reports/gate-red-green.md` 记录实际输出、退出码、提交号和隔离输入，真实资产基线另外归档

### Requirement: SEC-07 去内容操作审计及查询授权

操作审计 MUST 以结构化单行 JSON 持久化，记录操作人、操作时间、操作类型、操作对象、结果状态、技能标识、用量与耗时七组字段，关联请求标识。非适用字段使用明确空值。日志文本须安全转义与截断。仅本班授权教师可读去内容审计投影，学生不可读，教师视图须剔除私人会话或执行详情及敏感原文。

#### Scenario: SR-N02 技能成功和学生拒绝均可追溯
- **GIVEN** 有一次获准技能调用、A 班教师和学生 A1
- **WHEN** 按技能标识查调用，重放一次满足其他条件的 SEC-03 请求，再按 A1 与时间窗查询
- **THEN** 技能记录可查七组实际字段，拒绝请求有且仅有一条关联的 403 操作记录，公开投影不含秘密或私人正文

#### Scenario: SR-F12 查询审计越权
- **GIVEN** 两班均有审计记录
- **WHEN** A1 请求审计列表，A 班教师尝试读取 B 班审计对象或越范围查询
- **THEN** 学生返回 403，教师跨班对象按缺失返回 404，列表按本班过滤，无他班记录、计数或私人执行信息

#### Scenario: SR-F13 审计不可用时写入失败
- **GIVEN** 高风险写入需要操作审计，审计持久层不可用
- **WHEN** 业务收到配置变更或工具写入请求
- **THEN** 失败关闭且无业务写入，记录脱敏依赖故障并保留复测缺项；未经授权请求仍被拒绝

### Requirement: SEC-08 可选的四步提示注入实验

SEC-08 为选做项。小组选择执行时 MUST 在隔离候选实际运行恶意文档、索要提示词、改变评分规则、绕过权限四步，分别记录评分是否改变、模型返回了什么、规则范围是否扩大、模型是否提议写工具以及工具层是否执行。第四步工具层必须判绿。前三步如有偏差须如实记录并按仓库安全边界处理。

#### Scenario: SR-B01 模型偏差与工具层阻断分开取证
- **GIVEN** 小组选择执行 SEC-08，第 8 课素材、合成测验及学生身份可用，固定技能和模型版本
- **WHEN** 逐一执行四步，对比评分与权限快照；若真实模型没有提议写操作，另以固定提议重放实际工具执行层
- **THEN** 四步有真实现象记录，真实模型行为与固定提议证据分开；未授权写操作在执行层被拒、无持久副作用且有拒绝审计，第四步据此判绿

#### Scenario: SR-B02 小组选择不执行 SEC-08
- **GIVEN** 小组选择不执行 SEC-08
- **WHEN** 汇总课程复测及交付证据
- **THEN** 记录 SEC-08 为选做未执行，课程完成按必做项判定

### Requirement: SR-02 回归、演示与交叉评审

实施人 MUST 在同一候选跑完 `make check`、第 8 课三项异步判据和注入三件套，任何一组失败先复现并修复回归。每条安全修复须独立提交并标明对应课程 SEC 编号。复验人 MUST 在另一台机器从 README 冷启动，独立复验至少两条且判定一致。

#### Scenario: SR-N03 四步演示与课程交接
- **GIVEN** 三组回归均通过且两班夹具齐备
- **WHEN** 依次登录取得候选实际使用的认证、提交任务、轮询任务、换班级访问他班讲义
- **THEN** 实际记录登录成功、202 与任务标识、`pending → running → succeeded`、跨班 404 四步结果，保留可复跑命令和候选版本

#### Scenario: SR-F14 回归或评审有分歧
- **GIVEN** 任一回归失败或同伴复验判定不一致
- **WHEN** 小组按同一候选、夹具和命令复核
- **THEN** 保留前次结果，定位后复测，满足三组全绿及至少两条独立一致复验前保持待验收

归档 MUST 包含 `reports/security-fix-log.md` 的编号、修复前实际、修复后实际和判定、当日 `reports/security-baseline.md`、`reports/gate-red-green.md`、三件套用例索引及 `reports/security-rework.md`。选择执行 SEC-08 时另归档 `reports/sec08-experiment.md`。复盘记录真实代价最大的一次返工、定位与修复各自耗时、原因和一条可执行改法。无真实返工时登记缺项。评审从 `reports/review-02.md` 开始连续编号，每条评审写一份，含手段、对象、判据、结果。至少两份来自规则对照的 AI 自审或实际脚本输出。人工评审聚焦机器无法判定的项，并补一条用例或一条规则。独立同伴复验另据实际操作者与环境判定。
