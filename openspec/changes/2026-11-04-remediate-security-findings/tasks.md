## 实施交接与验证责任

各修复组按 [CK-03](../2026-11-04-add-skeleton/specs/skeleton-check/spec.md#requirement-ck-03-实现组可运行交接) 交接。自动化重放对应红项并用合法请求确认可用，涉及写入时核对失败无副作用。第 6 组执行完整自动化回归与技术证据交接。真人专项复验归最终验收，SEC-08 按必做四步登记。

## 1. 固定基线

- [ ] 1.1 收齐第 8 课预检技术结果与三项异步判据的实际证据（真人跨机器评审由最终验收补齐，不作开工前置），按 README 在隔离环境冷启动。固定提交、制品、依赖和 A/B 班夹具，原样重放 SEC-01–07 的前置条件、操作与预期，记录新的实际值。分类已复现红项并安排先授权后注入。已有绿项留真实对照，缺记录按 SR-F01 补齐。验证 SR-N01。
- [ ] 1.2 在修复前运行完整 `make check`，保留实际输出与退出码。基线非零时保存原因与复跑结果。核对 SEC-08 素材与记录；此前无运行记录时用本课首次实测建立基线。验证 SR-N01、SR-F01、SR-B02。

## 2. 授权红项与双层校验

- [ ] 2.1 逐条复核已登记入口的匿名 401 和配置写角色 403，复用现有策略及身份解析并修复已证实缺口。使用同一三段式验证至少五个受保护入口和三个配置写入口，记录 HTTP、业务码和库内差异。验证 SR-F02、SR-F04。
- [ ] 2.2 校验讲义归属及写条件，检查并消除旧的全表取数后过滤路径，验证 SQL 与向量两侧均先限班级再召回。保留本班正常命中、跨班 404/空和查询证据。验证 SR-F03。
- [ ] 2.3 将直接批改和工具调用纳入同一业务验权，核对撤权、依赖故障、无残留及任务归属。无公开批改入口时沿用第 8 课等价确认；未确认的记录缺项。验证 SR-F05、SR-F06。

## 3. 三条注入回归

- [ ] 3.1 以 `project-add-tests` 建立 `apitest/cases/` 下的 SQL 注入、XSS、CSRF 可执行用例。先保留真实基线，再补查询参数绑定和结构白名单，核对页面原始 HTML 和渲染副作用。验证 SR-F07、SR-F08。
- [ ] 3.2 用 `project-data-change` 复核令牌摘要的迁移、清理和回退。同步配置写客户端、服务端和 OpenAPI，分别验证跨站表单、同源缺令牌、重放、合法首次写入与 SameSite 响应证据。保留 SEC-03 原样重放与满足防伪条件的补充角色探测。验证 SR-F04、SR-F09。
- [ ] 3.3 将三件套纳入 `make check`、现有 pytest 收集和适用静态检查，证明任何一条失效会阻断门禁。在 `reports/security-fix-log.md` 写明三段式及实际用例路径。验证 SR-01。

## 4. 资产修复与门禁证据

- [ ] 4.1 运行真实秘密扫描。确认有泄露时立即按权限撤销轮换，保存旧值失败和新值可用的脱敏证据，获授权后清理历史及副本、复扫零命中并通知小组重克隆。核对落库凭据字段是否存在，适用时验证静态密文与外置密钥，无此类字段时记核查范围。验证 SR-F10。
- [ ] 4.2 对锁定依赖运行审计，升级阻断发现或逐条书面登记延期理由、降险、负责人和期限。记录 High/Critical 数量、包和漏洞号，归档当日 `reports/security-baseline.md`。验证 SEC-06 的课程与仓库判定口径。
- [ ] 4.3 复用第 8 课安全预检已建立的 `make check-security`，同步修复后判据与 README。用隔离样本确认命中或高危时非零且两项均有输出，修复后同一命令零退出。归档 `reports/gate-red-green.md` 的实际前后输出、退出码与提交号。验证 SR-F11。

## 5. 操作审计与四步实验

- [ ] 5.1 用 `project-data-change` 补审计字典、留存和迁移验证。接入七组字段和教师本班去内容查询，分别验证技能成功、学生 403、学生读拒绝、跨班隐藏、审计故障无写入及行内容安全。验证 SR-N02、SR-F12、SR-F13。
- [ ] 5.2 按第 9 课必做要求建立并运行 SEC-08 四步实验脚本：恶意文档、索要提示词、改变规则、绕过权限。补齐上一课未选择准备的素材，固定模型、技能及合成身份，逐项保存实际现象；第四步工具执行层必须拒绝、无写入并有审计。归档 reports/sec08-experiment.md；真人观察与复验交最终验收 4.3。提示词/技能有实际修改时运行 project-prompt-eval。验证 SR-B01、SR-B02，不执行或缺任一步都保持未完成。

## 6. 回归、交叉评审与交付

- [ ] 6.1 在同一候选执行 `make check`、异步三项判据和注入三件套，保留各组实际输出。用自动化脚本完成认证、202 任务受理、三态轮询、换班读讲义得 404 的四步走查。任一回归失败先定位并复测，保留失败与修复耗时。验证 SR-N03、SR-F14。
- [ ] 6.2 按课程 SEC 编号将实际安全修复逐条独立提交。逐项核对 `reports/security-fix-log.md` 的修复前后实际和判定、固定报告路径及提交号。核对必做 SEC-08 四步报告。将代价最大的真实返工、定位与修复耗时、错误和可执行改法记录在 `reports/security-rework.md`，无实际返工时记缺项。
- [ ] 6.3 汇总可重复复验包、至少两份 AI 规则自审或脚本输出发现记录与处置、固定报告索引和原始产物忽略状态。用 project-review 复核技术证据；真人另一机器冷启动、至少两条修复独立复验及 reports/review-02.md 起的实际署名由最终验收 4.2 执行。技术交接与课程人工复验状态分列，验证 SR-F14 的缺项判定。
