## Context

OpenAPI 仅描述部分入口。业务工厂按配置装配路由，接口套件也包含探针、测试专用路由及独立 MCP 服务。

## Decisions

1. 用合成配置装配主应用，启用索引路由，获取 Flask 的实际路由与传给授权中间件的策略。逐条核对公开例外以及配置写授权和一次性令牌登记。使用源代码中的路由模板，避免在报告中出现资源 ID。
2. 在现有断网 API 套件内订阅 Flask 完成请求的信号。只读取方法、匹配路由、HTTP 状态、服务端身份是否存在、缓存指令和会话 Cookie 属性。输出文本或 JSON。独立教学服务通过合成机器凭据装配，单列 `/mcp` 方法；对已发生的响应核对 Bearer 头、Origin 与会话签发禁缓存。忽略页面、探针和 HEAD/OPTIONS。
3. 以非零退出区分检测到违规与运行未完成。回归失败或跳过时保留已观察项并标明证据不完整。未触达接口和仅有拒绝响应的接口单列，可回查真实依赖测试。

## Risks / Trade-offs

路由登记和测试替身无法证明真实数据的资源隔离。MySQL、Qdrant、浏览器及工具验证沿用已有隔离测试，在交付记录中按实际执行情况说明。
