# 完整预验收环境设计

## Context

已有基础、HTTPS、teaching 和 tools 的 Compose 定义，业务功能无需新增。部署密钥必须私有，当前 Docker Hub 直连不可用，现有镜像来源辅助保持摘要但只供集成夹具使用。

## Goals / Non-Goals

以单入口启动现有完整服务并提供可核对状态；不冻结候选、不开放公网、不替代真人和真实模型评估。

## Decisions

- 主机入口 `uv run --locked python -m scripts.start_acceptance [start|status|stop]`。项目名和合成库名以源码路径摘要区分克隆，监听本机 18000/8444；占用时明确失败，不停止其他服务。
- 私有配置、证书、日志和状态位于 runtime/acceptance，目录 700、凭据/私钥 600。数据库及演示口令首次生成并复用，停止不删卷。
- 根 .env 仅提供模型配置；每次启动刷新模型键，缺凭据标记未执行，不把替身写成真实模型通过。
- 沿用 Compose 扩展；先启动数据服务创建网络，读取实际私有 CIDR 配置 MCP 白名单，再迁移、种入合成账号并启动 app、gateway、MCP、Kafka、relay/worker。所有长命令有超时，错误只输出日志位置。
- 使用提交号标识镜像，启动前要求源码干净。检查双探针版本和必需服务；安全状态记录只含版本、服务名/健康和模型配置是否齐备，不含秘密。
- 将来源转换提为主机侧通用辅助，显式 --mirror-host 可替换已知依赖来源但保留完整摘要；不改变默认生产定义、应用目标或测试断言。
- 备选只写手工命令会遗漏 MCP 的实际 CIDR、合成密码与启停边界，因此使用薄编排工具复用现有 Compose。

## Risks / Trade-offs

- 首次拉取依赖或漏洞库网络失败 → 保留实际失败与复跑，不换版本、不宣布最终通过。
- 本机源仅能直接用于本机浏览器 → 手机/跨机器实际访问另登记受控访问配置，不自动放开端口或信任库。
- 模型及独立参与者尚未提供 → 技术预验收结果与最终结论分开。

## Migration Plan

无表变更，执行已有可重跑迁移。停止仅 down，不删除卷及私有配置；工具回退不修改历史数据。镜像按提交标识，不覆盖其他源码版本。
