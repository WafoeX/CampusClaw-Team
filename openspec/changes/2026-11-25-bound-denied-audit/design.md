# 拒绝审计预算设计

## Context

HTTP 授权钩子早于业务写入限流；403 错误处理调用拒绝审计，另开数据库事务。因此调整后置业务额度不能解决已知审计放大风险。当前 WSGI 固定 1 worker / 8 threads。

## Goals / Non-Goals

限制拒绝审计写尝试和内存状态，保留原授权及响应。完整抗 DDoS、认证读取限流、多副本全局配额和持久队列不在本能力范围；上限不是生产容量承诺。

## Decisions

- 业务服务新增进程内 DeniedAuditBudget，以单调时钟的 60 秒固定窗口计数；Lock 保护重置、两类配额预留和一次告警标记，锁内不做 I/O。总量上限也限制主体字典条目数，超额请求不创建新主体条目。
- 统一 Settings 加载两个环境键，默认主体 60 / 总量 600，严格校验 1–10000 且主体不大于总量；Compose 显式透传。计数只使用当前数据库身份 actor.id。
- OperationAudit.denied 在数据库事务之前预留，结果用内部枚举区分已存、抑制、首次抑制及存储故障。第一次抑制只记录一次去内容告警；原 HTTP 403 及 request_id 日志每次仍存在，明确不保证超额逐次数据库审计。
- 预留后存储失败不退款，防止故障导致无限开事务；窗口结束后自然重试。成功审计和其他审计类型不受影响。
- 备选把同一限流数据库消费移到 403 处理：每次仍写库且新主体可放大，不能满足减少写尝试目标。备选 Redis 会新增基础设施，当前单 worker 无此必要，故采用进程内有界预算并明确重启/多副本边界。
- 用可控时钟与线程验证边界，用真实 MySQL 和已有教学夹具证明拒绝审计上限及成绩副作用。禁止通过删断言或把告警视为成功来降标准。

## Risks / Trade-offs

- 多 worker、重启或扩容会增加整体额度 → 文档写明每进程预算，改变拓扑前另评审共享配额，不能复用当前结论。
- 超额不逐次落审计库 → 每个请求仍有 HTTP 去内容拒绝日志，首次超额有窗口告警，正常预算内事件按原 90 天留存；此新覆盖边界提交人工复核。
- 限额为工程预算而非容量实测 → 按既有部署默认值预登记，实测记录合法操作 P95 和错误数；不反向修改判据换绿灯。

## Migration Plan

无表迁移。预算仅含主体标识、计数、单调窗口和告警标记，最长保留至下一窗口的请求重置；不进入备份，不含正文或凭据。升级时新建进程预算，回退保留历史审计数据，但会恢复原风险，应暂停拒绝洪泛验证。更新数据字典声明该瞬时元数据边界。

### 本机镜像来源兼容

本机 Docker Hub 超时，隔离测试增加可选 `CAMPUSCLAW_TEST_DOCKER_MIRROR`，只允许改变 MySQL/Qdrant 的仓库主机来源，保留原路径映射及完整 SHA-256。覆盖文件位于测试临时目录，不改生产 Compose、应用镜像、测试目标或断言。默认不设置，CI 沿用原来源；主机格式和未锁摘要拒绝路径有单元回归。
