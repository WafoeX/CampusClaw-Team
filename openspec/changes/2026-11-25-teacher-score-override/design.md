# 教师改分优先设计

## Context

现有 `quiz_results` 保存不可变规则总分和逐题结果，正式提交在 MySQL 短事务内完成；提交列表、学生成绩和看板直接读取规则分。身份、班级与教师角色均来自数据库会话，答案开放前已有学生投影屏蔽。

## Goals / Non-Goals

**Goals:** 在不修改规则评分的前提下增加并发安全、可追溯的最终分覆盖，并让三类投影使用同一口径。

**Non-Goals:** 不实现模型批改、学生异步 `202` 作业、错题讲解技能、跨班管理或删除改分历史。

## Decisions

- 新增 `quiz_score_overrides` 当前表和 `quiz_score_override_events` 只增表。当前表支持常数时间投影与修订锁，事件表满足评分变更只增审计；直接覆盖 `quiz_results.score` 会丢失规则分，单用事件最大修订会放大所有读查询，因此放弃。
- 当前表以提交为主键，同时保存 `class_id`、教师、分数、理由、修订和时间，并通过 `(class_id, submission_id)` 归属约束关联提交。事件以 UUID 主键，对同一提交和修订唯一，保存前后最终分。迁移为追加表，不回填业务行；无覆盖即规则分。
- 写入口为 `PUT /api/v1/quizzes/{quiz_id}/submissions/{submission_id}/score-override`。服务层在同一事务锁定本班测验、正式提交和当前覆盖，验证 0..max_score、修订与重放，再更新当前表并插入事件。教师 ID 和班级不接受客户端输入。
- 仓储查询左连接当前覆盖，以 `COALESCE(override_score, rule_score)` 得到最终分；服务投影同时返回 `rule_score`、`score`、`score_source`、覆盖修订和理由。看板平均分使用最终分，逐题正确率仍使用规则详情。
- 学生投影沿用答案开放闸门，开放后才附覆盖理由；教师页面在本班提交行提供分数、理由和当前修订输入。原因作为教学记录保存，但不写普通日志或操作审计正文。
- 相同 expected_revision、score、reason 视为等价重放并返回现值；同修订不同内容返回 409。这样浏览器重试不重复事件，不另引入客户端幂等键。

## Risks / Trade-offs

- [总分与逐题得分和不一致] → 明确区分规则分和教师最终分，逐题结果标为规则评分，不伪造分项。
- [并发教师互相覆盖] → 行锁、修订号和数据库唯一约束共同拒绝陈旧写入。
- [跨班标识探测] → 所有提交查询同时限定当前班级和测验，跨班与不存在共用 404。
- [回退应用忽略覆盖分] → 回退期间暂停改分并保留两表，按规则分提供兼容读取；恢复前核对事件连续性。

## Migration Plan

0017 在 0016 后追加两表及提交的同班复合唯一键。空库、从 0016 升级、重复升级和含既有规则评分升级均验证；升级后先部署兼容读写应用。应用回退保留新表并暂停改分入口。物理降级仅允许随机 `campusclaw_test_` 合成库，删除新增表和复合索引，不修改 `quiz_results` 或提交；生产不执行物理降级。
