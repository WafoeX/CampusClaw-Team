# Design

## Context

现有错题查询已经执行学生身份、本人提交、答案开放及题目来源撤销检查；现有私人会话提供限流、模型容量、取消、SSE、本人历史和技能审计。内置解题引导把模型输出限制为四个提示槽位，再由服务端渲染固定文本。当前缺口是独立的错题技能标识、从具体错题启动的入口以及对应配置和回归。

## Goals / Non-Goals

**Goals:**

- 复用现有私人会话安全边界，为具体本人错题建立独立可追问会话。
- 从结构上保证模型无法把标准答案写进任何 SSE 增量或持久结果。
- 保留班级教师对助手和技能绑定的配置权，并给学生明确的缺配置状态。

**Non-Goals:**

- 不改变答案开放后错题卡原有的标准答案和教师解析展示。
- 不让模型生成自由形式的个性化长解析，也不新增检索引用。
- 不在本变更处理学生正式提交 202/任务轮询差异。

## Decisions

### 以专用启动端点编排教学授权与私人会话

新增 `POST /api/v1/quizzes/{quiz_id}/mistakes/{item_id}/explanation-sessions`。教学服务先从冻结的本人提交派生错题上下文，只返回题干和学生自己的错误作答；会话服务再选择本班已启用且绑定 `mistake_explanation` 的助手并创建 `problem_guidance` 私人会话。返回的 `opening_question` 由服务端构造，前端随后通过现有消息 SSE 端点发送。

这样可以复用现有会话、执行记录、容量和幂等契约，同时让错题资源校验留在教学服务。替代方案是在浏览器直接拼接通用解题引导请求；该方案无法证明入口确实来自本人错题，也无法区分班级缺少独立技能配置，因此放弃。

启动涉及两个短事务但没有跨库原子提交：先读冻结错题，再幂等创建会话。冻结题目和提交结果不会被普通编辑改写；若第二步失败，不产生成功响应，原幂等键可重试。

### 新内置技能只允许选择固定错题提示

新增 `mistake_explanation` 内置技能和四个固定槽位：`diagnose`、`locate`、`retry`、`verify`。选择模型只接收题干、错误作答、追问、技能步骤及可用课内证据作为 JSON 数据，不接收独立 `answer` 字段；系统消息只允许返回 `{"hints":[...]}`。服务端依据实际选中的内置技能选择允许集合，并在持久化前再次验证。

SSE 只发送验证后固定文本，引用固定为空。即使题干、选项、资料或用户追问含提示注入，输出也不能回显自由数据。替代方案是生成自由错因正文后做字符串过滤；短答案、同义答案和分段增量无法可靠过滤，因此放弃。

### 配置缺失明确失败

会话服务按稳定顺序选择第一个已启用、且当前修订只绑定一个已启用 `mistake_explanation` 技能的助手，避免同一助手的其他技能参与选择或渲染。没有合格配置时返回 409/1400，页面提示教师先配置；不退化为未审计的通用解题引导。创建和执行仍分别核对当前助手/技能修订，配置变化触发现有冲突保护。

### 只增迁移扩展内置技能标识

0018 仅替换 `skills.builtin_key` 的检查约束，加入 `mistake_explanation`，不改既有行和索引。升级前旧应用不知道新标识；部署顺序为先扩约束、再切应用。应用回退前须停用并删除该内置技能行，再恢复旧约束；合成隔离库执行物理降级演练。

## Risks / Trade-offs

- [固定提示比自由解析个性化程度低] → 本轮优先满足答案不泄露的可证明边界，人工效果在最终验收评测；后续若引入自由正文须另开变更和语义泄露评测。
- [首轮错题读取与会话创建之间配置变化] → 会话创建再次锁定助手与技能绑定；不满足则失败，不返回部分成功。
- [多个合格助手的选择可能随配置变化] → 使用稳定 ID 排序，并把最终助手修订写入现有执行配置；幂等重放保留同一会话。
- [公共提示文字可能偶然包含极短答案字符] → 固定提示使用中文且不回显任何输入；评测以标准答案语义和完整选项文本核对，单字母答案按独立 token/字段检查。

## Migration Plan

1. 在合成空库和已升级库运行 0018，核对旧内置技能不变、重复升级幂等。
2. 切换新应用，教师添加新内置技能并绑定启用助手，再开放学生入口。
3. 回退应用前删除或迁出 `mistake_explanation` 行，再在合成隔离库降级约束；生产回退默认保留扩展约束，不做破坏性删除。
