# Design

## Context

见 [proposal](proposal.md) 的问题定义及[能力规约](specs/teaching-job-audit/spec.md)。`CandidateJobs.admit/replay` 在 MySQL 事务中写 `teaching_jobs` 与 outbox；worker 以代次、事件 ID 和租约拒绝旧执行者，再将草稿及任务终态提交。0013 的 `operation_audit_events` 已有班级、操作者、请求标识、动作、对象、结果、技能、用量和耗时，教师查询按当前班级过滤并有 90 天清理，但结果约束只接受 `succeeded/denied`，列表不能按任务 ID 过滤。候选任务没有 JSON 技能绑定，也未将模型用量传给任务结算。

## Goals / Non-Goals

**Goals:**

- 从同一任务 ID 追查受理、重放及最终结果，并证明旧租约和重复投递不会产生第二终态审计。
- 复用现有教师审计查询和去内容留存边界，保留任务状态与审计同事务。
- 将模型适配器确实返回的用量与实际执行耗时传至结算，不把缺失数值伪装成零。

**Non-Goals:**

- 不把正式交卷改为异步，不新增主观题批改、教师改分或新的课程技能。
- 不从旧日志推算历史用量，也不因审计事件增加学生可读的任务细节。

## Decisions

### 复用操作审计表，按任务 ID 查询

`resource_type` 使用固定的教学任务类型，`resource_id` 为任务 UUID；受理和重放事件使用原 HTTP `request_id`，worker 终态事件使用由任务 ID、代次和终态类别派生的稳定 32 位关联标识。教师列表增加可选任务 ID 过滤，必须与原班级和有效期条件同时应用；详情沿用现有 404 同构。拒绝另建审计表，避免两套授权、清理和恢复规则；拒绝仅依赖 worker 日志，因为日志不满足持久化班级查询和同事务要求。任务不是技能，`skill_id` 保持 `NULL`，不可凭空造标识。

### 业务状态与审计同事务，终态只记录生效结算

在 `admit`、`replay` 与持有当前租约的 `complete` 中调用共用审计写入，不在 Kafka 投递成功或轮询 GET 时追加。受理审计插入失败回滚任务及 outbox；终态审计失败回滚草稿、结果及状态，消息 offset 不提交，恢复后按原租约/重试协议处理。旧租约、重复消息和未获准重放在现有状态检查前返回，不写成功审计。终态事件的稳定标识与唯一约束共同防重；真实的下一代次使用不同标识并保留前次事件。

### 用量与耗时来自生效执行，不做历史补算

给模型调用传入只接收有效 `total_tokens` 的受控上下文；服务将该次有效租约的用量和单次处理耗时送到结算事务。新增任务累计用量字段：每个已生效尝试的有效 token 相加；任一实际调用未给有效数值时，累计状态为 `unavailable` 且数值为空；从未调用模型时为 `not_applicable`。终态审计取本代次累计值，重放重置本代次累计值，旧租约不能贡献用量。耗时记录本次终态处理的实测毫秒数，排队等待由任务 `created_at/updated_at` 另行解释，不混入处理耗时。若模型响应结构非法但提供有效用量，仍按实际调用计入。

### 追加迁移与旧记录兼容

0016 仅扩展：为 `teaching_jobs` 增加可空累计用量与状态字段，为操作审计结果约束增加失败/取消等终态，并增加按班级、对象类型、对象 ID 和时间的查询索引。旧任务维持既有状态，旧审计不回填，也不把旧任务写成新事件。数据字典登记枚举、分级、90 天审计期限、业务任务期限和恢复清理顺序。现有客户端不传新增字段，审计列表新增的过滤参数可选，已有响应字段含义不变。

## Risks / Trade-offs

- 审计插入故障会阻断本次受理或结算 → 保留旧任务状态和 outbox，明确依赖错误，隔离测试注入故障并复测恢复。
- 稳定 worker 标识与 HTTP 请求标识来源不同 → 两者都只用作审计事件关联，业务主键仍是任务 ID；在字典注明来源和唯一性。
- Kafka 至少一次投递会产生多次物理模型调用 → 审计只记录生效租约的用量，不冒充提供方实际计费；日志中的物理调用另按现有观测口径保留。
- 可空 `skill_id` 可能与课程示例的“技能标识”口径不等价 → 在最终验收 1.5 保留课程方判断，不因字段存在或本变更通过而勾选第 10 课 4.3。

## Migration Plan

先在合成空库和已有 0015 库应用 0016，复核旧任务、审计与评分不变，重复升级不产生记录；再切换兼容应用和 worker。上线前确认双方都理解新增结果枚举，避免旧 worker 与新约束混用。应用回退先暂停新候选受理并排空在途任务，保留 0016 扩展列和审计记录；物理降级只在 `campusclaw_test_` 隔离库演练，记录被移除的本课数据。恢复备份后先按原 UTC 期限执行审计清理及既有资料删除清单，再开放任务查询和接流量。
