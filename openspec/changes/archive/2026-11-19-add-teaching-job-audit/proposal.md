# Proposal

## Why

教师与验收人需要按任务 ID 追查 H5 候选题受理、执行结果和模型用量，以复核异步教学的真实操作。现有候选题接口能返回 202 和任务状态，但未写入班级操作审计，无法把四步走查与去内容审计记录直接关联。

## What Changes

- 为教师发起的候选题任务追加受理、获准重放和终态操作审计，保留服务端操作者、班级、时间、动作、任务 ID、结果、耗时及可用模型用量；非技能任务的 `skill_id` 明确为空且用量状态如实标记。
- 教师可按本班任务 ID 过滤现有操作审计列表，保留学生拒绝及跨班隐藏；任务查询和审计查询均不触发执行。
- 在任务状态事务内写入对应审计；重复投递、租约失效和重放不得制造重复的同一代次终态事件。审计故障不得留下已受理或已结算却缺审计的状态。
- 扩展审计结果约束、查询索引、数据字典和回退/留存证据，并以真实 MySQL/Kafka、H5 浏览器主路径和故障注入验证。

本变更服务于第 10 课 L10-N07 的技术证据。它不改变正式测验提交的 201 契约，不新增“作业提交 202”，也不把候选题伪装成 JSON 技能。课程方仍须在最终验收 1.5 确认候选题 202、可空技能标识与课程示例是否等价；未经确认，4.3 不自动勾选。

## Capabilities

### New Capabilities

- `teaching-job-audit`：候选题异步任务的去内容操作审计、任务关联、授权查询、留存与恢复。

### Modified Capabilities

无。仓库当前 `openspec/specs/` 尚无已归档主规格；本变更沿用既有异步教学和操作审计增量的行为边界，不改其 202/201、授权与评分契约。

## Impact

涉及 `CandidateJobs`、教学任务仓储与 worker、`operation_audit_events` 的追加迁移及现有审计查询、OpenAPI/H5 走查、数据字典、隔离测试和变更证据。沿用 MySQL、Kafka 与现有模型适配器，不新增外部依赖或采集私人题干、答案、提示词与模型正文。放弃仅以分散运行日志关联任务、给候选题造技能 ID，以及新增第二张审计表：这些方案分别缺持久授权查询、语义失真或增加副本与清理负担。
