# 规范文档组织与验收方案

## 上下文

动机与范围见 [变更提案](proposal.md)。以下为变更提出时的事实，保留初始决策背景；2026-10-28 当前状态为规范载体和 Git 已建立、应用尚未实现：

- 根目录只有《规范.md》、六页选题 PDF、`.agents/skills/` 和 `openspec/`；无业务源码、构建文件、测试、README 或 AGENTS.md，也未发现 Git 仓库。
- `openspec/config.yaml` 使用 `spec-driven`，没有有效的项目 context；主规格目录无现有能力。
- 《规范.md》包含八类通用规范、CampusClaw 的 Go/React 样例及功能、安全测评判据。它是参考资料，不是本仓库的实现报告。
- 选题说明给出了 Flask 技术方向和基础平台、教学业务、可选提高项。依用户说明，文中“复用”“已完成”全部视为另一仓库的历史描述。
- 本次用户已明确：文档使用中文，优先工程规范，功能设计文档后续再做。
- 补充课件明确了四步启动顺序、五类必修规范的最小集合，以及“规则 + 按需技能”和跨会话生效验证；本次修订据此补足原方案的缺口。

本文件仅设计规范文档的组织与检查方式，不是应用功能设计。

## 目标与非目标

### 目标

让新成员和代码助手从两个根目录入口找到适用规范；每条规范能回答“约束什么、如何检查、什么算失败”；在尚无代码时，文档也能如实验收。

### 非目标

只确定产品规范所需的最小规划页面清单，不展开完整页面交互、全部接口、数据库字段、业务状态机、具体模型版本或实验实现。不创建功能或骨架代码、验证脚本或编辑器规则插件；新增技能仅包含中文操作说明，不宣称运行门禁已经实现。

## 决策

### 一、两类入口承载规则与执行流程

| 目标文件 | 内容职责 | 读取时机 |
| --- | --- | --- |
| `README.md` | 项目定位与价值三问、用户与场景概述、从零建设状态、范围分层、技术方向、规则和技能导航、分支与评审、当前可用和未来约定的命令、机密事件处置入口 | 入门和了解项目时 |
| `AGENTS.md` | 工作边界、读取顺序、常驻硬约束、门禁、提交与评审、完成定义 | 每次工作会话开始时 |
| `docs/standards/01-产品设计规范.md` | 角色场景、信息架构、视图状态、术语、交互与视觉、可达性的制定规则 | 页面、交互、文案变更前 |
| `docs/standards/02-后端开发规范.md` | 分层、接口契约、校验、事务、幂等、并发、配置 | 服务端和契约变更前 |
| `docs/standards/03-安全开发规范.md` | 身份、班级与个人数据边界、机密、不可信输入、附件、依赖安全 | 所有业务和配置变更前 |
| `docs/standards/04-测试规范.md` | 场景追溯、层次、正常/失败/边界用例、隔离、断言、判定与报告 | 编写和评审测试前 |
| `docs/standards/05-部署运维规范.md` | 制品、环境、健康、日志、发布、回滚、备份、容量与告警 | 运行环境、部署变更前 |
| `docs/standards/06-AI应用规范.md` | 模型边界、证据、提示词、工具、输出校验、降级、评测与成本 | 检索、模型、提示词、技能和工具变更前 |
| `docs/standards/07-数据规范.md` | 命名、归属、审计、迁移、字典、分级、留存、副本与补偿 | 数据结构和生命周期变更前 |
| `docs/standards/08-评审与完成定义规范.md` | 完成定义、变更规模、评审分工、时限、门禁、例外与证据 | 每次变更自检与评审时 |
| `.gitignore` | 排除私有环境配置、虚拟环境、缓存、运行数据库、上传文件、容器数据与备份，保留规范与配置样例 | 首次业务代码入库前，以及审查新增文件时 |

选择普通 Markdown 加 AGENTS.md 的显式读取要求，而非直接照搬 `.cursor/rules/*.mdc`：本仓库使用 Codex/OpenSpec，普通文档不依赖某个编辑器的规则匹配机制。不得声称 Markdown 会自动按源码路径触发；AGENTS.md 应明确要求助手根据改动类型实际打开对应文件。

README 提供导航，AGENTS.md 保留少量硬约束，其余详细规则只在对应规范维护，避免复制成两份后不同步。产品规范直接包含课件要求的最小规划页面清单，不增加独立功能设计文档；数据字典、完整页面设计仍由相应功能变更补齐。

五类必修规范是交付下限；本项目额外保留三类补充规范：AI 应用处理生成和工具风险，数据规范处理关系库/向量/文件的生命周期，评审规范处理多人协作与完成判定。性能/容量/限流归运维，依赖引入/许可归安全，不再新增分类。

执行流程落实为以下五个技能文件，均只包含元数据与中文步骤：

| 文件 | 技能名称与触发时机 | 执行要求 |
| --- | --- | --- |
| `.agents/skills/project-add-tests/SKILL.md` | 按规范补测试：实现一组任务后或修复缺陷时 | 读取功能场景与测试规范，建立正常/失败/边界映射，检查越权与隔离，执行真实命令并留证 |
| `.agents/skills/project-release/SKILL.md` | 按规范发一次版本：准备发布时 | 检查批准与前置条件，构建不可变制品→兼容迁移→发布→就绪→留证与标签；失败进入已验证的回滚路径 |
| `.agents/skills/project-prompt-eval/SKILL.md` | 按规范改提示词并跑评测：提示词、模型或检索参数变化时 | 锁定版本和参数，跑正向/拒答/注入回归，比较前后结果并归档 |
| `.agents/skills/project-data-change/SKILL.md` | 按规范做数据变更：结构或生命周期变更时 | 核对字典、兼容迁移、回退、归属、副本和补偿，验证失败注入与恢复删除行为 |
| `.agents/skills/project-review/SKILL.md` | 按规范评审变更：交付自检或提交人工评审前 | 检查场景、规则、证据与文档；区分已通过/失败/未执行/不适用/待人工评审，不伪造批准 |

每个技能写明输入、必读文件、顺序步骤、停止条件、输出证据；前置代码或命令不存在时报告缺失，不创建占位实现，不写“已通过”。技能被发现不等于已调用，AGENTS.md 应列明何时调用及如何记录。发布、提交、打标签等动作仍须符合当时用户授权，技能本身不自动授予这些操作权限。

### 二、四步启动与本变更的关系

| 课程步骤 | 本次落实后的交付 | 尚待后续变更验证 |
| --- | --- | --- |
| 建仓库 | README、AGENTS.md 协作约定和 `.gitignore`；随后依独立授权初始化 Git 与远程 | 教师访问、主干保护、全员克隆、一条命令启动、主干可启动；该课程步骤尚未完成 |
| 定规约 | 本次纯规范变更的规划文件及严格校验 | 骨架和业务变更各自的 proposal/design/specs/tasks、前置条件→操作→可观测结果场景，及独立会话可执行性 |
| 立规范 | 五类必修 + 三类补充规则、AGENTS.md 读取入口、五个可调用技能 | 独立会话读取和真实代码正向/违规验证的证据 |
| 落骨架 | 只规定验收契约：克隆→配置→一条命令→免认证 `/health`，以及配置外置、日志与版本 | 最小可启动实现、Compose/Dockerfile、真实健康测试、版本标签；本次不写代码 |

纯文档变更保留 `skip_specs: true`，不为凑齐“四份文件”编造业务规约；这不能替代后续骨架或业务变更的四份规划文件。README 必须用“已交付载体 / 待验证现象”分别标记，避免将课程全部完成当作本次结果。

2026-10-28 课程复核采用 README C7-01–07 作为本课任务入口，严格区分课内必交项、本项目补充约定与学期业务。骨架另开变更但仍属本课；骨架本身不引入完整登录、题库或测验；按课程参考思路，仍须明确通用授权检查位置、默认拒绝与显式公开健康入口。补齐主干保护在编码前核验、每能力至少四条真实失败场景、跳过数只减不增、删除已有授权检查的违规验证，以及本课当前/前一可运行版本回滚演练。保留无代码时运行项未执行的状态；这些修订只收紧可审查的文字约束，不伪造测试或批准。源课件与证据见本变更验证记录。

本轮进一步读取网站正式任务清单及33个HTML课件页，按课程要求增加 `docs/lesson-07/README.md` 和 `sources.md`；前者逐项区分未实现、未执行、待核验与历史偏差，后者保存来源指纹及示例解读。通用证据保留原路径，从课程目录链接真实记录；不新增业务规格占位。详细缺口为后续本课骨架变更的输入，不在纯文档任务里伪造关闭。

用户本轮明确授权文档直接推送 main 且不提 PR，按 REV-EX-2026-10-28-DOC-MAIN 单次执行；保留远端已合入的上轮历史。用户提交方式授权不等于人工批准所有规则，主干保护和整课运行验收仍待完成。

README 的常规协作约定至少明确：拟用 `main` 主干、`change/<变更名>` 短分支、禁止直接向主干推送、评审通过后合并、每组任务自检、按同一仓库增量交付并关联 OpenSpec 变更。成员采用实施/评审/运维角色记录责任，实名分工待小组确定；不虚构成员批准或已经启用的分支保护。后续骨架就绪后，主干可启动成为持续合并要求。

`.gitignore` 至少覆盖 `.env` 与环境私有变体、`.venv/`、Python/pytest 缓存、本地数据库、`uploads/`、Compose 持久数据和备份；配置样例和 `.agents/skills/` 必须保留，不能用宽泛的目录规则误排除。忽略规则只能防止新文件误入库，已经泄露的凭据仍须轮换。检查用虚构路径，不创建真实敏感数据。

### 三、统一规范条目的写法

每份规范包含适用范围、读取时机、规则表、执行检查清单、违规处理。规则编号分别使用 `PROD`、`BE`、`SEC`、`TEST`、`OPS`、`AI`、`DATA`、`REV` 前缀。

规则表至少有“编号、规定、原因、检查动作、失败判据”五列。检查必须是可执行动作，例如“以另一班账号重放资料详情请求，比较其业务错误和敏感字段”，不能只写“注意权限安全”。尚需代码才能执行的检查标明“实现后执行”，文档审阅能执行的检查标明“本次执行”。

单条规则正文原则上不超过五行，参数、术语或示例拆到就近表格。规范保留判据和流程摘要，详细执行步骤由对应技能承载并引用规则编号，不复制成两份长流程；不覆盖 `.agents/skills/openspec-*`。

### 四、状态与技术方向必须真实

README 使用以下状态，不以另一仓库的状态替代本仓库证据：

| 范围 | 本仓库状态与写法 |
| --- | --- |
| 基础平台：认证、班级隔离、资料、切片与索引、多模式检索、可追溯问答、多 AI 应用、提示词模板、Skill、HTTP/MCP、本人执行记录 | 均待从零实现，不能标记已完成或直接复用 |
| 教学业务：章节、问答历史与反馈、结构化题库及审核、测验、作答与评分、错题、学习看板 | 均待从零实现；本次只说明范围与规范适用性 |
| 文本 PDF、后台索引、检索效果实验页面 | 均未实现；保留选题说明“核心完成后择项”的可选属性，不写成已经交付或全部强制首版完成 |
| 检索对照评价与工程验收 | 将来建立本仓库证据；实验评价不等于必须实现可选实验页面 |

拟用技术遵循选题说明：Python/Flask、HTML 模板/CSS/原生 JavaScript、SQLAlchemy/MySQL 8、Qdrant、pytest、Docker Compose。SQLite 仅用于适合的本地测试，不能代替真实 MySQL/Qdrant 验收。Go、React、`go-vet`、`fe-typecheck`、`backend/internal/` 等不得作为本项目已用技术或现有路径。

命令统一登记“用途、前置条件、状态、预期退出码、证据位置”。当前可用的 OpenSpec 命令可直接列出；`make check`、`pytest`、`docker compose up --build -d` 等只能列为“未来约定，待相应文件建立后可执行”。命令缺失要记录为未建立，不得伪造绿灯，也不在本次创建空目标凑通过。

### 五、课件最小集合与八类规范的检查判据

先逐项满足以下五类必修的最小集合，不能以“三类补充写得多”替代必修缺项：

| 必修规范 | 本次必须形成的文字约定或载体 | 后续运行验证及状态 |
| --- | --- | --- |
| 产品设计 | 用户与场景、最小规划页面清单、加载/正常/错误/空状态四份文案模板、术语表；补充间距刻度与三级字号 | 页面按清单可访问且复用术语组件；本次未实现 |
| 后端开发 | 分层与依赖方向、资源命名与版本前缀、统一响应、初始错误码清单、配置外置及缺项启动失败 | 一读一写接口及故意跨层查询检查；本次未实现 |
| 安全开发 | 默认拒绝、逐资源授权、密钥外置与轮换、输入白名单、查询参数绑定 | 未登记接口被拒、换账号重放被拒、密钥扫描；本次未实现 |
| 测试 | 唯一一键测试/门禁命令的约定、至少一条能力的正常/失败/边界用例卡片、数据隔离约定 | 骨架健康能力建立后实现卡片，执行命令并验证失败非零退出；本次不创建测试代码 |
| 部署运维 | Dockerfile/Compose 待建文件契约、唯一启动命令的约定、免认证 `/health`、单行 JSON 请求标识日志和版本标签约定 | 文件实际入库、冷启动、健康成功、日志核对与标签检索；本次不创建运行文件或标签 |

测试最小示例选用骨架健康能力，只写三类用例卡片：正常时核心依赖就绪，返回契约成功且含版本；失败时核心数据库不可达，就绪应失败并给出可诊断结果；边界时可选模型/向量不可达，核心存活及确定性服务仍可用且报告降级。完成任务后对照课程网站，将 `/health` 明确为免认证就绪入口，独立存活路径仍由骨架变更确定；卡片不充当现成测试或替代未来功能场景。

一键约定统一为未来 `make check`、启动约定为未来 `docker compose up --build -d`；只有对应文件建立且真实执行后，才从“约定/未建立”改为“已可用”。README 必须列前置环境变量的类别与配置填写方式，不提供真实秘密。

最小页面清单放在产品规范，包含“规划页面/路由、角色、服务场景、入口、状态”列。至少覆盖登录、AI 应用工作台、资料列表与原文详情、检索、资料问答、个人会话与执行记录、教师资料与配置入口，以及章节、问题反馈、题库审核、测验、错题、教师看板的教学入口。全部标为“规划/未实现”，可按一个功能页面附带列表/详情路径表达，不在本次展开表单字段和完整交互。路由作为未来基线，可由后续功能变更留痕调整；清单不存在的入口不得静默新增。

| 规范 | 必须写入的约束 | 代表性检查与判据 |
| --- | --- | --- |

### 六、对源资料冲突给出明确处理口径

1. **技术栈冲突**：选题说明是本项目技术方向，样例仅借鉴规范方法，不迁入 Go/React 约定。
2. **认证存储冲突**：《规范.md》通用安全要求禁止访问令牌进入浏览器持久存储，选题说明的历史实现使用 `sessionStorage`。本仓库没有兼容负担，规范采用通用安全基线：访问令牌仅内存持有；若后续确需刷新令牌，只能使用 HttpOnly、Secure、SameSite=Strict Cookie 并轮换。此处不承诺恢复旧仓库 Cookie 登录路径；实际会话流程由后续认证变更设计。偏离此基线必须书面例外及人工安全评审，不能默默照搬历史实现。
3. **AI 职责冲突**：样例“只有回答使用模型”不适用于选题中的多 AI 应用和辅助出题；禁止由模型决定权限、计分及事务结果，但允许受限生成候选题，最终由教师审核。
4. **错误判据冲突**：先看业务码、数据是否泄露和副作用判断业务成功；HTTP 状态映射另按契约检查。比较跨班与不存在时排除 request_id、时间等动态观测字段，避免把可追踪性误判为泄露。
5. **就绪与降级冲突**：不把可降级的模型/向量依赖不可达等同于整个系统不可接流量；核心数据库和可选依赖状态分开检查。
6. **案例阈值不是测量结果**：50/100 毫秒、向量阈值 0.35、某端口等样例值不能直接声称本项目采用或已达标。性能、备份恢复、留存及限流须在规范中标明暂定基线或在相应实现开始前必须确定的参数及责任人，缺失不得放行相关上线验收。

本次载体完成定义：README、AGENTS.md、`.gitignore`、八份规范、五个 `SKILL.md` 及证据记录齐全；中文表达、导航有效、五类最小集合和补充规范有判据、技能可发现且有停止条件、从零范围无遗漏、冲突处理明确、未来项有状态标识、无代码改动。文档阶段的审阅记录归档在 `docs/changes/establish-project-standards.md`，分别记录变更、验证和评审状态；该记录是证据，不是功能设计。

规范生效分四层验证，结论分别记录，不能用第一层通过替代后面三层：

1. **载体检查**：核验链接、规则编号、AGENTS.md 必读映射和技能元数据/输入/步骤/停止条件/输出；本次可完成。
2. **独立会话检查**：另起会话，只给仓库路径和 `establish-project-standards` 变更名，检查助手能否找到规则和技能，并准确说明不写代码及未建立门禁的边界；记录会话标识、实际读取文件与结论。未实际开展时记“待验证”，不能用同一会话自述代替，也不在未获用户指令时自动创建新聊天。
3. **正向生成检查**：骨架或首个功能变更中，仅新增一页、一读一写接口，检查组件术语复用、分层与命名、统一响应及测试；本次不执行。
4. **故意违规检查**：在独立可回退的测试分支分别构造自造样式、业务层查询、未登记访问、移除已有授权或破坏关键逻辑（保持有效断言），观察审查/门禁是否指出；不合并违规样本，保留修复和复测证据；本次不执行。

## 风险与取舍

- 规范过度泛化 → 每类至少一个本项目检查例子，所有硬规则均有动作和失败判据。
- 规范偷跑功能设计 → 只在产品规范内保留课件必需的最小页面清单，完整页面/API/数据设计后移。
- 外部成果造成虚假进度 → 统一“本仓库未实现”，226 项测试、浏览器和部署结论不计作证据。
- 未来路径和命令被误当现有 → 明确区分规范文件真实链接、未来路径代码标记、未来命令状态。
- AGENTS.md 与规范漂移 → 根文件只保留摘要和链接，规则更改同步核对引用。
- 文档未经人工复核就被当作批准 → 记录“待人工评审”，不由助手自填已批准。
- 只有规则而没有可调用流程 → 提交五个 SKILL.md 并检查发现路径和触发条件，已有 OpenSpec 技能保持原样。
- 载体齐备被误认为四步完成 → 四步对照表及四层验证分别标记状态，保留缺失证据。
