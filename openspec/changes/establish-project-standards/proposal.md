# 建立 CampusClaw 项目工程规范

## 为什么

本变更提出时，仓库尚无业务代码、README 和 AGENTS.md，需要先将《规范.md》的通用约束和 CampusClaw 样例转化为适用于本项目的工程规范。现已交付文档载体并初始化 Git，仍无应用代码。选题说明中的“已实现”属于另一个仓库；本仓库必须从零建设全部基础能力及后续教学业务，不能把外部成果记作本仓库已完成。

依据补充的“小组项目启动”任务，规范必须落在助手能够读取的规则和按需调用的技能中，并能够通过重复会话及违规检查验证。此次聚焦“立规范”，同时补齐 README、忽略规则和协作约定；完整业务规约与可启动骨架另行实施。

2026-10-28 继续审查修正：第 7 课要求四步在本课内完成，“另行实施”仅表示另开变更，不能把本课骨架义务推迟到下一课。第 6 组追加课程任务矩阵与文档纠偏：主干保护时点、失败场景下限、测试跳过限制、移除授权验证和本课回滚演练。保持纯文档意图，不新增业务 specs 或实现代码；文档可交付与整课完成分别判定。

## 变更内容

- 全部文档使用中文，保留必要的技术名称、路径、命令和标识符。
- 新建根目录 `README.md`：说明项目定位、从零建设状态、技术方向、范围边界、文档导航、主干与变更分支、评审和证据约定；新建 `.gitignore`，确保私有配置、运行数据和备份先于代码被排除。
- 新建根目录 `AGENTS.md`：固化每次会话必读的安全硬约束、规范读取顺序、变更边界、门禁与完成定义。
- 新建 `docs/standards/` 下五类必修规范：产品设计、后端开发、安全开发、测试、部署运维，逐项覆盖课件的最小交付；另建 AI 应用、数据、评审与完成定义三类补充规范，因为本项目涉及模型不确定性、跨存储数据和小组协作判定。
- 产品规范包含角色与场景、最小规划页面清单、四状态文案模板和术语表；其余功能详细设计后续再做。
- 将样例中的 Go、React、Go 测试路径等替换为选题说明中的 Python/Flask、HTML 模板/CSS/原生 JavaScript、SQLAlchemy/MySQL 8、Qdrant、pytest 和 Docker Compose 技术方向。
- 常驻规则由 AGENTS.md 索引并要求按改动范围读取；新增五个仓库级中文技能，分别用于按规范补测试、发布版本、修改提示词并评测、数据变更、评审变更。技能只编写 `SKILL.md` 操作说明，不含运行脚本，不覆盖已有 OpenSpec 技能。
- 建立课件最小集合对照表和规范生效核验清单，分别记录本次文档检查、独立会话读取、未来代码正向检查与违规检查；缺少实际证据时不得宣称整课四步完成。
- 区分“当前已存在”“未来约定”“待验证目标”，不把计划中的命令、页面、测试和部署能力写成已可运行的事实。

放弃的候选方案：仅在 README 写通用建议、流程只保留在会话中。该方式缺少可按范围读取的规则与可调用技能，不能支持课件要求的独立会话与违规核验，因此采用独立规范文件和仓库技能。
