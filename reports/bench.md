# 第 10 课提交、查询和检索压测

## 对照判据

以 `51ceebd` 为无索引的应用基线。实验组在同一查询上增加 `quizzes(class_id, created_at DESC, id)`，两个候选使用相同版本的压测脚本、容器依赖、负载和夹具。两班各 1,000 条列表测验，A 班另备 36 条已发布测验供独立提交，关键词夹具使用本班一条已索引资料。所有账号及内容均为合成。异步使用真实 Kafka、一个投递器和一个消费者，模型固定替身。

固定并发 1、4、10。列表 API 和分页 SQL 每档各 120 次，预热各 8 次。正式提交、关键词检索和候选受理各 12 次，受理结束后再测该批任务的异步完成。提交和检索使用不同合成账号，减少两类请求共用固定写入额度的影响。接口耗时从 Flask 入口测到实际响应，含认证、仓储和序列化。分页 SQL 独立记录，用于剥离列表总数和接口固定开销。完成耗时从开始投递至各任务处理并提交 offset，吞吐按该批成功数除以整段墙钟时间。完成表中的并发指上游受理并发，实际消费者数固定为 1。

饱和点取首次达到以下条件的档位。相邻并发档吞吐提高不足 10%，或错误率大于 0，或普通查询 P95 大于 1000 ms。并发 10 的普通查询 P95 超过 300 ms 标记为偏慢。完成吞吐的三档比较只用于观察单消费者的固定供给，检查错误率与吞吐停滞。所有请求均保留成功吞吐、全部样本的 P95 与错误数。

改进的通过判据为同条件下分页 SQL 在预先选定的并发 1 至少降低 P95 15%，且执行计划消除对班级结果的排序。接口的硬档与错误率均不得退化到超标。若结果不可比较或未达标，记录原样结果，保留 L10-F06。

复跑命令在仓库根目录执行。

```bash
CAMPUSCLAW_BENCH_LEVELS=1,4,10 CAMPUSCLAW_BENCH_SAMPLES=12 CAMPUSCLAW_BENCH_QUIZZES=1000 \
  uv run --locked python scripts/check_pytest.py -q -s tests/bench/test_teaching_bench.py
```

脚本启动一次性 Compose 项目，回收测试容器、网络、卷和应用镜像。环境变量只配置并发级别、每档样本和合成数据量，应用地址和数据库由隔离夹具固定。运行概要输出到终端，可归档到 Git 忽略的文件。
